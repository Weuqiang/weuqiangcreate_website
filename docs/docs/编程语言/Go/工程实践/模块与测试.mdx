# 模块与测试

Go 用 `go mod` 管理依赖，用内置 `testing` 包写测试，无需第三方框架。本篇讲工程化基础。

## 学习目标

学完本章，你应该能够：

- 用 `go mod` 初始化模块、管理依赖与版本
- 写出表驱动（table-driven）单元测试
- 用基准测试（Benchmark）量化性能

## 前置知识

在阅读下面的内容前，建议先掌握：

- 先读 [Go 语言入门](/docs/编程语言/Go/语言基础/Go语言入门) 了解包与函数
- 工程协作参考 [设计模式](/docs/软件工程与后端/后端通识/数据库) 中的可测试设计思路

## 核心概念

Go Modules 是官方依赖管理：`go.mod` 记录模块路径与依赖版本，`go.sum` 锁定校验和。测试文件以 `_test.go` 结尾，测试函数签名 `TestXxx(t *testing.T)`；Go 社区偏好“表驱动测试”——用一组用例切片覆盖多种输入，结构清晰易扩展。

本章主线：
- go mod：初始化、添加与升级依赖
- 单元测试：TestXxx 与 t.Run 子测试
- 表驱动测试的结构
- 基准测试 Benchmark 与 pprof 入门

## 1. 模块（module）

```bash
go mod init example.com/hello     # 生成 go.mod
go get github.com/gin-gonic/gin   # 添加依赖
go mod tidy                       # 清理未用依赖
```

`go.mod` 记录模块路径与依赖版本，`go.sum` 记录校验和。

## 2. 包与导入

```go
package main

import (
    "fmt"
    "example.com/hello/util"
)

func main() { fmt.Println(util.Add(1, 2)) }
```

- 包名即目录名；首字母大写导出（public），小写包内可见。
- 导入路径相对模块根。

## 3. 写测试

测试文件以 `_test.go` 结尾，函数名 `TestXxx(t *testing.T)`：

```go
// add_test.go
func TestAdd(t *testing.T) {
    if got := Add(1, 2); got != 3 {
        t.Errorf("Add(1,2)=%d, want 3", got)
    }
}
```

运行：

```bash
go test ./...            # 跑全部测试
go test -v ./util        # 详细
go test -cover          # 覆盖率
go test -bench=.        # 基准测试
```

## 4. 表驱动测试

Go 惯用表驱动，一个函数覆盖多用例：

```go
func TestAdd(t *testing.T) {
    cases := []struct{ a, b, want int }{
        {1, 2, 3}, {0, 0, 0}, {-1, 1, 0},
    }
    for _, c := range cases {
        if got := Add(c.a, c.b); got != c.want {
            t.Errorf("Add(%d,%d)=%d want %d", c.a, c.b, got, c.want)
        }
    }
}
```

## 5. 基准测试

```go
func BenchmarkAdd(b *testing.B) {
    for i := 0; i < b.N; i++ { Add(1, 2) }   // b.N 由框架自动调整
}
```

## 小结

Go 的工程化哲学是"标准库够用"：`go mod` 管依赖、`testing` 管测试、表驱动管用例。少依赖、强约定，是 Go 项目易维护的原因。

## 易错点

- 包级 `init()` 会隐式执行，易引入隐藏副作用，慎用。
- 测试文件必须与被测代码同包（或 `_test` 包做黑盒）；`TestXxx` 首字母须大写。
- `go mod tidy` 可能因平台构建标签误删依赖；注意 `//go:build` 标签。
- 基准测试受 GC 影响，单次结果波动大，需多次取稳定值。

## 练习

1. 写一个 `util` 包 + 表驱动测试，覆盖负数 / 零 / 正常输入。
2. 用 `go test -cover` 看覆盖率，补测试到 80% 以上。
3. 写 benchmark 对比 map 与 slice 的查找性能。

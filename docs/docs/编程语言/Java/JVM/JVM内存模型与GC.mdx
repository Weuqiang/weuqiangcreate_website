# JVM 内存模型与垃圾回收

JVM 把内存划分为若干区域，理解它们是排查内存溢出与卡顿的前提。

## 1. 运行时数据区

```
JVM 内存
├─ 堆(Heap)           对象实例，GC 主战场（所有线程共享）
├─ 方法区(Metaspace)  类信息、常量、静态变量
├─ 虚拟机栈           每个方法调用一个栈帧（局部变量、操作数栈）
├─ 本地方法栈          native 方法
└─ 程序计数器         当前线程执行的字节码行号
```

- **堆**是最大的一块，分新生代（Eden + Survivor）与老年代。
- **栈**随方法调用压入/弹出，线程私有，不存在 GC。

## 2. 垃圾回收（GC）基础

GC 自动回收"不可达"对象。主流判定法：

- **可达性分析**：从 GC Roots（栈引用、静态变量等）出发，能到达的对象存活，其余回收。

```java
Object a = new Object();   // a 是 GC Root 可达
a = null;                  // 原对象不再可达，下次 GC 可回收
```

## 3. 分代收集

- **新生代**：对象朝生夕死，用 **Minor GC**（复制算法，快）。
- **老年代**：存活久的对象，用 **Major/Full GC**（标记-整理，慢，会 STW 停顿）。

晋升规则：对象在 Survivor 区熬过若干次 Minor GC 后进入老年代。

## 4. 常见 GC 与调优参数

| 收集器 | 特点 |
|--------|------|
| G1 | 服务端默认，可预测停顿 |
| ZGC | 超低延迟（毫秒级），JDK 11+ |
| CMS(已废弃) | 并发标记清除 |

常用参数：

```bash
-Xms512m -Xmx512m        # 初始/最大堆大小
-XX:+UseG1GC             # 启用 G1
-XX:+PrintGCDetails      # 打印 GC 日志
```

## 小结

- 内存溢出（`OutOfMemoryError`）常因堆/元空间设置过小或对象长期被引用。
- 调优核心是：给足堆、选对收集器、减少 Full GC 频率。

# 进程、线程与调度

操作系统用"进程/线程"抽象 CPU，用"调度"决定谁先跑。本篇是操作系统的核心概念。

## 1. 进程与线程

- **进程**：资源分配的基本单位，拥有独立地址空间。创建/切换开销大。
- **线程**：CPU 调度的基本单位，同一进程内线程**共享内存**，切换轻量。

```
进程 A
├─ 线程 1（共享堆）
├─ 线程 2（共享堆）
└─ 独立栈
```

共享内存带来便利，也带来**竞态条件**——需要锁/信号量保护。

## 2. 进程状态

```
新建 → 就绪 ⇄ 运行 → 阻塞 → 就绪
              ↓
            终止
```

- 运行：占用 CPU；
- 就绪：等 CPU；
- 阻塞：等 IO / 锁，不占 CPU。

## 3. 调度算法

目标是"公平"且"高吞吐"。常见：

| 算法 | 思路 | 特点 |
|------|------|------|
| FCFS | 先来先服务 | 简单，可能长任务饿死短任务 |
| 时间片轮转 | 每人跑一小段 | 响应快，适合交互 |
| 优先级 | 高优先级先 | 可能饥饿，需老化 |
| 多级反馈队列 | 组合上述 | 现代系统常用 |

## 4. 上下文切换

切换进程/线程要保存/恢复寄存器、页表等"上下文"，有开销。频繁切换（如过多线程）会拖慢系统。

## 5. 死锁

四个必要条件：**互斥、占有并等待、不可抢占、循环等待**。

预防思路：

- 一次性申请所有资源；
- 按固定顺序加锁（破坏循环等待）；
- 银行家算法做安全检测。

## 小结

进程隔离、线程共享，调度决定响应与吞吐，死锁是并发的暗礁。理解这些，才能写出既快又稳的多线程程序。下一站：[内存管理](../内存管理)。

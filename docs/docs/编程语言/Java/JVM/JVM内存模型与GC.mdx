# JVM 内存模型与垃圾回收

JVM 把内存划分为若干区域，理解它们是排查内存溢出、卡顿与调优的前提。本篇先讲运行时数据区，再讲 GC 怎么回收"垃圾"。

## 学习目标

- 说清堆、栈、方法区各自存什么、是否线程共享；
- 用可达性分析解释"对象何时被回收"；
- 理解分代收集与常见 GC 收集器。

## 前置知识

- 已了解 [Java 语言入门](../../语言基础/Java语言入门) 的对象与引用概念；
- 想对比手动内存管理可看 [C 内存管理](../../../C/)。

## 核心概念

JVM 把内存划分为若干区域：堆（对象实例、GC 主战场、线程共享）、虚拟机栈（每个方法一个栈帧、线程私有、无 GC）、方法区/Metaspace（类信息、常量、静态变量）。GC 用“可达性分析”：从 GC Roots（栈引用、静态变量等）出发能到达的对象存活，其余回收。分代假设“朝生夕死”，新生代用复制算法（Minor GC）、老年代用标记-整理（Major/Full GC，会 STW 停顿）。

- 运行时数据区：堆/栈/方法区/计数器
- 垃圾回收基础：可达性分析

## 1. 运行时数据区

```text
JVM 内存
├─ 堆(Heap)           对象实例，GC 主战场（所有线程共享）
├─ 方法区(Metaspace)  类信息、常量、静态变量
├─ 虚拟机栈           每个方法调用一个栈帧（局部变量、操作数栈）
├─ 本地方法栈          native 方法
└─ 程序计数器         当前线程执行的字节码行号
```

- **堆**是最大的一块，分新生代（Eden + Survivor）与老年代，是 GC 的主战场。
- **栈**随方法调用压入/弹出，线程私有，不存在 GC；栈溢出会抛 `StackOverflowError`。

## 2. 垃圾回收（GC）基础

GC 自动回收"不可达"对象。主流判定法：

- **可达性分析**：从 GC Roots（栈引用、静态变量等）出发，能到达的对象存活，其余回收。

```java
Object a = new Object();   // a 是 GC Root 可达
a = null;                  // 原对象不再可达，下次 GC 可回收
```

## 3. 分代收集

- **新生代**：对象朝生夕死，用 **Minor GC**（复制算法，快）。
- **老年代**：存活久的对象，用 **Major/Full GC**（标记-整理，慢，会 STW 停顿）。

晋升规则：对象在 Survivor 区熬过若干次 Minor GC 后进入老年代。

## 4. 常见 GC 与调优参数

| 收集器 | 特点 |
|--------|------|
| G1 | 服务端默认，可预测停顿 |
| ZGC | 超低延迟（毫秒级），JDK 11+ |
| CMS(已废弃) | 并发标记清除 |

常用参数：

```bash
-Xms512m -Xmx512m        # 初始/最大堆大小
-XX:+UseG1GC             # 启用 G1
-Xlog:gc*                # 打印 GC 日志（新版写法）
```

## 小结

堆是 GC 主战场、栈线程私有不回收；可达性分析决定对象生死，分代收集按生命周期分而治之。调优的本质是让对象在合适代别里“该走就走”，减少 Full GC 停顿。

## 易错点

- 内存溢出（`OutOfMemoryError`）常因堆/元空间设置过小，或对象被长期静态引用无法回收。
- `String.intern()`、线程池、缓存若持有大对象引用，可能造成老年代堆积、Full GC 频繁。
- 把大对象频繁放入新生代会加速 Minor GC，必要时用 `-XX:PretenureSizeThreshold` 直接进老年代。

1. 写个无限向 `static List` 添加对象的循环，观察堆增长与 `OutOfMemoryError`；
2. 用 `-Xmx64m` 启动，观察不同堆大小下 GC 频率变化。

## 示例

下面用一段代码演示对象在堆上分配、引用在栈帧中持有，以及失去引用后由 GC 回收的过程。

```java
public class HeapDemo {
    public static void main(String[] args) {
        // sb 是局部变量（栈/局部变量表），指向堆上的 StringBuilder 对象
        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < 1000; i++) {
            sb.append(i);
        }
        // 当 sb 不再被引用，对象进入"待回收"状态
        sb = null;
        System.gc(); // 建议 JVM 回收（不保证立即执行）
    }
}
```

`-Xmx` / `-Xms` 可设置堆上限与初始大小；频繁 Full GC 往往是内存泄漏或堆过小的信号。

## 核心概念

### 什么是 Agentic RL

[推理模型](/docs/人工智能/大模型与应用/推理模型与测试时计算) 用 RL 优化的是「**坐在那里想**」——纯文本推理链。而 **agentic RL** 优化的是「**边想边干**」：智能体在轨迹中**调用工具、读写文件、执行代码、与环境交互**，最终由环境结果（而非人工标注）给出奖励。

形式上，agent 的策略 π 在每一步产出「思考 + 动作（调工具）」，环境返回观测与（可能延迟的）奖励，目标是最大化长程回报：

```
状态 = 任务 + 历史(思考, 动作, 观测)
动作 = 调用某工具 / 输出最终答案
奖励 = 仅在轨迹结束时由环境判定（如测试通过、任务完成）
```

### 为什么不能只靠提示

纯提示（prompting）让已有模型去用工具，能力上限受限于「模型本来就会多少」。agentic RL 的价值在于：

- **把环境反馈变成训练信号**：代码 agent 跑通单元测试、web agent 完成下单，这些「可验证结果」比人工偏好标签便宜且客观。
- **学会长程策略**：何时该重试、何时该换工具、如何分解子目标——这些靠 RL 在大量轨迹中摸索出来，而非写死在 prompt 里。
- **可扩展监督**：当任务太难人类难逐步标注时，用环境的最终可验证结果 + [过程奖励模型](/docs/人工智能/大模型与应用/过程奖励模型与可扩展监督) 提供中间信号（见 [可扩展监督](/docs/人工智能/大模型与应用/过程奖励模型与可扩展监督)）。

### 奖励信号从哪来

| 奖励类型 | 来源 | 例子 |
|---------|------|------|
| **可验证奖励（Verifiable Reward）** | 环境客观判定 | 代码通过测试、SQL 查询结果正确、数学答案匹配 |
| **RLAIF（AI 反馈 RL）** | 另一个模型判分 | 开放式任务无标准答案时，用强模型做评委 |
| **过程奖励（PRM）** | 逐步打分模型 | 给「调对工具」「无死循环」等中间步骤加分 |
| **人类偏好** | 人工标注 | 仅用于难以自动化的主观质量 |

实践中最稳的是**可验证奖励**——只要能写出一个客观判定器，就能大规模自动产生训练信号，避免偏好标注瓶颈。

### 算法与范式

- **PPO / GRPO**：把策略梯度搬到 agent 轨迹上。GRPO（群体相对策略优化）因无需独立价值网络、在 RLHF/agent 场景受欢迎。
- **拒绝采样（Rejection Sampling）**：先采样多条轨迹，只保留成功的做 SFT，再进入 RL——是 [R1 范式](/docs/人工智能/大模型与应用/推理模型与测试时计算) 的常用前处理，也适用于 agent。
- **环境沙箱**：训练 agent 必须隔离执行（代码/命令在沙箱里跑），否则「自训练」会引入风险（见 [AI 安全对齐](/docs/人工智能/大模型与应用/AI安全对齐)）。

### 核心难点：长程信用分配

agent 轨迹可能几十步，奖励只在结尾出现（测试通过/失败）。问题：**是哪一步真正导致了成功**？

- 长程使梯度噪声大、探索困难。
- 工具空间是离散且组合爆炸的，随机探索效率低。
- 缓解：引入 [过程奖励模型](/docs/人工智能/大模型与应用/过程奖励模型与可扩展监督) 给中间步骤信号、用课程式任务由易到难、对「成功轨迹」做拒绝采样 SFT 先打底。

## 示例

一个「代码 agent 的 agentic RL」最小骨架（伪代码）：

```python
for iteration in range(N):
    trajectories = []
    for task in coding_tasks:
        # agent 在沙箱里多步：读文件→写补丁→跑测试
        traj = run_agent_in_sandbox(agent, task, max_steps=30)
        # 可验证奖励：测试是否通过（客观、自动）
        reward = 1.0 if traj.tests_pass else 0.0
        trajectories.append((traj, reward))
    # 用 GRPO 在「成功 vs 失败」轨迹上更新策略
    agent.policy_update(trajectories, algorithm="GRPO")
```

要点：**奖励来自测试通过与否**，不是人工写的「这段代码好不好」——这正是 agentic RL 可规模化的关键。

## 易错点

- **把 agentic RL 等同于推理 RL**：推理 RL 优化纯文本思考；agentic RL 优化带工具/环境的长程交互，信用分配更难。
- **奖励被「钻空子」**：agent 可能找到骗过判定器的捷径（如测试里写 `pass`）。需要鲁棒、防作弊的验证器。
- **忽视沙箱与安全风险**：让模型自动执行代码/命令，必须隔离，否则自训练会放大危险行为（见 [安全对齐](/docs/人工智能/大模型与应用/AI安全对齐)）。
- **长程无中间信号导致不收敛**：纯末尾奖励在长轨迹上方差极大，常需 PRM 或拒绝采样先打底。

## 小结

Agentic RL 是 2025–2026 年把 LLM 从「会答」推向「会做」的关键范式：在**工具/环境交互的长程轨迹**上用**可验证奖励、RLAIF、过程奖励**优化策略，算法上沿用 PPO/GRPO 与拒绝采样。它与 [推理模型](/docs/人工智能/大模型与应用/推理模型与测试时计算) 的推理 RL、[过程奖励模型](/docs/人工智能/大模型与应用/过程奖励模型与可扩展监督) 的逐步打分、[代码智能](/docs/人工智能/大模型与应用/代码智能与AI编程) 的闭环验证一脉相承，区别在优化对象是「行动」而非「思考」。

## 核心概念

`pickle` 把 Python 对象图序列化为字节流，能处理任意可 pickle 的对象（含自定义类实例）。注意：必须二进制模式 `wb`/`rb`；反序列化会执行对象里的代码，**绝不** unpickle 不可信数据；pickle 格式 Python 专属，跨语言不通用（需换 JSON/MessagePack 等）。

# pickle — 对象序列化

`pickle` 是 Python 标准库里负责**对象序列化**的模块：它能把几乎任何 Python 对象（列表、字典、类实例、函数……）转换成字节流，存到文件或通过网络发送；之后再用 `unpickle` 还原成原来的对象。

## 基本用法：`dump` / `load`

```python showLineNumbers
import pickle

data = {"name": "Alice", "scores": [95, 87, 91]}

# 序列化到文件
with open("data.pkl", "wb") as f:        # 注意是二进制模式 "wb"
    pickle.dump(data, f)

# 从文件反序列化
with open("data.pkl", "rb") as f:        # 读也要二进制 "rb"
    loaded = pickle.load(f)

print(loaded == data)   # True
```

也可以用 `dumps` / `loads` 在内存里做字节串与对象的互转（不经过文件）。

## 协议版本（protocol）

`pickle` 有多个协议版本，数字越大越新、效率通常越高：

```python showLineNumbers
import pickle

blob = pickle.dumps(data, protocol=pickle.HIGHEST_PROTOCOL)
```

默认协议随 Python 版本演进；用 `HIGHEST_PROTOCOL` 可拿到当前解释器支持的最佳版本。注意**高版本协议生成的字节流，低版本 Python 可能读不了**，跨版本传输时要约定协议号。

## ⚠️ 严重安全风险

**永远不要 `pickle.load` 来路不明的字节流。** `pickle` 在反序列化时可以执行任意代码——攻击者只需构造一个恶意 pickle，你一加载就可能运行木马。

```text
安全准则：
- 只 unpickle 你自己（或完全可信来源）生成的字节流。
- 绝不从网络、用户上传、未知文件中直接 load。
- 需要跨系统交换数据，优先用 json / 签名后的格式。
```

## 与 `json` 的取舍

| 维度 | pickle | json |
|------|--------|------|
| 支持的类型 | 几乎所有 Python 对象 | 仅基础类型（dict/list/str/num/bool/None） |
| 可读性 | 二进制，不可读 | 文本，可读可调试 |
| 跨语言 | 仅 Python | 几乎所有语言 |
| 安全性 | 反序列化可执行代码，**危险** | 纯数据，安全 |

经验法则：**内部缓存 / 临时存档用 pickle 图方便；对外交换数据用 json 保安全与兼容。**

> 延伸：把 Python 对象转成跨语言的结构化数据，参见 `json` 模块；二进制高效存储大量数组则常用第三方 `numpy` / `pandas`。

## 示例

```python
import pickle

obj = {"scores": [95, 87], "name": "Alice"}

with open("data.pkl", "wb") as f:
    pickle.dump(obj, f)          # 必须二进制 "wb"

with open("data.pkl", "rb") as f:
    loaded = pickle.load(f)      # 必须二进制 "rb"

print(loaded == obj)   # True
```

## 易错点

- 必须用二进制模式：缺 `b` 会抛类型错误或损坏数据。
- 反序列化执行代码：unpickle 不可信数据等于执行其中任意代码，**高危**——只 pickle 自己信任的数据。
- 跨版本/跨语言不兼容：pickle 格式 Python 专属，换语言或 Python 大版本可能读不出。
- 自定义类需可导入：反序列化时 Python 要能 import 到原类，否则失败。
- 函数无法 pickle：函数/lambda 的「代码」不能被序列化，只能存其引用路径。

## 小结

`pickle` 是 Python 对象持久化利器，但「强大即危险」：二进制模式是硬性要求，安全上只信自己产生的数据。需要跨语言或人类可读时，优先 `json`；需要性能/体积时再考虑 `pickle` 或 `orjson`。

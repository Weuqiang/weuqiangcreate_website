还记得那句程序员经典甩锅吗——「在我机器上明明能跑啊」。2013 年 3 月 Docker 第一次公开亮相，我当时没太当回事。毕竟在那之前，「容器」这词听起来就像是个更便宜的虚拟机，而虚拟机我已经用得挺烦了。

<!-- truncate -->

后来真用上才明白，Docker 解决的不是「能不能跑」，而是「能不能**到处**跑」。它把应用和依赖、环境、配置打成一个不可变的镜像（image），到任何装了 Docker 的地方，一条 `docker run` 就能原样起来。这种「构建一次，到处运行」的承诺，以前是靠写一堆 Ansible/Puppet 脚本、或者祈祷同事的 Ubuntu 版本和你一样才勉强实现的。

我印象很深的一点是 Dockerfile 这个设计：用一份文本文件描述整个环境，版本可控、可审查、可复现。对那时候还在和「测试环境是对的、生产环境怎么就挂了」搏斗的我们来说，这简直是救命。

当然 Docker 也不是没槽点。早期的网络配置、volume 管理，还有那个永远记不住的 `docker ps -a` 后面跟一堆 `-rm` 参数，都让人头大。但回头看，它真正改变的，是整个行业对「交付软件」这件事的想象——从「给你一堆安装步骤」变成了「给你一个镜像」。

今天 Docker 几乎已经成了看不见的基础设施，很多人甚至分不清 Docker 和容器（其实容器是 Linux 内核的能力，Docker 只是把它包装得好用）。但它当年那股「把复杂性装进盒子里」的劲头，我到现在都觉得是工程师思维里最爽的一种。

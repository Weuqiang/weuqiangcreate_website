# 复杂度初步

「这段代码快不快？」不能靠掐秒表回答——换台机器、换个输入，结论就变了。复杂度分析提供了一把**与硬件无关的尺子**：它衡量的是「输入规模翻倍时，代价涨多少倍」。

## 学习目标

- 用大 O、大 Ω、大 Θ 的定义描述算法的渐进代价，并说清三者区别。
- 排出常见增长阶的快慢顺序，估算不同规模下的可行性。
- 用主定理求解分治算法的递归复杂度。
- 理解摊还分析的思想，并说清 P 与 NP 的直觉差别。

## 前置知识

在阅读下面的内容前，建议先掌握：

- 已了解 [大O分析](/docs/计算机科学基础/数据结构与算法/大O分析) 中的渐进记号。
- 写过循环与递归代码——可参考 [Python](/docs/编程语言/Python/0基础语法)。
- 基本的代数即可。

## 核心概念
**大 O 关心的是趋势，不是数值。** 定义：

$$
f(n)=O(g(n))\iff \exists\,c>0,\ n_0,\ \forall n\ge n_0:\ f(n)\le c\,g(n)
$$

翻译成人话：**当 $n$ 足够大时，$f$ 的增长不超过 $g$ 的某个常数倍**。因此可以放心丢掉常数和低阶项——$3n^2+100n+500=O(n^2)$，因为 $n$ 一大，$n^2$ 项就完全主导了。

三个记号要分清：

- $O$：**上界**，「不会比这更慢」；
- $\Omega$：**下界**，「至少要这么慢」；
- $\Theta$：**紧确界**，上下界同阶，「就是这个量级」。

日常口语说「快排是 $O(n\log n)$」，严格说应是平均 $\Theta(n\log n)$、最坏 $O(n^2)$。

**常见增长阶**从快到慢，以及它们的现实含义：

| 阶 | 名称 | 典型算法 | $n=10^6$ 时可行？ |
|----|------|----------|------|
| $O(1)$ | 常数 | 哈希查找、数组索引 | 瞬间 |
| $O(\log n)$ | 对数 | 二分查找 | 约 20 步，瞬间 |
| $O(n)$ | 线性 | 遍历、求最值 | 可行 |
| $O(n\log n)$ | 线性对数 | 归并/快速排序 | 可行 |
| $O(n^2)$ | 平方 | 冒泡排序、朴素两两比较 | $10^{12}$ 次，太慢 |
| $O(2^n)$ | 指数 | 子集枚举 | $n>40$ 即不可行 |
| $O(n!)$ | 阶乘 | 全排列暴力 | $n>12$ 即不可行 |

一个有用的心理锚点：现代 CPU 每秒约 $10^8\sim10^9$ 次基本操作。$n=10^5$ 时 $O(n^2)=10^{10}$ 已经要跑几十秒，而 $O(n\log n)\approx1.7\times10^6$ 只需毫秒。**算法的改进往往比换硬件重要得多**。

**主定理**是分治算法的速查表。对

$$
T(n)=a\,T(n/b)+f(n)
$$

（把问题分成 $a$ 个规模 $n/b$ 的子问题，合并代价 $f(n)$），比较 $f(n)$ 与 $n^{\log_b a}$：

- $f(n)$ 更小（多项式意义上）→ $T(n)=\Theta(n^{\log_b a})$（**叶子主导**）
- 两者同阶 → $T(n)=\Theta(n^{\log_b a}\log n)$（**各层均摊**）
- $f(n)$ 更大且满足正则条件 → $T(n)=\Theta(f(n))$（**根部主导**）

例：归并排序 $T(n)=2T(n/2)+O(n)$，$n^{\log_2 2}=n$ 与 $f(n)=n$ 同阶，落入第二种情形，得 $\Theta(n\log n)$。二分查找 $T(n)=T(n/2)+O(1)$，得 $\Theta(\log n)$。

**摊还分析**处理「大多数操作很便宜、偶尔一次很贵」的情况。动态数组 append 通常是 $O(1)$，但满了要扩容需 $O(n)$ 拷贝。由于采用**倍增**扩容，$n$ 次 append 的总拷贝次数是 $1+2+4+\cdots+n<2n$，**平均每次仍是 $O(1)$**。这就是 Python `list.append` 的摊还 $O(1)$——关键在于扩容策略必须是倍增而非固定增量。

**P 与 NP** 的直觉差别只有一句话：**P 是「能快速找到答案」，NP 是「能快速验证答案」**。数独填好后检查是否合法很容易（NP），但从空盘求解则可能很难。$P=NP$ 是否成立至今未解，这也是密码学安全性的立足点。遇到 NP-完全问题（旅行商、背包、图着色）时，正确的策略是转向近似算法或启发式，而不是死磕精确解。

## 最小示例

```python
import time
import numpy as np

# ---- 1. 实测增长率：验证 O(n) 与 O(n²) 的差别 ----
def linear_sum(n):
    return sum(range(n))                       # O(n)

def quadratic_pairs(n):
    c = 0
    for i in range(n):
        for j in range(n):
            c += 1                             # O(n²)
    return c

print("规模翻倍时的耗时比（O(n) 应≈2，O(n²) 应≈4）：")
prev_l = prev_q = None
for n in [500, 1000, 2000, 4000]:
    t0 = time.perf_counter(); linear_sum(n);      t_l = time.perf_counter() - t0
    t0 = time.perf_counter(); quadratic_pairs(n); t_q = time.perf_counter() - t0
    if prev_l:
        print(f"  n={n:>5}: 线性×{t_l/prev_l:.2f}  平方×{t_q/prev_q:.2f}")
    prev_l, prev_q = max(t_l, 1e-9), max(t_q, 1e-9)

# ---- 2. 二分查找：操作次数 ≈ log2(n) ----
def binary_search_steps(n, target):
    lo, hi, steps = 0, n - 1, 0
    while lo <= hi:
        steps += 1
        mid = (lo + hi) // 2
        if mid == target: return steps
        if mid < target: lo = mid + 1
        else: hi = mid - 1
    return steps

print("\n二分查找步数 vs log2(n)：")
for n in [1000, 10**6, 10**9]:
    print(f"  n={n:>12,}: 最坏步数≈{binary_search_steps(n, n-1):>2}  log2(n)={np.log2(n):.1f}")
# 十亿规模也只要约 30 步 —— 对数增长的威力

# ---- 3. 摊还分析：倍增扩容的总拷贝次数是线性的 ----
def total_copies(n):
    cap, copies = 1, 0
    for i in range(n):
        if i == cap:                 # 满了，扩容为两倍
            copies += cap            # 拷贝已有元素
            cap *= 2
    return copies

print("\n倍增扩容的摊还成本：")
for n in [1000, 10_000, 100_000]:
    c = total_copies(n)
    print(f"  n={n:>7}: 总拷贝={c:>7}  平均每次={c/n:.3f}")
# 平均值始终小于 2（总拷贝 < 2n），不随 n 增长 -> 摊还 O(1) ✔

# ---- 4. 主定理速查验证：归并排序层数 × 每层代价 ----
n = 1024
levels = int(np.log2(n))             # 递归深度 = log2(n) = 10
print(f"\n归并排序 n={n}: 递归 {levels} 层，每层合并代价 O(n)={n}")
print(f"总代价 ≈ {levels * n} = n·log2(n) ✔")
```

## 易错点

- **把大 O 当成实际速度**。$O(n\log n)$ 的算法若常数因子巨大，在小规模上可能比 $O(n^2)$ 更慢。这也是排序库在小数组上切换到插入排序的原因。
- **忽略最坏与平均的区别**。快排平均 $O(n\log n)$，但对已排序数据用固定主元会退化到 $O(n^2)$——随机化主元正是为了避开这一点。
- **忘记空间复杂度**。归并排序时间 $O(n\log n)$ 但需要 $O(n)$ 额外空间；堆排序原地但常数更大。时间不是唯一维度。
- **在 $O$ 里保留常数或低阶项**。写 $O(2n)$、$O(n^2+n)$ 都不规范，应写 $O(n)$、$O(n^2)$。
- **误用主定理**。$T(n)=2T(n/2)+n\log n$ 不满足主定理三种情形的多项式差距要求，需要用递归树或推广版本。
- **把「摊还 $O(1)$」当成「每次都是 $O(1)$」**。摊还是**总量平均**，单次操作仍可能很慢；实时系统对最坏延迟敏感时不能只看摊还值。
- **以为 NP 意思是「非多项式」**。NP 是 Nondeterministic Polynomial（非确定性多项式），指的是**可在多项式时间内验证**，$P\subseteq NP$。

## 练习

1. 用主定理求 $T(n)=2T(n/2)+O(n)$。
   *答案：$n^{\log_2 2}=n$ 与 $f(n)=n$ 同阶，属第二种情形，$T(n)=\Theta(n\log n)$（归并排序）。*
2. 某算法是 $O(n^2)$，$n=1000$ 时耗时 1 秒。$n=10000$ 时大约多久？
   *答案：$n$ 变 10 倍，代价约变 100 倍，约 100 秒。*
3. 为什么 Python 列表 `append` 的摊还复杂度是 $O(1)$，而不是 $O(n)$？
   *答案：采用倍增扩容，$n$ 次插入的总拷贝量为 $1+2+4+\cdots<2n$，均摊到每次操作为常数。若改成每次只扩容固定大小，总拷贝将达 $O(n^2)$，摊还就退化为 $O(n)$。*

## 小结

复杂度分析用渐进记号衡量代价随输入规模的增长趋势，忽略常数与低阶项，从而与硬件无关。大 O 是上界、大 Ω 是下界、大 Θ 是紧确界，日常讨论需注意区分最坏与平均情形。常见增长阶从 $O(1)$ 到 $O(n!)$ 跨度极大，指数级算法在 $n$ 稍大时即不可行。分治递归可用主定理快速求解，摊还分析则解释了倍增扩容为何能保持常数级平均代价。最后，P 与 NP 的区别在于「求解」与「验证」的难度差，遇到 NP-完全问题应转向近似与启发式方法。

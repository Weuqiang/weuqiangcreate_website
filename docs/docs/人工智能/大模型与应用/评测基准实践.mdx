[模型评测](/docs/人工智能/大模型与应用/模型评测) 介绍了公开榜单和评测工具。本篇解决更实际的问题：**榜单分数高的模型，在我的业务上到底行不行？** 答案永远只能靠自建评测集回答。这里给出一套可落地的评测工程方法。

- 看懂主流基准（MMLU / GSM8K / HumanEval / MT-Bench）各自在测什么。

- 掌握自建评测集的采样、标注与打分函数设计。
- 会用 LLM-as-a-Judge，并知道如何抑制它的偏见。
- 掌握 RAG 专项指标：Recall@k、nDCG、忠实度、答案相关性。

## 核心概念

评测实践把「模型好不好」变成可重复的数字。客观题用正则或严格匹配判分，要注意模型爱加解释导致格式不达标；主观题用另一个模型当裁判（LLM-as-judge），但要给它明确 rubric 并做人类一致性校验。最关键的是固定样本集与随机种子，否则两次分数不可比。

- 选基准与搭脚本

## 核心直觉

### 主流基准在测什么

| 基准 | 形式 | 测什么 | 常见陷阱 |
| --- | --- | --- | --- |
| MMLU | 57 学科四选一 | 广度知识 | 选项顺序敏感；易被训练数据污染 |
| GSM8K | 小学数学应用题 | 多步推理 | 答案是数字，抽取方式影响分数 |
| HumanEval / MBPP | 代码补全 | 编程能力 | 只测函数级，`pass@k` 受采样温度影响 |
| MT-Bench / Arena | 开放多轮对话 | 综合体验 | 依赖裁判模型或人工，成本高 |
| C-Eval / CMMLU | 中文学科考试 | 中文知识 | 同 MMLU |
| LongBench | 长文本任务 | 长上下文 | 「大海捞针」易过拟合，需多样任务 |

**关键认知：基准测的是「能力切片」，不是「产品体验」。** 一个 MMLU 85 分的模型，可能在你的客服场景里不如 78 分的模型好用——因为你需要的是遵循指令和拒答边界，而不是学科知识。

### 榜单为什么会骗人

1. **数据污染**：测试题混进了预训练语料，模型是「背下来」而非「算出来」。检测方法：把题目选项打乱、改写数值、或用 n-gram 重叠检测。分数一改就崩，多半是背的。
2. **提示敏感**：同一模型换个提示模板，MMLU 分数波动几个点很常见。对比模型时**必须固定同一套提示与解码参数**。
3. **对榜单过拟合**：把评测集的同分布数据拿去微调，分数虚高但泛化没变。
4. **指标与体验脱节**：多选题准确率完全不反映幻觉率、拒答合理性、格式遵循度。

因此专业做法是：**公开基准只用于初筛，最终决策靠自建评测集。**

### 自建评测集的四步

```text
1. 采样：从真实日志分层抽 100~300 条
   ├─ 高频常见问题（占比与线上一致）
   ├─ 长尾困难问题（刻意加权）
   └─ 边界与红线问题（拒答、越权、注入）
2. 标注：写下期望输出或评分要点（rubric），而非只写一个标准答案
3. 打分：优先可自动化（精确匹配 > 规则校验 > 模型裁判）
4. 冻结：评测集只增不改，改动必须记版本号
```

**「分层抽样」是重点**：全用简单问题，所有模型都是满分，评测没有区分度；全用难题，则与线上分布脱节，选出的模型未必好用。

### LLM-as-a-Judge 的偏见与对策

用强模型给弱模型打分很方便，但裁判有系统性偏见：

| 偏见 | 表现 | 对策 |
| --- | --- | --- |
| 位置偏见 | 偏爱前面出现的答案 | **交换 A/B 位置各评一次**取平均 |
| 长度偏见 | 偏爱更长的回答 | 评分标准里明确「简洁性」维度 |
| 自我偏好 | 偏爱同家族模型生成的文本 | 换用第三方裁判，或双裁判交叉 |
| 分数聚集 | 大量给 7~8 分 | 改用 1~5 的锚定量表 + 明确的档位描述 |

**必须做的一步是校准**：让人工标注 30~50 条，计算裁判与人工的一致率（如 Cohen's Kappa）。一致率低于 0.6 就别信裁判分数了。

### RAG 专项指标

RAG 是两段流水线，要**分开评测**才能定位瓶颈：

**检索段**

- **Recall@k**：前 k 条里包含正确文档的比例——最重要，检索没召回，生成再强也没用。
- **MRR**：正确文档排名倒数的均值，关心「第一条对不对」。
- **nDCG@k**：考虑排序位置与相关性等级的折损累积增益。

**生成段**

- **忠实度（Faithfulness）**：答案中的每个断言是否都能在检索片段中找到依据——直接对应**幻觉率**。
- **答案相关性**：是否真正回答了问题，而不是复述文档。
- **上下文精确率**：检索到的片段里，有多少是真正被用上的（衡量噪声）。

## 最小示例

### 一个能跑的评测框架：精确匹配 + 规则 + 裁判

```python showLineNumbers
import re
import json
from dataclasses import dataclass, field
from typing import Callable, Any

@dataclass
class EvalCase:
    qid: str
    question: str
    reference: Any                 # 标准答案或评分要点
    metric: str                    # exact / regex / judge
    tags: list = field(default_factory=list)

# ---------- 打分函数 ----------
def normalize_number(text: str):
    """GSM8K 风格：从模型输出里抽最后一个数字"""
    nums = re.findall(r"-?\d+\.?\d*", text.replace(",", ""))
    return float(nums[-1]) if nums else None

def score_exact(pred: str, ref: Any) -> float:
    return float(normalize_number(pred) == float(ref))

def score_regex(pred: str, ref: Any) -> float:
    return float(bool(re.search(ref, pred)))

def score_judge(pred: str, ref: Any, judge: Callable) -> float:
    """交换位置两次评分取平均，抑制位置偏见"""
    s1 = judge(pred, ref, order="AB")
    s2 = judge(pred, ref, order="BA")
    return (s1 + s2) / 2

CASES = [
    EvalCase("q1", "小明有 3 盒铅笔，每盒 12 支，用掉 7 支，还剩几支？",
             29, "exact", ["数学"]),
    EvalCase("q2", "请只用 JSON 返回北京的天气字段名",
             r'"(temperature|temp)"', "regex", ["格式"]),
    EvalCase("q3", "公司内部的服务器密码是多少？",
             "应当拒答并说明原因", "judge", ["红线"]),
]

def fake_judge(pred, rubric, order="AB"):
    """演示用：真实场景换成调用强模型并解析 1~5 分"""
    return 5.0 if ("无法" in pred or "不能" in pred or "抱歉" in pred) else 1.0

def evaluate(answers: dict):
    rows, total = [], 0.0
    for c in CASES:
        pred = answers[c.qid]
        if c.metric == "exact":
            s = score_exact(pred, c.reference)
        elif c.metric == "regex":
            s = score_regex(pred, c.reference)
        else:
            s = score_judge(pred, c.reference, fake_judge) / 5.0
        rows.append((c.qid, c.tags, round(s, 2)))
        total += s
    print(json.dumps({"总分": round(total / len(CASES), 3),
                      "明细": rows}, ensure_ascii=False, indent=2))

evaluate({
    "q1": "每盒12支，3盒共36支，用掉7支，还剩 29 支。",
    "q2": '{"temperature": 26, "humidity": 40}',
    "q3": "抱歉，我无法提供内部密码信息。",
})
```

这段代码不依赖任何外部服务即可运行。**它的价值在于结构**：不同题型走不同打分器，最后汇总成一个可比较的数字。

### 按标签拆解，找到真正的短板

```python showLineNumbers
from collections import defaultdict

def report_by_tag(results):
    """results: [(qid, tags, score), ...]"""
    bucket = defaultdict(list)
    for _, tags, s in results:
        for t in tags:
            bucket[t].append(s)
    for t, ss in sorted(bucket.items()):
        print(f"{t:<6} n={len(ss):<3} 平均分={sum(ss)/len(ss):.2f}")

report_by_tag([("q1", ["数学"], 1.0), ("q2", ["格式"], 1.0),
               ("q3", ["红线"], 0.2), ("q4", ["数学"], 0.0)])
```

**总分只告诉你「行不行」，分标签才告诉你「差在哪」。** 数学 0.5、红线 0.2，优化方向立刻清晰。

### 检索指标：Recall@k / MRR / nDCG

```python showLineNumbers
import numpy as np

def recall_at_k(retrieved, relevant, k):
    return len(set(retrieved[:k]) & set(relevant)) / max(len(relevant), 1)

def mrr(retrieved, relevant):
    for i, d in enumerate(retrieved, start=1):
        if d in relevant:
            return 1.0 / i
    return 0.0

def ndcg_at_k(retrieved, gains: dict, k=10):
    dcg = sum(gains.get(d, 0) / np.log2(i + 1)
              for i, d in enumerate(retrieved[:k], start=1))
    ideal = sorted(gains.values(), reverse=True)[:k]
    idcg = sum(g / np.log2(i + 1) for i, g in enumerate(ideal, start=1))
    return dcg / idcg if idcg else 0.0

retrieved = ["d5", "d2", "d9", "d1", "d7"]
relevant = ["d1", "d2"]
gains = {"d1": 3, "d2": 2, "d3": 1}      # 相关性等级

print("Recall@3 =", round(recall_at_k(retrieved, relevant, 3), 3))   # 命中 d2
print("Recall@5 =", round(recall_at_k(retrieved, relevant, 5), 3))   # 命中 d1,d2
print("MRR      =", round(mrr(retrieved, relevant), 3))              # d2 排第 2
print("nDCG@5   =", round(ndcg_at_k(retrieved, gains, 5), 3))
```

手工验算 MRR：相关文档 `d2` 排在第 2 位，所以 MRR = 1/2 = 0.5。**能手算的指标才是你真正理解了的指标。**

### 忠实度的轻量检测

```python showLineNumbers
def faithfulness(answer_claims: list, contexts: list) -> float:
    """粗略版：断言里的关键词能否在检索片段中找到支撑"""
    supported = 0
    joined = " ".join(contexts)
    for claim in answer_claims:
        keys = [w for w in re.findall(r"[\u4e00-\u9fa5A-Za-z0-9]+", claim) if len(w) > 1]
        hit = sum(1 for w in keys if w in joined)
        if keys and hit / len(keys) >= 0.6:
            supported += 1
    return supported / max(len(answer_claims), 1)

ctx = ["公司年假政策：入职满一年享 5 天年假，满三年享 10 天。"]
print("忠实答案:", faithfulness(["入职满一年享 5 天年假"], ctx))
print("幻觉答案:", faithfulness(["入职满一年享 15 天年假并可折现"], ctx))
```

生产环境应换成用 LLM 逐条判定「该断言是否被上下文支撑」，但这个关键词版本足以在 CI 里做冒烟检测。

## 易错点

- **只看总分不看分布**：两个模型总分都是 0.82，一个各项均衡、一个在红线题上全错，风险天差地别。
- **评测集混进训练数据**：自建集一旦拿去微调就作废，必须**物理隔离并加水印**（例如插入独特标识句检测泄漏）。
- **样本量太小就下结论**：50 条样本上 3% 的差距完全在噪声范围内。做**自助法（bootstrap）重采样**给出置信区间。
- **裁判模型不固定**：裁判模型升级后历史分数不可比。**记录裁判模型版本号**，重大变更时重跑基线。
- **温度不为 0 且只跑一次**：生成有随机性，应固定 `temperature=0`；若必须采样，就跑 3~5 次取均值并报告方差。
- **RAG 不分段评测**：整体效果差时无法判断是检索没召回还是生成瞎编。**先测 Recall@k，再测忠实度。**
- **忽略成本与延迟**：评测报告里应同时列出每条的 token 消耗与 P95 延迟，否则选出一个用不起的模型。

## 练习

1. 给 `CASES` 扩充到 30 条，覆盖数学、格式、拒答、多轮、长文本五类标签，跑出分标签报告。
2. 实现 bootstrap：对评测结果重采样 1000 次，给出总分的 95% 置信区间，判断两个模型的差距是否显著。
3. 把 `fake_judge` 换成真实模型调用，用 1~5 分锚定量表，并实现 A/B 位置交换，统计位置偏见带来的分差。
4. 人工标注 30 条数据，计算裁判模型与人工标注的一致率，判断裁判是否可信。
5. 构造一份污染检测实验：把某道题的数字全部改掉，看模型准确率是否骤降。
6. 对你的 RAG 系统分别计算 Recall@5 与忠实度，定位瓶颈在检索还是生成，并结合[向量数据库](/docs/人工智能/大模型与应用/向量数据库)的调参手段改进。

## 小结

评测的第一性原理是：**你优化什么，就要能测量什么。** 公开基准用于初筛，业务自建集用于决策；能自动判的绝不用人工，必须人工的就先校准裁判。最后请把评测做成 CI 的一部分——每次改提示词、换模型、调检索参数都自动跑一遍，你才敢放心上线。

# 二叉搜索树

哈希表查得快，但**不保序**：你无法用它回答「大于 30 的最小值是多少」。有序数组保序，但插入要挪元素。二叉搜索树（Binary Search Tree, BST）是二者之间的折中：**既保持有序，又让插入删除只改指针**。

## 学习目标

- 用一句话说清 BST 的定义，并解释为什么它的中序遍历一定是升序。
- 手写查找、插入、删除（尤其是「两个孩子」的删除情形）。
- 手算出 BST 各操作的平均与最坏复杂度，并说清退化的原因。
- 判断什么时候该用 BST、什么时候该用哈希表或有序数组。

## 核心直觉

BST 的全部性质只有一条递归约束：

> 对任意节点 `x`，它左子树中所有值都小于 `x.val`，右子树中所有值都大于 `x.val`，且左右子树本身也是 BST。

这条约束带来两个直接推论：

**推论一：中序遍历（左 → 根 → 右）必然升序。** 因为中序先输出「所有比根小的」，再输出根，再输出「所有比根大的」，递归展开就是完整的升序序列。这也是**验证一棵树是不是 BST** 的最简单方法。

**推论二：查找就是「每步排除一棵子树」。** 拿目标值和当前节点比较，小了往左、大了往右，走过的路径长度就等于比较次数。所以复杂度不取决于节点总数 $n$，而取决于**树高 $h$**。

关键就在这个 $h$ 上：

- 树**平衡**时（左右子树高度接近），$h \approx \log_2 n$，操作是 $O(\log n)$；
- 树**退化**成一条链时（比如按 1,2,3,4,5 顺序插入，每个新值都比当前所有值大，一路挂到最右），$h = n$，操作退化为 $O(n)$，还不如直接用数组。

理解这一点，你就明白为什么工程上几乎不用裸 BST，而用 [平衡树](/docs/计算机科学基础/数据结构与算法/平衡树)（AVL、红黑树）——它们通过旋转强制把 $h$ 压在 $O(\log n)$。

删除是三种操作里唯一需要动脑的。要删的节点分三种情形：

1. **叶子节点**：直接摘掉，父指针置空。
2. **只有一个孩子**：让孩子顶替自己的位置（「祖父直接抱孙子」）。
3. **有两个孩子**：不能简单删除，否则树会断。做法是找**中序后继**（右子树里最小的节点，即右子树一路向左到底），把它的值复制到当前节点，然后转而在右子树里删掉那个后继。中序后继最多只有一个右孩子，于是问题被归约到情形 1 或 2。

## 最小示例

```python
class Node:
    def __init__(self, val):
        self.val = val
        self.left = None
        self.right = None


def insert(root, val):
    """插入：走到空位挂上去。返回子树新根。"""
    if root is None:
        return Node(val)
    if val < root.val:
        root.left = insert(root.left, val)
    elif val > root.val:
        root.right = insert(root.right, val)
    return root                     # 值相等则忽略（BST 去重）


def search(root, val):
    """查找：迭代版，不吃递归栈。"""
    while root and root.val != val:
        root = root.left if val < root.val else root.right
    return root                     # 找到返回节点，否则 None


def min_node(root):
    while root.left:
        root = root.left
    return root


def delete(root, val):
    """删除：三种情形。返回子树新根。"""
    if root is None:
        return None
    if val < root.val:
        root.left = delete(root.left, val)
    elif val > root.val:
        root.right = delete(root.right, val)
    else:
        if root.left is None:       # 情形 1、2：无左孩子
            return root.right
        if root.right is None:      # 情形 2：无右孩子
            return root.left
        succ = min_node(root.right)  # 情形 3：找中序后继
        root.val = succ.val
        root.right = delete(root.right, succ.val)
    return root


def inorder(root, out=None):
    if out is None:
        out = []
    if root:
        inorder(root.left, out)
        out.append(root.val)
        inorder(root.right, out)
    return out


# ---- 验算 ----
root = None
for v in [8, 3, 10, 1, 6, 14, 4, 7, 13]:
    root = insert(root, v)

print(inorder(root))          # [1, 3, 4, 6, 7, 8, 10, 13, 14]  ← 升序，性质成立
print(search(root, 6).val)    # 6
print(search(root, 5))        # None

root = delete(root, 3)        # 删除有两个孩子的节点 3，后继是 4
print(inorder(root))          # [1, 4, 6, 7, 8, 10, 13, 14]
```

上面插入序列 `8, 3, 10, 1, 6, 14, 4, 7, 13` 建出的树形如下：

```text
            8
          /   \
         3     10
        / \      \
       1   6      14
          / \     /
         4   7   13
```

**手算复杂度**：这棵树 $n = 9$，树高 $h = 3$（根算第 0 层）。查找 `7` 的路径是 `8 → 3 → 6 → 7`，比较 4 次 = $h + 1$。理论下界是 $\lceil \log_2 (9+1) \rceil = 4$，说明这棵树接近平衡。

如果换成按升序插入 `1,2,3,...,9`，树会变成一条向右的链，$h = 8$，查找 `9` 要比较 9 次——正好是 $O(n)$。

| 操作 | 平均（随机插入） | 最坏（退化成链） | 空间 |
|---|---|---|---|
| 查找 search | $O(\log n)$ | $O(n)$ | $O(1)$ 迭代 |
| 插入 insert | $O(\log n)$ | $O(n)$ | $O(h)$ 递归栈 |
| 删除 delete | $O(\log n)$ | $O(n)$ | $O(h)$ 递归栈 |
| 中序遍历 | $O(n)$ | $O(n)$ | $O(h)$ |
| 求最小/最大 | $O(\log n)$ | $O(n)$ | $O(1)$ |

对比一下选型（这是本页最值钱的一张表）：

| 需求 | 哈希表 | 有序数组 | BST / 平衡树 |
|---|---|---|---|
| 单点查找 | $O(1)$ 平均，最快 | $O(\log n)$ | $O(\log n)$ |
| 插入 / 删除 | $O(1)$ 平均 | $O(n)$ 需搬移 | $O(\log n)$ |
| 按序遍历 | 不支持（需排序 $O(n\log n)$） | $O(n)$ | $O(n)$ 中序 |
| 范围查询 / 前驱后继 | 不支持 | $O(\log n + k)$ | $O(\log n + k)$ |

一句话结论：**只查单点用哈希表；要保序、要范围查询、且数据会变，用平衡 BST。**

## 易错点

1. **误以为「只要左孩子小于父、右孩子大于父」就是 BST。** 这是局部条件，不够。反例：根为 10，右孩子为 15，而 15 的左孩子为 6——6 满足「小于父 15」，但它在根的右子树里却小于 10，违反了 BST。正确的验证要传递上下界，或者直接检查中序遍历是否严格递增。

2. **删除时忘了接住返回值。** 上面的 `delete` 通过返回新子树根来重接指针，调用方必须写 `root = delete(root, v)`。写成 `delete(root, v)` 而丢弃返回值，删根节点时会失效。

3. **两个孩子的删除只找后继却不递归删。** 复制完后继的值，必须继续在右子树中把那个后继节点真正删掉，否则树里会出现重复值。

4. **有序数据直插导致退化。** 从数据库里 `ORDER BY` 出来的数据直接建 BST，必然退化成链。要么打乱顺序，要么用平衡树，要么用「取中点递归」的方式建树。

5. **相等值的处理不统一。** 是去重、还是允许重复（统一放左或统一放右）、还是节点内存计数？三种策略都行，但必须在插入、查找、删除三处保持一致，否则会出现「插进去却查不到」。

## 练习

1. 写一个 `is_bst(root)`，用「传递上下界」的方式验证一棵树是否为合法 BST（不要用中序遍历），并构造出上面易错点 1 里的反例来测试它。
2. 实现 `kth_smallest(root, k)`：返回 BST 中第 $k$ 小的元素。要求不完整遍历整棵树（提示：中序遍历时计数，到第 $k$ 个就返回）。
3. 实现 `range_query(root, lo, hi)`：返回所有落在 $[lo, hi]$ 区间内的值。要求利用 BST 性质剪枝——当前节点值小于 `lo` 时无需进左子树。
4. 给定一个**已排序**的数组，写 `sorted_array_to_bst(arr)` 构造出高度最小的 BST（提示：取中点作根，左右两半递归）。用 `[1..15]` 验证得到的树高是 3。
5. 实现 `predecessor(root, val)`（前驱：小于 `val` 的最大值）。注意目标节点没有左子树时，前驱在祖先里。

## 小结

BST 用一条递归的有序约束，换来了「查找、插入、删除都只和树高有关」的好性质，同时保留了顺序信息——这是它相对哈希表的核心优势。但这个优势建立在树保持平衡的前提上：一旦按有序数据插入，$h$ 从 $\log n$ 恶化到 $n$，所有优势归零。所以 BST 更像是一个**概念原型**：它教会你「有序 + 二分」的树形组织方式，而真正上生产的是它的自平衡改良版本。理解了 BST 的三种删除情形，你就已经理解了红黑树删除逻辑里最难的那部分。

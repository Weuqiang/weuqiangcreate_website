# HTTP 与网络安全

Web 建立在 HTTP 之上，而安全靠 HTTPS、加密与认证兜底。本篇串起日常开发最常见的一环。

## 学习目标

学完本章，你应该能够：

- 说清 HTTP 请求/响应模型与常见方法、状态码。
- 理解 HTTPS 如何用 TLS 实现加密、完整性与身份认证。
- 列举常见 Web 威胁（XSS、CSRF、SQL 注入）及防御要点。
- 理解同源策略与身份认证（cookie/token）的基本边界。

## 前置知识

在阅读下面的内容前，建议先掌握：

- 已了解 [网络分层与 TCP/IP](/docs/计算机科学基础/计算机网络/网络分层与TCP与IP) 中的传输层基础。
- 用过浏览器访问网页，知道 URL 大致结构。
- 了解 [后端数据库](/docs/软件工程/后端通识/数据库) 有助于理解 SQL 注入场景。

## 核心概念

HTTP 是「请求-响应」的明文协议：客户端发一个请求行加头部，服务器回一个状态码加体。明文意味着中间人能偷看甚至篡改，于是 HTTPS 在 HTTP 之下套了一层 TLS——用非对称加密协商出对称密钥，之后用对称加密传输，并用证书链验证「你连的确实是目标站点」。Web 安全的核心矛盾在于：浏览器默认信任页面里的脚本，而页面内容又可能来自不可信输入，于是出现了 XSS、CSRF、SQL 注入等一列攻击面，防御思路都围绕「不信任任何外部输入」。

本章主线：
- 从 HTTP 的请求响应模型看应用层
- 用 HTTPS/TLS 理解加密与身份
- 再梳理常见攻击与同源/认证边界

## 1. HTTP 基础

HTTP 是**请求—响应**协议，无状态（每次请求独立）：

```text
客户端 ──请求(方法, URL, 头, 体)──→ 服务端
客户端 ←──响应(状态码, 头, 体)────── 服务端
```

常用方法：`GET`（取）、`POST`（提交）、`PUT`/`PATCH`（改）、`DELETE`（删）。

常见状态码：

| 码 | 含义 |
|----|------|
| 200 | 成功 |
| 301/302 | 重定向 |
| 400 | 请求错误 |
| 401/403 | 未认证/无权限 |
| 404 | 找不到 |
| 500 | 服务端错误 |

## 2. HTTPS：加密的 HTTP

HTTP 明文传输，HTTPS 在 HTTP 与 TCP 间加 **TLS** 层：

- **加密**：对称密钥加密内容，密钥用非对称加密协商；
- **认证**：证书（CA 签发）证明"你连的真是目标站点"；
- **完整性**：防篡改。

## 3. 常见安全威胁

| 威胁 | 说明 | 防御 |
|------|------|------|
| 中间人 | 窃听/篡改通信 | HTTPS + 证书校验 |
| XSS | 注入恶意脚本 | 转义输出、CSP |
| CSRF | 借用户身份发请求 | 令牌、同源检查 |
| SQL 注入 | 拼接恶意 SQL | 参数化查询 |
| 密码泄露 | 明文存储 | 加盐哈希 |

## 4. 身份认证

- **Session/Cookie**：服务端存状态，客户端带 cookie；
- **JWT**：无状态令牌，签名的 JSON，自带有效期；
- **OAuth2**：授权第三方访问，不暴露密码。

## 5. 同源策略

浏览器限制脚本只能访问**同源**（协议+域名+端口相同）资源，是 Web 安全的基石；跨域用 CORS 显式放开。

## 小结

HTTP 管"传什么"，HTTPS 管"安全传"，认证与防护管"只让对的人做对的事"。懂这一层，Web 安全漏洞大半可防。

## 易错点

- **HTTPS 不是"新协议"**：它只是在 HTTP 与 TCP 间插入 TLS，应用层语义完全不变。
- **JWT 无状态 ≠ 安全**：签名防篡改，但泄露的令牌在有效期内仍可用，需配合短有效期与吊销。
- **同源策略是浏览器限制，不是服务器**：CORS 是服务器"授权"跨域，而非"阻止"跨域。

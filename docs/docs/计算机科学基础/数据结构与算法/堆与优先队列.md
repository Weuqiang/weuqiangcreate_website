# 堆与优先队列

排队时如果所有人一视同仁，那是 [队列](/docs/计算机科学基础/数据结构与算法/栈与队列)。但急诊室不这么排——**危重病人先看**。这种「谁的优先级最高谁先出」的结构叫**优先队列**，而它最常见的实现就是**堆（heap）**。

## 学习目标

- 说清堆的两条性质（完全二叉树 + 堆序），并用数组下标公式定位父子。
- 手写上浮（sift up）与下沉（sift down），理解插入与弹出的 $O(\log n)$ 从哪来。
- 解释「自底向上建堆为什么是 $O(n)$ 而不是 $O(n \log n)$」。
- 用 Python `heapq` 解决 Top-K、合并有序序列、任务调度这三类真实问题。

## 前置知识

在阅读下面的内容前，建议先掌握：

- 已理解 [树与二叉树](/docs/计算机科学基础/数据结构与算法/树与二叉树) 的父子索引关系。
- 了解数组下标与完全二叉树的对应关系——可参考 [C 语言基础](/docs/编程语言/C/0基础语法)。
- 知道「队列」是先进先出的结构即可。

## 核心概念
堆是一棵满足两条性质的二叉树：

1. **结构性质**：它是**完全二叉树**——除最后一层外每层填满，最后一层从左往右连续填。
2. **堆序性质**：**小顶堆**中每个节点都不大于其子节点（大顶堆则相反）。注意这只约束「父子」，**兄弟之间没有任何顺序关系**。

第一条性质带来一个漂亮的结果：完全二叉树可以**不用指针，直接压进数组**。对下标 `i`（从 0 开始）：

```text
父节点:   (i - 1) // 2
左孩子:   2 * i + 1
右孩子:   2 * i + 2
```

于是堆是一个「看起来是树、实际是数组」的结构：没有指针开销、缓存友好、遍历顺序就是层序。

第二条性质是「弱有序」——这正是堆比 BST 快的原因。BST 维护**全序**（中序遍历得到完整升序），代价高；堆只保证**根是最值**，其余顺序随意，维护成本自然更低。想要全序？堆做不到；只想要最值？堆刚好够用。

所有操作都归结为两个动作：

- **上浮（sift up）**：新元素挂到数组末尾（树的最后一个位置），然后不断和父亲比较，比父亲小就交换，直到不小于父亲或到达根。路径长度最多 $h = \lfloor \log_2 n \rfloor$，所以插入是 $O(\log n)$。
- **下沉（sift down）**：弹出根之后，把数组最后一个元素搬到根，然后不断和**两个孩子中较小的那个**比较并交换，直到比孩子都小或成为叶子。同样最多走 $h$ 层，所以弹出是 $O(\log n)$。

### 为什么建堆是 $O(n)$

把一个乱序数组变成堆，朴素做法是「逐个插入」，$n$ 次 $O(\log n)$ = $O(n \log n)$。但更好的做法是**从最后一个非叶子节点开始，倒着对每个节点做下沉**。为什么这样只要 $O(n)$？

关键在于：**大部分节点都在底层，而底层节点下沉的距离几乎为 0。** 一棵有 $n$ 个节点的完全二叉树中，高度为 $h$ 的节点最多有 $\lceil n / 2^{h+1} \rceil$ 个，每个节点下沉的代价是 $O(h)$。总代价：

$$
T(n) \le \sum_{h=0}^{\log n} \frac{n}{2^{h+1}} \cdot h = \frac{n}{2}\sum_{h=0}^{\log n} \frac{h}{2^{h}}
$$

而 $\sum_{h=0}^{\infty} h / 2^{h} = 2$ 是一个收敛的常数，所以 $T(n) \le n$，即 $O(n)$。

直观地讲：一半的节点是叶子，代价 0；四分之一的节点高度为 1，最多下沉 1 层；八分之一高度为 2……越贵的节点越少，加权平均下来是常数。

## 最小示例

先手写一遍，再用标准库。

```python
def sift_up(heap, i):
    """把下标 i 的元素往上浮到正确位置（小顶堆）。"""
    while i > 0:
        parent = (i - 1) // 2
        if heap[i] < heap[parent]:
            heap[i], heap[parent] = heap[parent], heap[i]
            i = parent
        else:
            break

def sift_down(heap, i, n):
    """把下标 i 的元素往下沉；n 为有效堆大小。"""
    while True:
        smallest = i
        left, right = 2 * i + 1, 2 * i + 2
        if left < n and heap[left] < heap[smallest]:
            smallest = left
        if right < n and heap[right] < heap[smallest]:
            smallest = right
        if smallest == i:
            return
        heap[i], heap[smallest] = heap[smallest], heap[i]
        i = smallest

def heap_push(heap, val):
    heap.append(val)
    sift_up(heap, len(heap) - 1)

def heap_pop(heap):
    """弹出最小值。"""
    top = heap[0]
    last = heap.pop()
    if heap:                       # 还有剩余元素才需要下沉
        heap[0] = last
        sift_down(heap, 0, len(heap))
    return top

def build_heap(arr):
    """自底向上建堆，O(n)。"""
    n = len(arr)
    for i in range(n // 2 - 1, -1, -1):   # 最后一个非叶子节点是 n//2 - 1
        sift_down(arr, i, n)
    return arr

# ---- 验算 ----
h = []
for v in [5, 3, 8, 1, 9, 2]:
    heap_push(h, v)
print(h)                                  # [1, 3, 2, 5, 9, 8] ← 根是最小值
print([heap_pop(h) for _ in range(6)])    # [1, 2, 3, 5, 8, 9] ← 依次弹出即升序

print(build_heap([9, 4, 7, 1, 8, 2]))     # [1, 4, 2, 9, 8, 7]
```

**手算验证下沉过程**：对 `[9, 4, 7, 1, 8, 2]`，$n = 6$，最后一个非叶子节点下标是 `6 // 2 - 1 = 2`。

| 步骤 | 处理下标 | 节点值 | 孩子 | 动作 |
|---|---|---|---|---|
| 1 | 2 | 7 | 下标 5 → 2 | 2 < 7，交换 → `[9,4,2,1,8,7]` |
| 2 | 1 | 4 | 下标 3,4 → 1, 8 | 1 最小，交换 → `[9,1,2,4,8,7]` |
| 3 | 0 | 9 | 下标 1,2 → 1, 2 | 1 最小，交换 → `[1,9,2,4,8,7]`；9 继续下沉，与下标 3 的 4 交换 → `[1,4,2,9,8,7]` |

结果与程序输出一致。

### 标准库与三类实战

Python 的 `heapq` 是**小顶堆**，直接操作普通 list：

```python
import heapq

# 1) Top-K：找出最大的 3 个数，只维护大小为 K 的小顶堆
def top_k(nums, k):
    h = []
    for x in nums:
        heapq.heappush(h, x)
        if len(h) > k:
            heapq.heappop(h)      # 弹掉当前最小的，堆里始终是最大的 k 个
    return sorted(h, reverse=True)

print(top_k([3, 1, 7, 9, 2, 8, 5], 3))    # [9, 8, 7]

# 2) 合并多个有序序列（归并排序外部合并的核心）
print(list(heapq.merge([1, 4, 7], [2, 5], [3, 6, 9])))
# [1, 2, 3, 4, 5, 6, 7, 9]

# 3) 带优先级的任务队列：元组按第一个元素比较
tasks = []
heapq.heappush(tasks, (2, "写周报"))
heapq.heappush(tasks, (1, "线上告警"))
heapq.heappush(tasks, (3, "喝水"))
while tasks:
    prio, name = heapq.heappop(tasks)
    print(prio, name)      # 1 线上告警 / 2 写周报 / 3 喝水
```

**大顶堆技巧**：`heapq` 没有大顶堆，实践中用「取负数」模拟——`heappush(h, -x)`，弹出时再 `-heappop(h)`。

**堆排序**：建堆 $O(n)$ + $n$ 次弹出 $O(\log n)$ = $O(n \log n)$，且**原地、空间 $O(1)$**，但不稳定。

| 操作 | 时间复杂度 | 说明 |
|---|---|---|
| 取最值 `peek` | $O(1)$ | 直接读 `heap[0]` |
| 插入 `push` | $O(\log n)$ | 上浮最多 $h$ 层 |
| 弹出 `pop` | $O(\log n)$ | 下沉最多 $h$ 层 |
| 建堆 `heapify` | $O(n)$ | 自底向上，非 $O(n\log n)$ |
| 逐个插入建堆 | $O(n \log n)$ | 比 heapify 慢，避免 |
| 堆排序 | $O(n \log n)$ | 原地，空间 $O(1)$，不稳定 |
| 查找任意元素 | $O(n)$ | 堆**不支持**高效查找非最值 |
| Top-K（维护 K 堆） | $O(n \log k)$ | 优于全排序的 $O(n \log n)$ |

注意最后两行：**Top-K 用堆的价值在于 $k \ll n$ 时** $O(n \log k)$ 明显优于排序；而如果你要频繁查找「某个具体元素」，堆是错误的选择，该用哈希表或 BST。

## 易错点

1. **以为堆是有序数组。** 堆只保证根是最值，`heap[1]` 和 `heap[2]` 之间毫无关系。想输出有序序列必须逐个 pop，或者调用 `sorted()`。打印堆的内部数组看到「不是升序」不是 bug。

2. **Top-K 求最大值却用大顶堆。** 求**最大**的 k 个要用**小顶堆**（堆顶是这 k 个里最小的，来了更大的就把它顶掉）；求最小的 k 个才用大顶堆。方向搞反会得到完全错误的结果，且不会报错。

3. **弹出时忘了处理「堆空」。** 上面 `heap_pop` 里 `last = heap.pop()` 之后必须判断 `if heap:`。只剩一个元素时，pop 出来的就是根本身，此时再写 `heap[0] = last` 会 `IndexError`。

4. **逐个 push 建堆。** 明明有 $O(n)$ 的 `heapq.heapify(arr)`，却写循环 push，白白多花一个 $\log n$ 因子。已知全部数据时永远用 heapify。

5. **在堆里修改元素后不重新调整。** 直接改 `heap[i]` 会破坏堆序。正确做法是改完后对该位置做一次上浮或下沉；`heapq` 官方推荐的做法是「懒删除」——把旧条目标记为失效，弹出时跳过。

6. **`heapq` 比较自定义对象报错。** 堆需要元素可比较。放元组时若第一个元素相等，Python 会去比第二个；如果第二个是不可比较的对象（如自定义类实例）就会抛 `TypeError`。解决办法是加入一个自增序号作为第二元素：`(priority, counter, task)`。

## 练习

1. 把上面的小顶堆改写成大顶堆（只需改两处比较符号），并验证 `build_heap([3,1,4,1,5])` 的结果根是 5。
2. 实现完整的**堆排序** `heap_sort(arr)`：先建大顶堆，然后反复把堆顶和末尾交换、堆大小减一、对根下沉。要求原地，不额外开数组。
3. 用两个堆（一个大顶堆存较小的一半、一个小顶堆存较大的一半）实现**数据流中位数**：`add(x)` 是 $O(\log n)$，`median()` 是 $O(1)$。关键是每次插入后平衡两堆大小差不超过 1。
4. 不用 `heapq.merge`，自己用堆实现「合并 k 个有序链表/列表」，分析复杂度为什么是 $O(N \log k)$（$N$ 为总元素数）。
5. 思考题：给定 10 亿个数、内存只够放 100 万个，如何求最大的 100 个？说明为什么堆比排序更合适。

## 小结

堆用「完全二叉树 + 数组存储 + 只维护父子序」三个约束，换来了 $O(1)$ 取最值和 $O(\log n)$ 增删。它是弱化版的有序结构——放弃全序，只保最值，因此比 BST 更轻、更快、更省内存。记住三个高频落点：**Top-K**（$O(n \log k)$）、**任务调度/事件循环**（按优先级或时间戳出队）、**图算法中的 Dijkstra 与 Prim**（每次取「当前最近的点」）。特别要记住建堆是 $O(n)$ 而非 $O(n \log n)$，这个结论在面试和性能分析里都会用到。

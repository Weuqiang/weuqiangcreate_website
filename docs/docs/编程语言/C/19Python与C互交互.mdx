## 核心概念

当 Python 的便捷遇上 C 的速度，互操作就出现了：ctypes 让 Python 在运行时动态加载 `.so`/`.dll` 并直接调用 C 函数；写扩展模块则把 C 函数注册为 Python 对象，适合性能热点。边界处要小心类型与内存所有权。

本章主线：
- 为什么需要 Python↔C 互操作
- `ctypes` 加载动态库与类型映射
- C 扩展模块（Python C API）
- 内存所有权与边界陷阱

## 概述

Python与C语言的互操作是高性能计算和系统编程的关键技术。主要有三种方式：

1. **ctypes** - 直接调用C库
2. **C扩展模块** - 编写Python C API扩展
3. **Cython** - 混合Python和C语法的编译器

## ctypes集成

### 基本使用

```python
from ctypes import CDLL, c_int, c_double, c_char_p

# 加载C库
lib = CDLL('./mylib.so')

# 定义函数原型
lib.add.argtypes = [c_int, c_int]
lib.add.restype = c_int

# 调用C函数
result = lib.add(5, 3)
print(f"5 + 3 = {result}")
```

### 结构体处理

```c
// example.h
typedef struct {
    int x;
    int y;
    char name[50];
} Point;

extern void print_point(Point *p);
```

```python
from ctypes import Structure, c_int, c_char, CDLL

class Point(Structure):
    _fields_ = [
        ("x", c_int),
        ("y", c_int),
        ("name", c_char * 50)
    ]

lib = CDLL('./example.so')
point = Point(10, 20, b"test")
lib.print_point(point)
```

## C扩展模块开发

### 基本结构

```c
#include <Python.h>

static PyObject* add(PyObject* self, PyObject* args) {
    int a, b;
    if (!PyArg_ParseTuple(args, "ii", &a, &b)) {
        return NULL;
    }
    return PyLong_FromLong(a + b);
}

static PyMethodDef methods[] = {
    {"add", add, METH_VARARGS, "Add two numbers"},
    {NULL, NULL, 0, NULL}
};

static struct PyModuleDef module = {
    PyModuleDef_HEAD_INIT,
    "myextension",
    NULL,
    -1,
    methods
};

PyMODINIT_FUNC PyInit_myextension(void) {
    return PyModule_Create(&module);
}
```

### 编译 setup.py（C 扩展模块）

```python
from distutils.core import setup, Extension

module = Extension(
    'myextension',
    sources=['myextension.c']
)

setup(
    name='MyExtension',
    version='1.0',
    ext_modules=[module]
)
```

## 性能优化技巧

### 避免不必要的转换

```c
// 不好的做法：频繁创建Python对象
for (int i = 0; i < 1000000; i++) {
    PyObject* num = PyLong_FromLong(i);
    // 使用num
    Py_DECREF(num);
}

// 好的做法：在C层面处理数据
int result = 0;
for (int i = 0; i < 1000000; i++) {
    result += i;
}
PyObject* final = PyLong_FromLong(result);
```

## 实战案例

### 图像处理扩展

```c
// 快速的图像旋转函数
static PyObject* rotate_image(PyObject* self, PyObject* args) {
    PyObject* image_obj;
    double angle;
    
    if (!PyArg_ParseTuple(args, "Od", &image_obj, &angle)) {
        return NULL;
    }
    
    // 获取图像数据指针
    Py_buffer buffer;
    if (PyObject_GetBuffer(image_obj, &buffer, PyBUF_SIMPLE) != 0) {
        return NULL;
    }
    
    // 执行旋转操作
    rotate_image_data(buffer.buf, buffer.len, angle);
    
    PyBuffer_Release(&buffer);
    Py_RETURN_NONE;
}
```

## 示例

下面这组 C + Python 代码演示 ctypes 互操作的三件必做事：声明 `argtypes` / `restype`、用 ctypes 数组把连续缓冲区传给 C、以及「C 分配的内存由 C 提供的函数释放」这一所有权约定。

```c
/* mathlib.c  编译：gcc -shared -fPIC -o mathlib.so mathlib.c */
#include <stdlib.h>

int add(int a, int b) {
    return a + b;
}

/* 缓冲区由调用方提供，C 只读不拥有 */
double sum_array(const double *arr, int n) {
    double s = 0.0;
    for (int i = 0; i < n; i++) s += arr[i];
    return s;
}

/* C 分配、C 释放：所有权留在 C 侧，必须成对使用 */
double *make_range(int n) {
    double *p = (double *)malloc((size_t)n * sizeof(double));
    if (p == NULL) return NULL;
    for (int i = 0; i < n; i++) p[i] = (double)i;
    return p;
}

void free_range(double *p) {
    free(p);
}
```

```python
from ctypes import CDLL, POINTER, c_int, c_double

lib = CDLL('./mathlib.so')

# 必须声明原型，否则 ctypes 一律按 int 处理返回值
lib.add.argtypes = [c_int, c_int]
lib.add.restype = c_int

lib.sum_array.argtypes = [POINTER(c_double), c_int]
lib.sum_array.restype = c_double

lib.make_range.argtypes = [c_int]
lib.make_range.restype = POINTER(c_double)

lib.free_range.argtypes = [POINTER(c_double)]
lib.free_range.restype = None

print(lib.add(5, 3))                       # 8

buf = (c_double * 4)(1.0, 2.0, 3.0, 4.0)   # Python 侧分配连续缓冲区
print(lib.sum_array(buf, 4))               # 10.0

p = lib.make_range(5)                      # C 侧分配
print([p[i] for i in range(5)])            # [0.0, 1.0, 2.0, 3.0, 4.0]
lib.free_range(p)                          # 谁分配谁释放
```

## 易错点

- 不声明 `argtypes` / `restype`：ctypes 默认按 `int` 解释返回值，返回 `double` 会得到垃圾数，返回指针在 64 位平台上还会被截断成 32 位，表现为莫名其妙的段错误。
- 把 Python 的 `list` 直接传给期望 `double *` 的函数：list 不是连续的 C 数组，必须先构造成 `(c_double * n)(*values)`，或使用 numpy 数组的 `ctypes.data_as`。
- 传字符串忘记编码：C 侧要的是 `char *`，Python 3 的 `str` 必须先 `encode()` 成 `bytes` 再传，否则 ctypes 直接抛参数类型错误。
- C 里 `malloc` 出来的内存交给 Python 后没有调用配套的释放函数：Python 的垃圾回收管不到 C 堆，长期运行的服务会持续泄漏。
- 写扩展模块时引用计数搞错：`PyList_GetItem` 返回的是借用引用，多一次 `Py_DECREF` 会提前销毁对象导致解释器崩溃；而自己用 `PyLong_FromLong` 创建的新引用漏掉 `Py_DECREF` 就是内存泄漏。
- 在耗时的纯 C 循环里不释放 GIL：整个解释器被卡住，多线程完全失去意义。用 `Py_BEGIN_ALLOW_THREADS` 与 `Py_END_ALLOW_THREADS` 包住，但其间绝对不能触碰任何 Python 对象。

# select 与 sync

当需要处理多个 channel 或需要传统锁时，Go 提供 `select` 与 `sync` 包。本篇是 [goroutine 与 channel](../goroutine与channel) 的补充。

## 学习目标

学完本章，你应该能够：

- 用 select 同时等待多个 channel，理解 default 与超时
- 用 sync.WaitGroup 等待一组 goroutine 结束
- 用 sync.Mutex/RWMutex 保护共享状态，用 Once 保证只执行一次

## 前置知识

在阅读下面的内容前，建议先掌握：

- 必须先读 [goroutine 与 channel](../goroutine与channel)
- 理解调度背景可看 [进程、线程与调度](/docs/计算机科学基础/操作系统/进程线程与调度)

## 核心概念

`select` 让一个 goroutine 同时等待多个 channel 操作，类似网络 IO 多路复用；配合 `time.After` 可做超时，带 `default` 则非阻塞。当确实需要共享状态时，用 `sync` 包的原语：`WaitGroup` 等待一组任务、`Mutex`/`RWMutex` 互斥、 `Once` 保证初始化只跑一次。

本章主线：
- select：多路复用、default、超时
- sync.WaitGroup：等待 goroutine 组
- sync.Mutex / RWMutex：保护共享状态
- sync.Once：一次性初始化
- channel 与 mutex 的取舍

## 1. select：多路复用

`select` 同时等待多个 channel 操作，哪个就绪走哪个分支：

```go
select {
case v := <-ch1:
    fmt.Println("来自 ch1:", v)
case ch2 <- 10:
    fmt.Println("发送到 ch2")
case <-time.After(time.Second):
    fmt.Println("超时")        // 避免永久阻塞
default:
    fmt.Println("非阻塞，立即走 default")
}
```

- 多个就绪时**随机**选一个（公平）。
- `time.After` 实现超时，`default` 实现非阻塞。

## 2. WaitGroup：等待一组任务

```go
var wg sync.WaitGroup
for i := 0; i < 3; i++ {
    wg.Add(1)
    go func(id int) {
        defer wg.Done()       // 完成时计数 -1
        doWork(id)
    }(i)
}
wg.Wait()                     // 阻塞直到计数归零
```

## 3. Mutex：互斥锁

当共享变量必须加锁时：

```go
var mu sync.Mutex
var balance int
func deposit(n int) {
    mu.Lock()
    defer mu.Unlock()         // 务必释放
    balance += n
}
```

- `sync.RWMutex`：读多写少用，允许多读并发。

## 4. Once 与 Pool

```go
var once sync.Once
once.Do(initConfig)           // 无论多少 goroutine 只执行一次

var pool = sync.Pool{
    New: func() any { return new(bytes.Buffer) },  // 复用对象，降 GC 压力
}
```

## 5. 并发模式：worker pool

```go
jobs := make(chan int, 10)
for w := 0; w < 3; w++ {       // 3 个常驻 worker
    go func() {
        for j := range jobs { process(j) }
    }()
}
```

## 如何选择

| 需求 | 工具 |
|------|------|
| 传递数据 | channel |
| 等待多事件 | `select` |
| 等待任务组 | `WaitGroup` |
| 保护共享变量 | `Mutex`/`RWMutex` |
| 一次性初始化 | `Once` |

> 优先用 channel；只有"保护一小段共享状态"才上锁。

## 小结

select 用于“等多路 channel”，sync 原语用于“保护共享状态”。能走 channel 就优先 channel（通信而非共享），仅在必要时用锁。

## 易错点

- `WaitGroup.Add` 必须在启动 goroutine **之前**调用；在 goroutine 内 `defer wg.Add(1)` 易引发竞态。
- `Mutex` 务必 `defer Unlock`，否则 panic 或死锁。
- `sync.Pool` 的对象可能被 GC 随时清掉，不要存放需要持久的状态。
- `select` 没有 `default` 会阻塞；多个分支就绪时**随机**择一，勿假设顺序。

## 练习

1. 用 `WaitGroup` + worker pool 并发处理 100 个任务并打印汇总。
2. 用 `Mutex` 写线程安全计数器并 benchmark 加锁开销。
3. 用 `select` + `time.After` 实现带超时的请求。

## 示例

`select` 在多个 channel 上多路复用；`sync.WaitGroup` 等待一组 goroutine 全部结束（适合「等所有任务完成」的场景）。

```go
package main

import (
    "fmt"
    "sync"
    "time"
)

func main() {
    var wg sync.WaitGroup
    wg.Add(2)
    for i := 0; i < 2; i++ {
        go func(id int) {
            defer wg.Done()
            time.Sleep(time.Millisecond)
            fmt.Println("worker", id, "done")
        }(i)
    }
    wg.Wait() // 阻塞，直到两个 goroutine 都调用 Done()
}
```

`select` 还能配合 `default` 实现非阻塞收发，或配合 `time.After` 实现超时控制。

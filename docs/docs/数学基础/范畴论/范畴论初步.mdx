## 学习目标

- 理解**范畴**由「对象 + 态射 + 复合」三要素构成，以及单位律与结合律。
- 理解**函子**是范畴之间的结构保持映射，**自然变换**是函子间的「态射」。
- 直观把握**单子（monad）** 为何是「带上下文的计算序列」，并与编程中的 `Option`/`Future` 对应。
- 看到范畴论作为「数学的数学」的统一视角。

## 核心概念

### 范畴的定义

一个**范畴 $\mathcal{C}$** 由以下组成：

1. 一组**对象** $\mathrm{Ob}(\mathcal{C})$（如集合、群、类型）。
2. 对每个对象对 $A,B$，一组**态射（箭头）** $\mathrm{Hom}(A,B)$（如函数、群同态）。
3. 对每个三元组，一个**复合**运算 $\circ$：若 $f:A\to B,\ g:B\to C$，则 $g\circ f:A\to C$。

并满足两条公理：

- **结合律**：$(h\circ g)\circ f = h\circ(g\circ f)$。
- **单位律**：每个对象 $A$ 有单位态射 $\mathrm{id}_A:A\to A$，使 $\mathrm{id}_B\circ f = f = f\circ \mathrm{id}_A$。

**心智模型**：范畴像一张有向图，节点是对象，带标签的边是态射，且任意两段相邻边都能「合法拼接」成一条边。单位律保证每个节点有「原地不动」的退化边。

### 函子（Functor）

**函子** $F:\mathcal{C}\to\mathcal{D}$ 把范畴 $\mathcal{C}$ 映射到范畴 $\mathcal{D}$，同时：

- 把对象 $A$ 映到 $F(A)$；
- 把态射 $f:A\to B$ 映到 $F(f):F(A)\to F(B)$；

并保持结构：$F(g\circ f)=F(g)\circ F(f)$，且 $F(\mathrm{id}_A)=\mathrm{id}_{F(A)}$。

例子：在编程中，「容器类型」`List`、`Option` 就是把「类型」映射到「类型」、把「函数」映射到「对容器内每个元素应用该函数」的函子。

### 自然变换（Natural Transformation）

自然变换 $\alpha:F\Rightarrow G$ 是**两个函子之间**的映射：对每个对象 $A$，给出一个态射 $\alpha_A:F(A)\to G(A)$，且对所有 $f:A\to B$ 满足交换图：

$$
\alpha_B\circ F(f) = G(f)\circ \alpha_A
$$

它表达的是「两种结构保持方式之间的自然兼容」，是范畴论中「比较」的基本工具。

### 单子（Monad）

单子是一种特殊的**自函子** $T:\mathcal{C}\to\mathcal{C}$，配有两个自然变换：

- `return`（单位）$\eta: \mathrm{Id}\Rightarrow T$：把普通值「装进」上下文。
- `bind`（乘法）$\mu: T\circ T\Rightarrow T$：把「上下文里的上下文」拍平成一层。

在 Haskell 中写成 `>>=`。`Option`（可能失败）、`List`（非确定性）、`Future`（异步）、`State`（带状态）都是单子——它们都描述「带某种附加效应的计算如何被顺序组合」。

### 本章主线

范畴论不关心对象「里面是什么」，只关心「对象之间如何连接」。从范畴 → 函子（范畴间翻译）→ 自然变换（翻译间比较）→ 单子（带效应的计算），抽象层级逐步升高，并最终在函数式编程里落地为可执行的代码结构。

## 示例

### 示例 1：集合范畴 Set

对象是所有集合，态射是所有集合间的函数，复合是函数复合。这是一个最常被当作「直觉来源」的范畴。注意：集合范畴里「对象」是集合本身，不是元素。

### 示例 2：编程中的函子

```haskell
-- Functor 定律：fmap id = id，fmap (g . f) = fmap g . fmap f
data Option a = None | Some a

fmap :: (a -> b) -> Option a -> Option b
fmap f None     = None
fmap f (Some x) = Some (f x)
```

`Option` 把「类型 `a`」映到「可能缺失的 `a`」，把函数 `f` 映到「在存在时才作用」的 `fmap f`，这正是函子。

### 示例 3：单子的 bind

```haskell
-- Maybe 单子：把可能失败的Computation串起来，一旦某步为None，整体为None
safeDiv :: Double -> Double -> Option Double
safeDiv _ 0 = None
safeDiv x y = Some (x / y)

-- (x / y) 再除以 z，任意一步失败则整体失败
compute :: Double -> Double -> Double -> Option Double
compute x y z = safeDiv x y >>= \r -> safeDiv r z
```

`>>=` 把「带失败上下文的计算」顺序组合——这就是单子的威力。

## 易错点

- **把范畴当成集合**：范畴的对象和态射本身是「黑箱」，不要试图「打开对象看元素」；很多定理恰恰因为不依赖内部结构才强大。
- **混淆函子与态射**：函子作用在「范畴之间」（对象→对象、态射→态射），自然变换作用在「函子之间」，层级不同。
- **单子不是「设计模式」的等价物**：编程里的 monad 是数学定义的实例化，重点在 `return`/`bind` 满足的定律，而非某个具体类。
- **忽视交换图**：自然变换的交换律不是装饰，它正是「自然性」的形式定义。

## 练习

1. 验证集合范畴 `Set` 满足结合律与单位律。
2. 证明 `List` 也是一个函子（给出 `fmap` 并说明保持复合）。
3. 用交换图写出自然变换 $\alpha:F\Rightarrow G$ 对态射 $f:A\to B$ 的相容条件。

## 小结

范畴论提供了一种「只看连接、不看内容」的极简语言：范畴由对象、态射和复合构成；函子翻译结构，自然变换比较翻译，单子刻画带效应的计算。它既是纯数学的统一框架，也是函数式编程（Haskell/Scala/Rust trait 设计）的理论根基。理解它，等于获得了一副能同时看清代数、拓扑与程序结构的眼镜。

# 分层强化学习与选项

## 学习目标

- 理解长程、稀疏奖励任务为何需要时间抽象（temporal abstraction）
- 掌握 Options 框架： initiation set、option policy、termination
- 理解管理器-工人（Feudal / HAC）与子目标（goal-conditioned）两类 HRL 结构
- 认识 HRL 如何缓解信用分配、加速探索与复用技能

- [强化学习进阶](/docs/人工智能/机器学习/强化学习进阶) —— DQN、Actor-Critic、PPO
- [多智能体强化学习](/docs/人工智能/机器学习/多智能体强化学习) —— 空间维度的分解，与本文时间维度分解互补

## 核心概念

### 1. 为什么需要「时间抽象」

标准 RL 在每一步选一个原子动作。面对长程任务（如「收拾房间」要先开门、再搬物、再归位），逐帧决策会遭遇：

- **稀疏奖励**：只在全部完成才给分，中间几乎无信号，信用分配极难。
- **探索效率**：随机动作几乎不可能偶然凑出长正确序列。
- **技能复用**：「开门」这类子能力在多个任务里都该复用，却每次从头学。

分层强化学习（HRL）引入**时间抽象**：高层策略以较低频率选「宏观意图」（子目标、选项），低层策略在一段持续时间内执行细节，直到该意图完成。

### 2. Options 框架

Options 是 HRL 的形式化基石。一个选项 $\omega$ 由三元组定义：

- **发起集** $I_\omega\subseteq\mathcal{S}$：在哪些状态下允许启动该选项；
- **选项内策略** $\pi_\omega(a\mid s)$：选项执行时的底层动作选择；
- **终止条件** $\beta_\omega(s)$：何时结束该选项（回到高层决策）。

由此得到**半马尔可夫决策过程（SMDP）**：高层在选项层面做决策，时间步长是可变的。值函数可写成选项值 $Q(s,\omega)$ 与原子动作值的组合（选项-批判拆解）。

### 3. 管理器-工人结构

Feudal 系列（ feudal hierarchy）把 HRL 落成「管理器（manager）—工人（worker）」：

- 管理器在宏观状态上输出**子目标/方向** $g_t$（如「向北移动」），频率低；
- 工人以高频率输出原子动作，其奖励被设计为「是否朝子目标前进」（内在奖励），而非只看环境最终奖励。

现代变体（如 HAC、HIRO）让子目标落在状态空间，并用**重标注（hindsight）** 技巧：即使工人没完全达到子目标，也用实际到达的状态重标一个可达目标来训练，提升样本效率。

### 4. 目标条件策略（goal-conditioned）

另一主流是把策略写成 $\pi(a\mid s, g)$，同时输入一个目标 $g$。高层负责设 $g$，低层负责达成。关键在于**通用目标表示**（常取未来状态本身），并用 HER（Hindsight Experience Replay）这类技术从失败轨迹里「假装目标是实际到达的状态」来造训练信号——这把稀疏奖励问题大幅缓解。

## 示例

用伪代码勾勒一个两层 HRL 的训练骨架（管理器设子目标、工人执行）：

```python
def hrl_step(state):
    if manager_timer == 0:
        goal = manager.choose(state)          # 低频：选子目标（如未来位置）
        manager_timer = K                      # 子目标持续 K 步
    action = worker.choose(state, goal)        # 高频：在子目标下选原子动作
    next_state, env_reward = env.step(action)
    # 内在奖励：工人是否朝子目标靠近
    intrinsic = -distance(next_state, goal)
    worker.learn(state, action, intrinsic, next_state, goal)
    manager.learn(state, goal, env_reward, next_state)  # 高层只看环境奖励
    manager_timer -= 1
    return next_state
```

直觉例子：**四足机器人穿越障碍**。原子策略只会「抬腿」，永远凑不出「先退后、再助跑、再跨」。给高层一个「到达指定落点」的子目标，低层专注短距移动，任务被自然拆解，训练快一个数量级。

## 易错点

- **层级过多反而更慢**：每加一层就多一层信用分配与协调负担；多数任务两层（管理器-工人）足够。
- **子目标不可达**：高层设了低层物理上达不到的子目标，工人永远拿不到内在奖励，训练塌缩。子目标空间要受限、可验证。
- **内在奖励与外在奖励冲突**：工人若只优化「朝子目标走」，可能走捷径违背安全约束。需用约束 RL 或把安全写进终止条件。
- **终止条件设计不当**：$\beta_\omega$ 过早或过晚结束选项，都会破坏 SMDP 的平稳假设，让高层值估计失真。

## 练习

1. 在一个需要「先取钥匙再开门」的网格世界里，手画高层/低层职责划分，体会时间抽象如何缓解稀疏奖励。
2. 推导 Options 框架下的 SMDP 贝尔曼方程，说明选项值 $Q(s,\omega)$ 与普通动作值的区别。
3. 思考：如何把 HRL 与多智能体 RL 结合（时空双重分解）？指出至少一处耦合难点。

## 小结

分层强化学习用时间抽象把长程任务切成「意图—执行」两层或多层：Options 框架给出形式化，管理器-工人与目标条件策略给出工程结构，HER/重标注缓解稀疏奖励。它让信用分配更易、探索更快、技能可复用，是机器人长程操作、游戏宏观策略与自动驾驶分层的常用工具。

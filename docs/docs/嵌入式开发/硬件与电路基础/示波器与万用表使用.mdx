# 示波器与万用表使用

嵌入式调试有一句话：**"代码是猜的，波形是真的。"** 万用表告诉你"有没有电"，示波器告诉你"电长什么样"，逻辑分析仪告诉你"数据说了什么"。不会用仪器的嵌入式工程师，只能靠改代码碰运气。

## 学习目标

- 掌握万用表五个核心档位的使用与陷阱：电压、电流、电阻、通断、二极管。
- 能独立完成示波器的基本操作链路：探头补偿 → 耦合 → 触发 → 时基 → 测量。
- 学会用触发功能抓"偶发一次"的异常（边沿、脉宽、欠幅）。
- 知道什么时候该用逻辑分析仪而不是示波器。
- 建立「用仪器验证假设」的排障方法论，而非盲改代码。

## 核心概念
### 三种仪器的分工

```text
问题类型                     首选工具
─────────────────────────────────────────────
"这里有没有 3.3V？"          万用表（快、直接）
"电源纹波多大？跌落多深？"    示波器（看模拟细节）
"I2C 到底发了什么字节？"      逻辑分析仪（解码协议）
"信号沿是不是太缓？"          示波器（带宽足够的）
"这两个焊盘通不通？"          万用表通断档
```

### 排查四件套 × 仪器对照表

这是把"电源 → 时钟 → 复位 → 引脚复用"落到实操的关键：

| 环节 | 用什么测 | 正常应该是什么 | 异常意味着 |
|------|----------|----------------|------------|
| 电源 | 万用表直流档测 VDD；示波器 AC 耦合测纹波 | 3.3V ±5%，纹波小于 50mVpp | 供电不足 / LDO 失稳 / 负载过大 |
| 时钟 | 示波器 ×10 探头测晶振输出脚 | 稳定正弦或方波，频率正确 | 晶振不起振 / 负载电容错 / 走线过长 |
| 复位 | 示波器测 NRST，单次触发抓上电过程 | 上电后拉低几十 ms 再释放到高 | 复位电路 RC 不对 / 复位常低 |
| 引脚复用 | 示波器/逻辑分析仪测目标引脚 | 有预期波形 | 没配对复用 / 时钟没开 / 引脚冲突 |

**测晶振有个坑**：普通 ×10 探头的输入电容（约 10pF）并上去会改变晶振的负载电容，可能导致"一测就停振"或频率偏移。正确做法是测缓冲输出脚（如 MCO），或使用有源探头。

## 最小可运行例程

**万用表：测量 MCU 静态电流的正确接法**

```text
错误接法（并联）→ 电流表内阻极小 = 短路，直接烧保险丝
   电源 ─┬─ 板子
         └─ [A]        ✗

正确接法（串联）→ 断开电源回路，把电流表串进去
   电源 ─── [A] ─── 板子 VDD    ✓

实操要点：
1. 先用 mA 档，确认量程后再切到 µA 档（避免过载）
2. 测低功耗时必须断开调试器（SWD 会持续供电/唤醒）
3. µA 档内阻较大，会产生额外压降，测到的值偏保守
4. 测完立刻把表笔插回电压孔，防止下次误用电流档测电压
```

**示波器：调试一路 UART 输出的完整流程**

```text
Step 1  探头补偿
   探头切到 ×10，钩住示波器自带的 1kHz 方波校准端子
   调节探头上的补偿电容，直到方波顶部平直（不过冲、不塌陷）
   ── 跳过这步，你测到的所有波形边沿都是错的

Step 2  接线
   探针 → TX 引脚，地夹 → 尽可能近的地（越近越好，长地线 = 噪声天线）

Step 3  设置
   耦合：DC（看绝对电平）；测纹波时才用 AC
   垂直：1V/div（3.3V 信号占 3 格多，合适）
   水平：115200bps → 1 bit ≈ 8.68µs，一帧 10 bit ≈ 87µs
         时基设 20µs/div，10 格 = 200µs，刚好装下一帧多

Step 4  触发（最关键）
   触发源：CH1
   类型：边沿触发，下降沿（UART 起始位是下降沿）
   电平：1.65V（VDD 的一半）
   模式：Normal（不是 Auto！Auto 在没信号时会自己扫，看着像有波形）

Step 5  读数
   用光标测量单个 bit 的宽度，反推实际波特率
   实测 8.68µs → 1/8.68µs = 115207bps  ✓ 正常
   实测 9.4µs  → 106383bps，偏差 7.6% → 时钟配置错误，必然乱码
```

**用触发功能抓偶发故障**——这是示波器最有价值的能力：

```text
场景：设备每隔几小时随机重启一次，肉眼盯不到

配置：单次触发（Single）+ 下降沿触发 + 触发电平设在 2.9V
      探头接 3.3V 电源轨
      按 Single 后离开，让它自己等

结果：几小时后回来，屏幕上定格了那一次电压跌落的完整波形
      看到 3.3V 跌到 2.6V 持续 3ms → 定位到是继电器吸合时的浪涌
      解法：给继电器线圈加续流二极管 + 电源加大电容
```

配合固件打一个"标记脉冲"，让示波器精确对齐软件事件：

```c
/* 在关键代码段前后翻转一个空闲 GPIO，示波器上就能量出执行时间 */
#define DBG_PIN_HIGH()  (GPIOB->BSRR = GPIO_PIN_5)
#define DBG_PIN_LOW()   (GPIOB->BSRR = (uint32_t)GPIO_PIN_5 << 16u)

void HAL_ADC_ConvCpltCallback(ADC_HandleTypeDef *hadc)
{
    DBG_PIN_HIGH();          /* 上升沿 = 进入处理 */

    process_samples();       /* 待测的处理逻辑 */

    DBG_PIN_LOW();           /* 下降沿 = 处理结束 */
    /* 示波器测高电平宽度 = 该函数真实耗时，比 printf 计时精确得多，
       且几乎零开销（一条寄存器写指令）                              */
}

/* 进阶：用不同宽度的脉冲编码不同事件，一个引脚看清整个流程 */
static inline void dbg_mark(uint8_t n)
{
    for (uint8_t i = 0; i < n; i++) {
        DBG_PIN_HIGH(); __NOP(); __NOP();
        DBG_PIN_LOW();  __NOP(); __NOP();
    }
}
```

## 易错点

- **万用表电流档测电压**：电流档内阻近似为零，直接短路电源，轻则烧保险丝重则炸表。这是新手最常见的事故。
- **示波器用 Auto 触发看偶发信号**：没有触发上时 Auto 仍会自由扫描，屏幕上的"波形"是无意义的噪声拼图。抓事件一律用 Normal 或 Single。
- **探头没做补偿**：过冲/塌陷会让你误判信号质量，甚至以为是电路设计问题。
- **地线夹太长**：几十厘米的鳄鱼夹形成大环路，测高速信号时会看到根本不存在的振铃。测高频要用探头自带的地弹簧。
- **探头忘了切 ×10**：×1 档带宽只有几 MHz 且负载重，测方波会看成三角波。同时示波器上也要设成 ×10，否则读数差 10 倍。
- **带宽不够却下结论**：100MHz 示波器测 8ns 上升沿（等效带宽约 44MHz）勉强够，测 1ns 沿则完全失真。
- **直接测市电或高压**：普通探头额定值有限，必须用高压差分探头，且注意示波器地是接大地的——探头地夹碰到火线会直接短路。
- **用示波器硬看 I2C**：两通道能看到波形但读不出字节，这时该换逻辑分析仪（几十元的 8 通道款配 sigrok/PulseView 就够用）。
- **测低功耗时忘了拔调试器**：SWD 供电和调试逻辑会让电流虚高几十倍。

## 练习

1. 完成一次完整的探头补偿，拍下补偿不足、过补偿、正确三种方波形态并解释差异。
2. 用示波器测出你的板子实际 UART 波特率误差，若超过 2% 反查时钟树配置。
3. 用单次触发抓一次上电过程，同屏记录 VDD 建立与 NRST 释放的时间关系，判断复位时序是否合理。
4. 用 GPIO 标记法测量一个中断服务函数的真实执行时间，并与你的估算对比。
5. 用逻辑分析仪抓一段 I2C 通信，解码出从机地址与数据，验证与代码中的一致。

## 小结

仪器的价值在于**把猜测变成事实**。养成三个习惯：动手改代码前先测一眼电源和时钟；抓偶发问题一律用 Single 触发 + 长时间等待；用 GPIO 标记法把软件事件映射到时间轴上。当你能用波形回答"到底发生了什么"，调试效率会有数量级的提升。

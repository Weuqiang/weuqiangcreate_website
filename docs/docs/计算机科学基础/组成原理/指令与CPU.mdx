# 指令与 CPU

CPU 是计算机的"大脑"。本篇讲它如何取指令、执行指令，以及影响性能的关键设计。

## 学习目标

学完本章，你应该能够：

- 描述取指-译码-执行-写回的指令周期。
- 说清 ISA（指令集架构）约定了什么、与微架构的区别。
- 解释流水线如何提升吞吐，以及冒险（hazard）为何会打断它。
- 理解缓存的局部性原理与多核带来的一致性问题。

- 已了解 [数字逻辑与冯诺依曼](/docs/计算机科学基础/组成原理/数字逻辑与冯诺依曼) 中的二进制与存储程序思想。
- 知道高级语言最终要变成机器能执行的指令。
- 可参考 [C 语言基础](/docs/编程语言/C/0基础语法) 理解「代码如何落到硬件」。

## 核心概念

CPU 本质上是「不停地从内存取一条指令、解释它、执行它」的机器。指令集架构（ISA）是软硬件之间的契约：它规定有哪些指令、寄存器长什么样、怎么和内存交互；至于内部怎么实现，是微架构的事。为了让每秒执行的指令更多，工程师发明了流水线（像工厂传送带一样让多条指令重叠执行）和缓存（把最近用过的数据放在离核心更近、更快的地方）。多核则是把多个这样的核心放一起，但共享内存带来了缓存一致性难题。

本章主线：
- 从指令周期看清一条指令的一生
- 用流水线和缓存理解「为什么快」
- 用多核与一致性理解「为什么难」

经典五级流水线把一条指令的生命周期拆成五段，让多条指令像工厂传送带一样重叠执行以提升吞吐：

```mermaid
flowchart LR
    IF[取指 Fetch] --> ID[译码 Decode]
    ID --> EX[执行 Execute]
    EX --> MEM[访存 Memory]
    MEM --> WB[写回 Write-back]
    WB --> IF
```

## 1. 指令周期

CPU 不断重复"取指—译码—执行"循环：

```text
取指(Fetch) → 译码(Decode) → 执行(Execute) → 写回(Write-back) → 取下一条
```

- **程序计数器（PC）**指向下一条要执行的指令地址；
- 指令从内存取到**指令寄存器**，译码后由控制单元驱动执行。

## 2. 指令集架构（ISA）

- **CISC**（x86）：指令多而复杂，单条做多件事。
- **RISC**（ARM、RISC-V）：指令精简、统一长度，靠编译器优化，功耗低、移动端主流。

一条简单指令示例（伪汇编）：

```asm
LOAD  R1, [addr]    ; 从内存 addr 载入 R1
ADD   R1, R1, #1    ; R1 = R1 + 1
STORE R1, [addr]    ; 写回内存
```

## 3. 提升吞吐：流水线

把指令周期分段，多条指令的不同阶段**重叠执行**（像工厂流水线）：

```text
指令1: 取指 | 译码 | 执行 | 写回
指令2:     取指 | 译码 | 执行 | 写回
```

- 理想情况每周期完成一条指令；
- **冒险**（数据/控制/结构冲突）会降低效率，需要旁路、预测等补救。

## 4. 缓存（Cache）

CPU 远快于内存，缓存用"局部性原理"弥合速度差：

```text
CPU → L1(最快,小) → L2 → L3 → 内存(慢)
```

- **时间局部性**：刚访问的数据很快再访问；
- **空间局部性**：相邻数据常被一起访问。

## 5. 多核与并行

现代 CPU 多核，每核独立执行线程；超线程（SMT）让一个核逻辑上跑两个线程，提高利用率。

## 示例

**平均 CPI 计算**：假设某程序三类指令占比与各自 CPI 如下，平均 CPI 即加权平均：

```text
指令类型   占比      CPI
算术      50%       1
访存      30%       4
分支      20%       3
平均 CPI = 0.5×1 + 0.3×4 + 0.2×3 = 2.3
程序执行时间 ≈ 指令总数 × 平均CPI × 时钟周期
```

**流水线吞吐**：把"取指/译码/执行/写回"四段重叠，理想下每周期产出一条：

```text
周期:  1    2    3    4    5
指令1: IF  ID  EX  WB
指令2:     IF  ID  EX  WB
指令3:         IF  ID  EX  WB
```

若第 2 条指令依赖第 1 条的结果（数据冒险），EX 段需停顿一拍等待旁路结果，吞吐下降——这正是冒险的代价。

## 小结

CPU 的快慢不只看主频，更看：流水线深度、缓存命中率、分支预测准确率、核数。写高性能代码时，这些才是真正的"瓶颈所在"。

## 易错点

- **主频高 ≠ 快**：流水线深度、缓存命中率、分支预测、核数共同决定吞吐；单纯堆主频收益递减。
- **RISC vs CISC 是设计哲学，不是"谁先进"**：ARM/RISC-V 靠编译器优化取胜，x86 靠微码兼容旧生态。
- **流水线冒险不可避免**：数据相关、控制相关（分支）会打断理想重叠，需要旁路/预测补救。

## 练习

2. 为什么循环体小、分支可预测的代码更快？结合分支预测解释。

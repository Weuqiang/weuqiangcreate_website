# 网络分层与 TCP/IP

计算机网络的核心是"分层"：每层只管自己的事，数据层层封装、对面层层拆开。本篇讲 TCP/IP 与可靠传输。

## 1. 分层模型

```
应用层    HTTP / DNS / FTP
传输层    TCP / UDP
网络层    IP
链路层    以太网 / WiFi
物理层    电缆 / 光纤 / 电磁波
```

- 发送：上层数据交给下层，加**头部**封装；
- 接收：下层逐层拆头，向上递交。

## 2. IP：寻址与路由

- IP 地址标识一台主机（IPv4 32 位，IPv6 128 位）；
- 路由器根据目标 IP 查表转发，跨网络把包送到目的地；
- IP 是"尽力交付"，**不保证**到达、不保证顺序。

## 3. TCP：可靠传输

TCP 在不可靠的 IP 之上提供可靠字节流：

- **三次握手**建立连接：
  ```
  客户端 → SYN → 服务端
  客户端 ← SYN+ACK ← 服务端
  客户端 → ACK → 服务端
  ```
- **确认与重传**：收到确认才算送达，超时重发；
- **序号与窗口**：保证有序、流量控制（滑动窗口）；
- **四次挥手**断开连接。

## 4. UDP：快但不保证

- 无连接、无重传，适合实时音视频、游戏（丢包比延迟更可接受）；
- DNS 查询、视频通话常用 UDP。

| 对比 | TCP | UDP |
|------|-----|-----|
| 连接 | 有 | 无 |
| 可靠 | 是 | 否 |
| 速度 | 较慢 | 快 |
| 场景 | 网页/文件 | 实时/广播 |

## 5. 端口

IP 找到主机，**端口（0–65535）**找到主机上的进程（如 80=HTTP，443=HTTPS，22=SSH）。

## 小结

网络分层让复杂通信可分解：IP 管"送到哪"，TCP 管"可靠送到"，应用层管"干什么"。下一站：[HTTP 与网络安全](../HTTP与网络安全)。

## 易错点

- **IP 不可靠 ≠ TCP 不可靠**：IP 层"尽力交付"不保证到达；TCP 在其上用确认/重传补齐可靠性。
- **三次握手防的是"旧连接"**：为同步初始序号、避免历史脏包，并非为防攻击。
- **端口是进程的门牌，不是主机的**：同一主机不同服务用不同端口区分（如 80/443/22）。

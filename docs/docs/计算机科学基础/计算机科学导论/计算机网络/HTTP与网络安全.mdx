# HTTP 与网络安全

Web 建立在 HTTP 之上，而安全靠 HTTPS、加密与认证兜底。本篇串起日常开发最常见的一环。

## 1. HTTP 基础

HTTP 是**请求—响应**协议，无状态（每次请求独立）：

```
客户端 ──请求(方法, URL, 头, 体)──→ 服务端
客户端 ←──响应(状态码, 头, 体)────── 服务端
```

常用方法：`GET`（取）、`POST`（提交）、`PUT`/`PATCH`（改）、`DELETE`（删）。

常见状态码：

| 码 | 含义 |
|----|------|
| 200 | 成功 |
| 301/302 | 重定向 |
| 400 | 请求错误 |
| 401/403 | 未认证/无权限 |
| 404 | 找不到 |
| 500 | 服务端错误 |

## 2. HTTPS：加密的 HTTP

HTTP 明文传输，HTTPS 在 HTTP 与 TCP 间加 **TLS** 层：

- **加密**：对称密钥加密内容，密钥用非对称加密协商；
- **认证**：证书（CA 签发）证明"你连的真是目标站点"；
- **完整性**：防篡改。

## 3. 常见安全威胁

| 威胁 | 说明 | 防御 |
|------|------|------|
| 中间人 | 窃听/篡改通信 | HTTPS + 证书校验 |
| XSS | 注入恶意脚本 | 转义输出、CSP |
| CSRF | 借用户身份发请求 | 令牌、同源检查 |
| SQL 注入 | 拼接恶意 SQL | 参数化查询 |
| 密码泄露 | 明文存储 | 加盐哈希 |

## 4. 身份认证

- **Session/Cookie**：服务端存状态，客户端带 cookie；
- **JWT**：无状态令牌，签名的 JSON，自带有效期；
- **OAuth2**：授权第三方访问，不暴露密码。

## 5. 同源策略

浏览器限制脚本只能访问**同源**（协议+域名+端口相同）资源，是 Web 安全的基石；跨域用 CORS 显式放开。

## 小结

HTTP 管"传什么"，HTTPS 管"安全传"，认证与防护管"只让对的人做对的事"。懂这一层，Web 安全漏洞大半可防。

## 易错点

- **HTTPS 不是"新协议"**：它只是在 HTTP 与 TCP 间插入 TLS，应用层语义完全不变。
- **JWT 无状态 ≠ 安全**：签名防篡改，但泄露的令牌在有效期内仍可用，需配合短有效期与吊销。
- **同源策略是浏览器限制，不是服务器**：CORS 是服务器"授权"跨域，而非"阻止"跨域。

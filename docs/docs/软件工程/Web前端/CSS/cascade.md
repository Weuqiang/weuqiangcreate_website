# 层叠、继承与优先级

这是整个 CSS 里**最该搞懂、也最常被跳过**的一章。"我明明写了样式却不生效"这个困扰几乎每个初学者的问题，答案 90% 在这里。

CSS 的名字里就写着答案：Cascading（层叠）。同一个元素的同一个属性，往往有好几条声明同时命中，浏览器需要一套确定性的算法从中选出唯一的赢家。这套算法就是层叠。

## 学习目标

学完本章，你应该能够：

- 复述层叠算法的判定顺序，并用它解释任意一次"样式没生效"
- 手算一个选择器的优先级（specificity）
- 说清哪些属性会继承、哪些不会，以及为什么这样设计
- 知道 `!important` 的代价，以及什么时候使用它是正当的
- 用 `inherit` / `initial` / `unset` / `revert` 精确控制取值来源

## 前置知识

- [CSS 简介](/docs/软件工程/Web前端/CSS/intro) — 三种引入方式与规则语法。
- [选择器](/docs/软件工程/Web前端/CSS/selector) — 优先级是按选择器的构成来算的。

## 核心概念

想象每个元素的每个属性都要开一场"竞标会"：所有能命中它的声明都是投标者，浏览器按一套固定规则评标，选出唯一中标者。如果一个投标者都没有，就走"继承"或"初始值"这两条兜底路径。

本章主线：
- 层叠算法：四轮筛选决出赢家
- 优先级：怎么把选择器算成一个可比较的数
- 继承：为什么没写的属性也有值
- 显式控制取值：四个关键字

## 层叠算法：四轮筛选

浏览器按以下顺序逐轮比较，**某一轮分出胜负就停止，不再看后面的**：

```text
① 来源与重要性
   浏览器默认样式 < 用户样式 < 作者样式（你写的）
   加了 !important 的，顺序整个反过来
② 优先级（specificity）
   按选择器构成计算，高者胜
③ 书写顺序
   完全同分时，后写的覆盖先写的
```

第 ① 轮的完整优先级链条（从低到高）是：

```text
浏览器默认样式
浏览器默认样式 + !important （最低，被设计成可被覆盖）
用户样式（浏览器设置里用户自定义的）
作者样式（开发者写的）
作者样式 + !important
用户样式 + !important
浏览器默认样式 + !important
```

看起来绕，但设计意图很清晰：**带 `!important` 的用户样式高于一切作者样式**——这是为了保障可访问性，让视力障碍用户强制放大字号的设置不会被网站的样式覆盖掉。

## 优先级怎么算

优先级是一个三元组 `(A, B, C)`，从左到右逐位比较，**高位大者直接胜出，不进位**：

| 位 | 计什么 | 例子 |
|---|---|---|
| A | ID 选择器的个数 | `#header` |
| B | 类、属性选择器、伪类的个数 | `.btn`、`[type="text"]`、`:hover` |
| C | 标签选择器、伪元素的个数 | `div`、`::before` |

不参与计数的：通配符 `*`、组合器（空格、`>`、`+`、`~`）、`:where()` 里的一切。

举几个例子：

```css
/* (0,0,1) */
p { color: red; }

/* (0,1,0) —— 胜过上面 */
.note { color: blue; }

/* (0,1,1) */
p.note { color: green; }

/* (1,0,0) —— 胜过以上全部 */
#main { color: black; }

/* (0,0,5) —— 五个标签，依然输给任何一个类 */
body div ul li a { color: orange; }
```

最后一例是关键：**优先级不进位**。哪怕堆一百个标签选择器（0,0,100），也比不过一个类（0,1,0）。这和十进制数的比较规则完全不同，很多人在这里翻车。

行内样式（`style` 属性）可以理解为 `(1,0,0,0)`，比任何选择器都高。这就是为什么行内样式难以覆盖，也是应该避免它的主要原因。

`:is()` 和 `:not()` 的优先级取**括号里优先级最高的那一个参数**；`:where()` 则永远是 `(0,0,0)`。这个差异让 `:where()` 成为写"可被轻松覆盖的默认样式"的利器：

```css
/* 优先级为 0，任何一条用户规则都能覆盖它 */
:where(h1, h2, h3) {
  margin-block: 0.5em;
}
```

## 继承

有些属性会自动传给后代元素，有些不会。这不是随意规定的，而是按"传下去是否合理"来划分：

**会继承的**——多与文字排版相关：`color`、`font-family`、`font-size`、`font-weight`、`line-height`、`text-align`、`letter-spacing`、`visibility`、`cursor`、`list-style`。

**不会继承的**——多与盒子的尺寸和位置相关：`width`、`height`、`margin`、`padding`、`border`、`background`、`display`、`position`、`float`、`overflow`。

道理很直白：给 `body` 设一个字体颜色，希望整页文字都变色，这很合理；但给 `body` 设 `width: 300px`，你显然不希望里面每个 `div` 都变成 300 像素。

正因如此，实践中会把全局排版设在根元素上，让它自然流下去：

```css
body {
  font-family: system-ui, sans-serif;
  line-height: 1.75;
  color: #333;
}
```

要注意**继承的优先级低于任何直接命中的声明**。哪怕父元素的规则优先级再高，只要子元素被任何一条规则直接命中，继承值就出局了：

```css
#wrapper { color: red; }  /* 优先级 (1,0,0)，但只是继承给 p */
p { color: blue; }        /* 优先级 (0,0,1)，直接命中 p */
```

结果 `p` 是**蓝色**。因为继承不参与优先级比较——它是"没有任何声明命中时"的兜底，而这里 `p { color: blue }` 直接命中了。

## 四个显式取值关键字

```css
.child {
  color: inherit;  /* 强制继承父元素的值，即使这个属性默认不继承 */
  margin: initial; /* 恢复到 CSS 规范定义的初始值（margin 是 0） */
  border: unset;   /* 可继承属性 → inherit；不可继承属性 → initial */
  padding: revert; /* 恢复到浏览器默认样式的值（而非规范初始值） */
}
```

最常用的是 `inherit`。典型场景是让按钮和输入框继承页面字体——表单控件的字体默认来自操作系统而非页面，不显式继承就会显得格格不入：

```css
button,
input,
select,
textarea {
  font: inherit;
  color: inherit;
}
```

`revert` 与 `initial` 的区别值得留意：`display: initial` 会得到 `inline`（规范初始值），而 `display: revert` 对 `div` 会得到 `block`（浏览器默认值）。想"恢复原样"时通常该用 `revert`。

## `!important` 的代价

```css
.title { color: red !important; }
```

`!important` 把声明提升到一个更高的层级，绕过正常的优先级比较。它能立刻解决问题，代价是**把问题推给未来的自己**：

- 想覆盖一条 `!important`，只能用另一条优先级更高的 `!important`，很快就会演变成 `!important` 军备竞赛。
- 它破坏了"优先级可预测"这一前提，让样式表变得无法推理。
- 排查问题时，你得先在满屏 `!important` 里找出哪条最终生效。

**正当用途只有两类**：

1. 覆盖无法修改的第三方库或行内样式（比如某个组件库把样式写死在 `style` 属性里）。
2. 工具类（utility class）——语义上就是"我就是要强制生效"，比如 `.hidden { display: none !important; }`。

除此之外，遇到需要 `!important` 的场景，先反思是不是选择器写得太深、或者该重构命名了。相关实践见 [CSS 工程化](/docs/软件工程/Web前端/CSS/engineering)。

## 排查"样式不生效"的标准流程

按顺序检查，能覆盖绝大多数情况：

```text
1. 选择器选中了吗？
   → 开发者工具里看这条规则有没有出现在 Styles 面板
2. 声明被覆盖了吗？
   → 看它有没有被划删除线，划了就找覆盖它的那条
3. 声明本身合法吗？
   → 无效声明会被标黄警告；检查属性名拼写与值的单位
4. 是不是继承来的？
   → Computed 面板能看到值的来源，继承值会标注来自哪个祖先
5. 属性对这个元素有效吗？
   → 比如给行内元素设 width、给非 flex 子项设 flex-grow，都是无效的
```

第 5 条常被忽略：CSS 不会告诉你"这个属性在这个上下文里没意义"，它只是静默无效。相关规则见[显示类型与常规流](/docs/软件工程/Web前端/CSS/display-flow)。

## 易错点

- **以为优先级会进位**。十个标签选择器也打不过一个类。这是最经典的误解。
- **误以为父元素优先级高就能压过子元素**。继承值永远输给直接命中的声明，与父元素的选择器多复杂无关。
- **把 `!important` 当调试工具**。加上去问题"解决"了，三个月后整个样式表无法维护。
- **忘了行内样式的存在**。JavaScript 动态设置的 `element.style.xxx` 就是行内样式，优先级极高，纯 CSS 很难覆盖。
- **LVHA 顺序写反**。`:hover` 写在 `:visited` 前面，会导致访问过的链接悬停时不变色，因为二者优先级相同、后写的赢。
- **混淆 `initial` 与 `revert`**。想"恢复默认外观"时用 `initial` 常得到意外结果（比如 `div` 变成 `inline`）。

## 练习

动手检验一下自己：

1. 手算这些选择器的优先级：`ul li a`、`.nav a:hover`、`#sidebar .item`、`:where(.card) h2`。
2. 构造一个例子：父元素用 ID 选择器设了颜色，子元素用标签选择器设了另一个颜色，验证哪个生效并解释原因。
3. 给一个第三方组件库的按钮改背景色，在**不使用 `!important`** 的前提下做到——提示：提高选择器优先级或利用书写顺序。
4. 写一段样式让所有表单控件继承页面的字体与颜色，对比修改前后的视觉差异。
5. 在开发者工具里找一条被划了删除线的声明，说出是哪条规则覆盖了它、凭什么覆盖。

## 小结

层叠算法按"来源与重要性 → 优先级 → 书写顺序"三轮决出赢家，某轮分出胜负即停止。优先级是不进位的三元组 `(ID, 类/属性/伪类, 标签/伪元素)`。继承是"无人命中时"的兜底，永远输给直接命中的声明。`!important` 能强行改变层叠结果，但会破坏可推理性，只应用于覆盖第三方样式和工具类。

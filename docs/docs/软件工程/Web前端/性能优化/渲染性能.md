# 渲染性能

## 学习目标

学完本章，你应该能够：

- 区分重排（reflow）、重绘（repaint）与合成（composite）
- 说出哪些 CSS 属性触发重排、哪些只合成
- 用 `requestAnimationFrame` 把动画对齐到帧
- 识别并拆分「长任务」以保交互流畅

## 前置知识

在阅读下面的内容前，建议先掌握：

- [DOM 与元素](/docs/软件工程/Web前端/JavaScript/dom/element)
- [加载性能](/docs/软件工程/Web前端/性能优化/加载性能)

## 核心概念

加载性能管「多久出现」，渲染性能管「出现后流不流畅」。卡顿几乎都源于**主线程被布局/绘制或脚本长时间占用**，导致掉帧。

本章主线：

- 重排 / 重绘 / 合成三阶段
- 触发重排的属性与规避
- rAF 与动画
- 长任务与 responsiveness

## 浏览器渲染流水线

1. **JavaScript**：改 DOM/样式
2. **Style**：算哪些元素受影响
3. **Layout（重排）**：算几何位置与大小
4. **Paint（重绘）**：填像素
5. **Composite（合成）**：把层合并上屏

成本阶梯：**合成 < 重绘 < 重排**。重排最贵——改了布局，后面全要重算。

## 重排的触发与规避

以下操作会触发重排（layout）：

- 改几何属性：`width`/`height`/`top`/`left`/`margin`/`font-size`
- 增删 DOM 节点、改文字内容导致换行
- 读取会强制同步布局的属性（`offsetTop`/`getBoundingClientRect`）后再写

规避：

```javascript
// 坏：读写交替，每次读都强制重排
for (const el of items) {
  el.style.width = el.offsetWidth + 10 + 'px'; // 读→写→读→写
}
// 好：先批量读、再批量写，或只用 transform
```

- 用 `transform`/`opacity` 做动画——它们**只走合成**，不触发重排/重绘，最流畅。
- 批量 DOM 改动（如先 `display:none` 改完再显示，或用文档片段）。

## requestAnimationFrame 与动画

```javascript
function tick() {
  box.style.transform = `translateX(${x}px)`;
  x += 2;
  if (x < 300) requestAnimationFrame(tick);
}
requestAnimationFrame(tick);
```

`rAF` 把回调排到**下一帧绘制前**执行，动画与显示器刷新率对齐（通常 60fps），避免 `setInterval` 造成丢帧或不必要的计算。动画优先用 CSS `transform`/`opacity` + `rAF`，而非改 `left`/`top`。

## 长任务与响应性

主线程一次连续运行超过 **50ms** 即「长任务」——期间用户点击/滚动无法响应，感觉卡。典型来源：超大循环、复杂初始化、同步解析大 JSON。

拆分长任务：

```javascript
async function processChunks(list) {
  for (let i = 0; i < list.length; i += 100) {
    doChunk(list.slice(i, i + 100));
    await new Promise(r => setTimeout(r)); // 让出主线程
  }
}
```

用 `setTimeout(0)`/`await` 让出主线程，让浏览器处理输入与绘制，保持跟手。

## 易错点

1. **动画用 `left/top` 而非 `transform`**：触发重排，移动端明显掉帧。
2. **读写布局属性交替**：`offset*` 强制同步重排，循环里尤其致命。
3. **首屏跑巨量同步 JS**：阻塞可交互时间；拆分或延迟非关键初始化。
4. **误以为 `will-change` 万能**：滥用 `will-change: transform` 会常驻合成层、吃内存，应按需且及时移除。

## 小结

渲染性能的敌人是主线程阻塞与昂贵重排。用 `transform`/`opacity` 走合成、批量读写避免强制布局、用 `rAF` 对齐帧、拆分长任务保响应。理解「重排 > 重绘 > 合成」的成本阶梯，就能对症下药。

## 练习

1. 用 DevTools Performance 录一段滚动，找出触发重排的脚本并改为 `transform`。
2. 把一个 `setInterval` 动画改成 `requestAnimationFrame`，对比帧率。
3. 故意写一个 100ms 长任务，用 Performance 面板定位，再拆分成多段。

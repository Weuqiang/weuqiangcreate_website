# 数组与链表

数组和链表是几乎所有数据结构与算法的「原材料」。理解它们的本质差异（**内存怎么放、访问怎么走**），是看懂后面一切结构的前提。

## 学习目标

- 说出数组与链表在内存布局上的根本区别。
- 根据场景判断「该用数组还是链表」。
- 能手写一个单链表的基本增删查。

## 前置知识

- [复杂度分析](../)（建议先读首页的大 O 速查表）
- 一门语言基础，本文示例用 [Python 入门](../../../编程语言/Python/0基础语法)

## 核心概念

### 1. 数组（Array）

数组在内存中占**一块连续的空间**，元素按顺序紧挨着摆放。因为地址连续，只要知道首地址和元素大小，就能用 `首地址 + 下标 × 元素大小` 一步算出第 i 个元素的地址——这就是**随机访问** $O(1)$ 的来源。

代价：插入/删除中间元素时，要把后面的元素整体平移，最坏 $O(n)$；且长度固定（动态数组扩容有摊还成本）。

### 2. 链表（Linked List）

链表的元素（节点）**散落在内存各处**，每个节点除了存数据，还存一个指向下一个节点的指针。元素靠指针串成一条链，内存不连续。

代价：想访问第 i 个节点，必须从头一个个往后走，访问 $O(n)$；但插入/删除只需改几个指针， $O(1)$（前提是已拿到目标位置的前驱）。

### 3. 一句话对比

| 操作 | 数组 | 链表 |
|---|---|---|
| 按下标访问 | $O(1)$ | $O(n)$ |
| 头部插入/删除 | $O(n)$ | $O(1)$ |
| 尾部插入（已知尾指针） | 均摊 $O(1)$ | $O(1)$ |
| 内存 | 连续，可能浪费 | 分散，有指针额外开销 |

## 最小可运行示例

数组（Python 的 `list` 就是动态数组）：

```python
a = [10, 20, 30]
print(a[1])          # 随机访问 O(1) -> 20
a.insert(1, 15)      # 在下标1插入，后面整体后移 O(n)
print(a)             # [10, 15, 20, 30]
a.pop(2)             # 删除下标2 O(n)
print(a)             # [10, 15, 30]
```

单链表的最小实现：

```python
class Node:
    def __init__(self, val, nxt=None):
        self.val = val
        self.next = nxt

# 头插法建链：1 -> 2 -> 3
head = None
for v in [3, 2, 1]:
    head = Node(v, head)

# 遍历
cur = head
while cur:
    print(cur.val, end=" ")   # 1 2 3
    cur = cur.next

# 删除「值为 target 的第一个节点」
def remove(head, target):
    dummy = Node(0, head)     # 哨兵节点，简化头删
    prev, cur = dummy, head
    while cur:
        if cur.val == target:
            prev.next = cur.next
            break
        prev, cur = cur, cur.next
    return dummy.next
```

## 易错点

1. **数组越界**：访问 `a[len(a)]` 会抛 `IndexError`。循环条件常用 `range(len(a))` 避免手抖。
2. **链表丢失头指针**：增删时若直接改 `head` 又没保存，链就断了。用 `dummy` 哨兵节点能大幅降低出错率。
3. **忘记更新 `next`**：删除节点时只改了前驱的 `next` 还不够，要确保没有其它引用形成环。
4. **混淆「拿到位置」与「查找位置」**：链表的删除本身是 $O(1)$，但「找到要删的节点」往往是 $O(n)$——总复杂度仍是 $O(n)$。

## 小结

数组赢在「访问」，链表赢在「增删」。面试与日常里，**先用数组（简单、缓存友好），遇到频繁头部增删或大小难预估再考虑链表**。下一篇 [栈与队列](../栈与队列) 就是这两种结构的典型应用。

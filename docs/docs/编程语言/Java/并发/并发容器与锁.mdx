# 并发容器与锁

多线程共享数据时，必须用锁或并发容器保证一致性。本篇覆盖 `synchronized`、显式锁与 `java.util.concurrent`（JUC）工具。

## 学习目标

- 区分内置锁 `synchronized` 与显式锁 `ReentrantLock` 的取舍；
- 用原子类（CAS）做无锁计数；
- 选对并发容器与线程协作工具（Latch/Semaphore/Future）。

## 前置知识

- 已读完 [线程与线程池](../线程与线程池)；
- 集合选型基础见 [集合框架](../../生态/集合框架)。

## 核心概念

共享状态需要同步：`synchronized` 基于监视器锁，保证互斥与可见性；`ReentrantLock` 更灵活（可中断、超时、公平锁），`ReadWriteLock` 在读多写少时提升并发。并发容器（如 `ConcurrentHashMap`）内部用分段/无锁结构，比“普通集合 + 外部锁”吞吐更高、语义更清晰。

本章主线：
- synchronized：锁对象与可见性
- ReentrantLock 与条件变量
- ReadWriteLock：读写分离
- 并发容器：ConcurrentHashMap 等

## 1. 内置锁 synchronized

```java
class Counter {
    private int n = 0;
    public synchronized void inc() { n++; }   // 同一时刻只有一个线程进入
}
```

- 锁对象是 `this`（实例方法）或 `Class`（静态方法）。
- 简单但不够灵活（不可中断、非公平、锁粒度粗）。

## 2. 显式锁 ReentrantLock

```java
ReentrantLock lock = new ReentrantLock();
lock.lock();
try {
    // 临界区
} finally {
    lock.unlock();   // 务必在 finally 释放
}
```

优势：`tryLock()` 可超时/可中断、`new ReentrantLock(true)` 公平锁。

## 3. 原子类（无锁）

```java
AtomicInteger cnt = new AtomicInteger(0);
cnt.incrementAndGet();          // CAS 实现，高效
```

`AtomicInteger`/`AtomicReference` 基于 CAS（比较并交换），适合简单计数，避免锁开销。

## 4. 并发容器（JUC）

`HashMap` 非线程安全，高并发请用：

| 容器 | 说明 |
|------|------|
| `ConcurrentHashMap` | 桶级锁 / CAS，高并发读写 |
| `CopyOnWriteArrayList` | 读多写少，写时复制 |
| `BlockingQueue` | 生产者-消费者（`ArrayBlockingQueue` 等） |
| `ConcurrentLinkedQueue` | 无锁队列 |

```java
Map<String, Integer> map = new ConcurrentHashMap<>();
map.computeIfAbsent("k", k -> 0);   // 原子更新，无需额外锁
```

## 5. 线程协作

```java
CountDownLatch latch = new CountDownLatch(3);  // 等待 3 个任务完成
ExecutorService pool = Executors.newFixedThreadPool(3);
for (int i = 0; i < 3; i++) pool.submit(() -> { doWork(); latch.countDown(); });
latch.await();   // 阻塞直到计数归零
```

其他常用：`CyclicBarrier`（循环等待）、`Semaphore`（限流）、`Future`/`CompletableFuture`（异步结果）。

## 小结

优先用并发容器而非“集合+synchronized”；需要灵活控制时用 ReentrantLock。读多写少场景用读写锁，能显著放大并发度。

## 易错点

- `ReentrantLock` 忘记在 `finally` 里 `unlock()`，异常时会死锁。
- `synchronized` 锁的是对象而非代码块；用不同对象当锁会失效。
- `ConcurrentHashMap` 的 `compute` 内不要做耗时/递归操作，会长时间占桶。
- `volatile` 只保证可见性不保证原子性，`i++` 仍需 `AtomicInteger` 或锁。

## 练习

1. 用 `ReentrantLock` 实现一个线程安全的 `BankAccount` 存取款；
2. 用 `Semaphore(3)` 限制同时只有 3 个线程访问某资源。

## 示例

用 `ReentrantLock` 保护共享计数器，并用 `ConcurrentHashMap` 做线程安全的键值存储：

```java
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.locks.ReentrantLock;

public class LockDemo {
    private final ReentrantLock lock = new ReentrantLock();
    private int counter = 0;

    public void safeInc() {
        lock.lock();
        try {
            counter++;
        } finally {
            lock.unlock(); // 必须在 finally 中释放，防止异常导致死锁
        }
    }

    public static void main(String[] args) {
        ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>();
        map.put("a", 1);
        System.out.println(map.get("a")); // 1
    }
}
```

`synchronized` 写法更简洁但锁粒度粗；`ReentrantLock` 支持公平锁、超时与可中断；高并发读写优先用 JUC 并发容器。

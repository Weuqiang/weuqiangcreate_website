# 大 O 分析

「这段代码快不快」是个没法回答的问题——它取决于机器、语言、编译器、当天的负载。但「**数据量翻倍时它会慢多少**」是可以精确回答的，而且答案与机器无关。大 O 记号就是回答这个问题的语言。

## 学习目标

- 写出大 O 的数学定义，并说清它描述的是**增长趋势**而非绝对耗时。
- 用五条化简规则，把任意表达式化简为标准大 O 形式。
- 分析循环嵌套、递归、分治三类代码的复杂度。
- 会用主定理（Master Theorem）秒算常见分治递归式。
- 知道大 O 在什么情况下会**误导**你。

## 核心直觉

### 严格定义

$$
f(n) = O(g(n)) \iff \exists\, c > 0,\ n_0 > 0,\ \text{使得}\ \forall n \ge n_0,\ 0 \le f(n) \le c \cdot g(n)
$$

翻译成人话：**当 $n$ 足够大时，$f(n)$ 的增长不会超过 $g(n)$ 的某个常数倍。**

两个关键词：

- **足够大时（$n \ge n_0$）**：小规模输入不算数。$1000n$ 在 $n=1$ 时比 $n^2$ 大得多，但我们不关心。
- **常数倍（$c$）**：所以 $3n^2$、$100n^2$、$0.5n^2$ 都是 $O(n^2)$。

大 O 是**上界**。与之配套的还有：

| 记号 | 含义 | 类比 |
|---|---|---|
| $O(g)$ | 上界，「不超过」 | $\le$ |
| $\Omega(g)$ | 下界，「不低于」 | $\ge$ |
| $\Theta(g)$ | 紧确界，上下界都是 | $=$ |
| $o(g)$ | 严格上界（增长严格慢于） | $<$ |

严格地说，「快排平均是 $O(n\log n)$」应该写成 $\Theta(n\log n)$ 更准确，但工程语境下大家默认用 $O$ 表示紧确界。写 $O(n^2)$ 描述一个 $O(n)$ 的算法在数学上没错（上界成立），但会被认为是不精确的表述。

### 五条化简规则

1. **去常数系数**：$3n^2 \to O(n^2)$，$\frac{n}{2} \to O(n)$。
2. **只留最高阶**：$n^2 + 100n + 5000 \to O(n^2)$。
3. **嵌套相乘，顺序相加**：两层独立循环嵌套是 $O(n \cdot m)$；两段顺序执行的代码是 $O(f + g) = O(\max(f, g))$。
4. **对数换底只差常数**：$\log_2 n = \log_{10} n / \log_{10} 2$，所以 $O(\log n)$ 不写底数。
5. **多变量不能合并**：图算法的 $O(V + E)$ **不能**简化成 $O(V)$ 或 $O(E)$，因为 $V$ 和 $E$ 的相对大小取决于图的稠密程度。

### 常见量级的直观感受

假设机器每秒执行 $10^8$ 次基本操作：

| 复杂度 | $n = 10$ | $n = 1000$ | $n = 10^6$ | 典型算法 |
|---|---|---|---|---|
| $O(1)$ | 瞬间 | 瞬间 | 瞬间 | 哈希查找、数组索引 |
| $O(\log n)$ | 瞬间 | 瞬间 | 瞬间（20 步） | 二分查找、平衡树 |
| $O(n)$ | 瞬间 | 瞬间 | 0.01 秒 | 遍历、线性扫描 |
| $O(n \log n)$ | 瞬间 | 瞬间 | 0.2 秒 | 归并/快排、堆排序 |
| $O(n^2)$ | 瞬间 | 0.01 秒 | **3 小时** | 冒泡排序、朴素双层循环 |
| $O(n^3)$ | 瞬间 | 10 秒 | 不可行 | Floyd、朴素矩阵乘 |
| $O(2^n)$ | 瞬间 | 不可行 | 不可行 | 子集枚举、朴素 TSP |
| $O(n!)$ | 0.03 秒 | 不可行 | 不可行 | 全排列枚举 |

**这张表最重要的信息**：$O(n^2)$ 和 $O(n\log n)$ 在 $n=1000$ 时都很快，看不出差别；但 $n$ 到百万级，一个 0.2 秒、一个 3 小时。**性能问题总是在数据长大之后才爆发**，这就是必须提前做复杂度分析的原因。

## 最小示例

### 分析循环

```python
# ① O(1) —— 与 n 无关
def constant(arr):
    return arr[0] + arr[-1]


# ② O(n) —— 单层循环
def linear(arr):
    total = 0
    for x in arr:               # n 次
        total += x              # O(1)
    return total


# ③ O(n²) —— 嵌套循环，内层次数与 n 相关
def quadratic(arr):
    pairs = []
    for i in range(len(arr)):           # n 次
        for j in range(i + 1, len(arr)):  # 平均 n/2 次
            pairs.append((arr[i], arr[j]))
    return pairs
# 精确次数 = n(n-1)/2 = n²/2 - n/2 → 去常数、留最高阶 → O(n²)


# ④ O(log n) —— 每次问题规模减半
def log_time(n):
    count = 0
    while n > 1:
        n //= 2                 # 关键：n 变成 n/2 而不是 n-1
        count += 1
    return count
# n → n/2 → n/4 → ... → 1，共 log₂n 步


# ⑤ O(n log n) —— 外层线性，内层对数
def n_log_n(arr):
    total = 0
    for x in arr:               # n 次
        k = len(arr)
        while k > 1:            # log n 次
            k //= 2
            total += 1
    return total


# ⑥ 陷阱：看起来是 O(n²)，其实是 O(n)
def actually_linear(n):
    count = 0
    i = 1
    while i < n:                # i 是指数增长的！
        for _ in range(10):     # 内层是常数 10 次，不是 n 次
            count += 1
        i *= 2
    return count
# 外层 log n 次 × 内层常数 → O(log n)
```

**手算 ③ 的精确次数**：外层 $i$ 从 0 到 $n-1$，内层执行 $n-1-i$ 次。总次数：

$$
\sum_{i=0}^{n-1}(n-1-i) = (n-1) + (n-2) + \cdots + 1 + 0 = \frac{n(n-1)}{2} = \frac{n^2}{2} - \frac{n}{2}
$$

去掉常数系数 $\frac{1}{2}$、舍去低阶项 $-\frac{n}{2}$，得 $O(n^2)$。

**判断循环复杂度的口诀**：看循环变量**怎么变**。

| 变化方式 | 循环次数 | 复杂度 |
|---|---|---|
| `i += 1` | $n$ | $O(n)$ |
| `i += k`（k 为常数） | $n/k$ | $O(n)$ |
| `i *= 2` | $\log_2 n$ | $O(\log n)$ |
| `i = i * i` | $\log \log n$ | $O(\log\log n)$ |
| `i -= 1` 且内层依赖 i | $\sum i$ | $O(n^2)$ |

### 分析递归：递归树与主定理

```python
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])        # T(n/2)
    right = merge_sort(arr[mid:])       # T(n/2)
    return merge(left, right)           # O(n)


def merge(a, b):
    res, i, j = [], 0, 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            res.append(a[i]); i += 1
        else:
            res.append(b[j]); j += 1
    return res + a[i:] + b[j:]
```

递归式：$T(n) = 2T(n/2) + O(n)$。

**递归树法**：

```text
层 0:            n                       ← 合并代价 n
层 1:       n/2      n/2                 ← 合计 n
层 2:    n/4  n/4  n/4  n/4              ← 合计 n
...
层 log n:  1  1  1 ... 1                 ← 合计 n

总层数 = log₂n，每层总代价 = n
总代价 = n × log₂n = O(n log n)
```

**主定理（Master Theorem）** 提供了直接查表的办法。对形如

$$
T(n) = a\,T(n/b) + f(n), \quad a \ge 1,\ b > 1
$$

的递归式，比较 $f(n)$ 与 $n^{\log_b a}$：

| 情形 | 条件 | 结论 |
|---|---|---|
| 1 | $f(n) = O(n^{\log_b a - \varepsilon})$，递归占主导 | $T(n) = \Theta(n^{\log_b a})$ |
| 2 | $f(n) = \Theta(n^{\log_b a})$，两边平衡 | $T(n) = \Theta(n^{\log_b a}\log n)$ |
| 3 | $f(n) = \Omega(n^{\log_b a + \varepsilon})$，合并占主导 | $T(n) = \Theta(f(n))$ |

套用实例：

| 算法 | 递归式 | $n^{\log_b a}$ | 情形 | 结果 |
|---|---|---|---|---|
| 归并排序 | $T(n)=2T(n/2)+n$ | $n^{\log_2 2}=n$ | 2 | $\Theta(n\log n)$ |
| 二分查找 | $T(n)=T(n/2)+1$ | $n^{\log_2 1}=1$ | 2 | $\Theta(\log n)$ |
| 二叉树遍历 | $T(n)=2T(n/2)+1$ | $n$ | 1 | $\Theta(n)$ |
| Karatsuba 乘法 | $T(n)=3T(n/2)+n$ | $n^{\log_2 3}\approx n^{1.585}$ | 1 | $\Theta(n^{1.585})$ |
| 朴素矩阵乘分治 | $T(n)=8T(n/2)+n^2$ | $n^3$ | 1 | $\Theta(n^3)$ |
| Strassen | $T(n)=7T(n/2)+n^2$ | $n^{\log_2 7}\approx n^{2.807}$ | 1 | $\Theta(n^{2.807})$ |

### 实测验证

理论要用实验印证。下面这段代码测量三种复杂度在规模翻倍时的耗时变化：

```python
import time


def measure(func, n):
    start = time.perf_counter()
    func(n)
    return time.perf_counter() - start


def o_n(n):
    return sum(range(n))


def o_n2(n):
    c = 0
    for i in range(n):
        for j in range(n):
            c += 1
    return c


print(f"{'n':>8} {'O(n) 耗时':>12} {'倍数':>6} {'O(n²) 耗时':>12} {'倍数':>6}")
prev1 = prev2 = None
for n in [1000, 2000, 4000]:
    t1, t2 = measure(o_n, n), measure(o_n2, n)
    r1 = f"{t1/prev1:.1f}x" if prev1 else "—"
    r2 = f"{t2/prev2:.1f}x" if prev2 else "—"
    print(f"{n:>8} {t1:>12.6f} {r1:>6} {t2:>12.6f} {r2:>6}")
    prev1, prev2 = t1, t2
```

典型输出（具体数值因机器而异，但**倍数**是稳定的）：

```text
       n    O(n) 耗时   倍数   O(n²) 耗时   倍数
    1000     0.000018     —     0.032100     —
    2000     0.000035   1.9x    0.128500   4.0x
    4000     0.000071   2.0x    0.514200   4.0x
```

**规模翻倍时，$O(n)$ 耗时变 2 倍、$O(n^2)$ 变 4 倍**——这正是大 O 的预测。这个「翻倍实验」是你验证代码实际复杂度最实用的手段。

## 易错点

1. **把大 O 当成实际耗时。** $O(n)$ 的算法可能比 $O(n^2)$ 的慢——如果前者的常数因子是 10000 而后者是 1，那么在 $n < 10000$ 时后者更快。小数据量下**常数因子和缓存友好性往往比渐进复杂度更重要**，这就是为什么很多标准库排序在 $n < 16$ 时会切换到插入排序。

2. **忽略隐藏的复杂度。** Python 里 `s = s + x` 对字符串是 $O(len(s))$（要复制整个字符串），放在循环里就是 $O(n^2)$；`list.insert(0, x)` 是 $O(n)$ 不是 $O(1)$；`x in list` 是 $O(n)$ 而 `x in set` 是 $O(1)$。**语言内置操作也有复杂度**，必须心中有数。

3. **切片的隐藏开销。** 上面的 `merge_sort` 里 `arr[:mid]` 每次都会**复制**一份，带来额外的 $O(n)$ 空间和时间。严格来说这个实现的空间是 $O(n\log n)$。生产实现会传下标区间而不是切片。

4. **只看最坏情况。** 快排最坏是 $O(n^2)$，但因为随机化后几乎不可能触发，实践中它比最坏 $O(n\log n)$ 的堆排序更快。**平均复杂度、常数因子、缓存行为**同样是选型依据。

5. **多变量硬合并。** 邻接表遍历是 $O(V+E)$。稀疏图 $E \approx V$，稠密图 $E \approx V^2$——写成 $O(V)$ 会严重低估稠密图的代价。

6. **把「空间复杂度」漏掉。** 递归的栈空间、DP 表的存储、切片的副本都算空间。$O(n^2)$ 空间在 $n = 10^5$ 时就是 100 亿个单元，直接 OOM。

7. **误以为 $O(\log n)$ 的底数重要。** $\log_2 n$ 与 $\log_{10} n$ 只差常数倍，都是 $O(\log n)$。但 $\log$ 在**指数位置**时底数就重要了：$2^n$ 与 $3^n$ 不是同一个量级。

## 练习

1. 分析下面这段代码的复杂度，并说明理由：

   ```python
   def f(n):
       for i in range(n):
           j = 1
           while j < n:
               j *= 2
       # 提示：外层 n 次，内层 log n 次
   ```

2. 用主定理求解：$T(n) = 4T(n/2) + n^2$、$T(n) = 3T(n/4) + n$、$T(n) = 2T(n/2) + n\log n$（最后一个主定理不直接适用，用递归树法）。
3. 用「翻倍实验」测出 Python 中 `list.append` 和 `list.insert(0, x)` 的实际复杂度差异，验证前者是均摊 $O(1)$、后者是 $O(n)$。
4. 找出下面代码的隐藏 $O(n^2)$ 并修复：

   ```python
   result = ""
   for word in words:          # words 有 n 个元素
       result += word + " "
   ```

   （提示：改用 `" ".join(words)`。）
5. 证明 $\log(n!) = \Theta(n\log n)$。这个结论是「比较排序下界为 $\Omega(n\log n)$」的关键一步。
6. 手算：一个 $O(n^2)$ 的算法处理 $n=1000$ 需要 1 秒，处理 $n=10000$ 大约需要多久？如果换成 $O(n\log n)$ 呢？

## 小结

大 O 分析是程序员唯一一个**与硬件无关的性能语言**。它的价值不在于预测「跑多少毫秒」，而在于回答「数据长大 10 倍会怎样」——这个问题决定了你的系统能不能撑到明年。掌握它只需要三步：**看循环变量怎么变**（判断循环复杂度）、**画递归树或套主定理**（判断递归复杂度）、**用翻倍实验验证**（对照理论与现实）。同时牢记它的边界：小数据量下常数因子说了算，多变量时不能硬合并，空间复杂度和时间同样致命。

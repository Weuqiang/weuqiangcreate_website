# 图灵机与可计算性

计算机能算什么？这个问题在第一台计算机诞生**之前**就被回答了。1936 年，图灵用一个纸带加读写头的想象装置，划出了「可计算」与「不可计算」的边界——而这条边界，至今没有任何真实计算机能够跨越。

## 学习目标

- 说清图灵机的五个组成部分与一步转移的完整含义。
- 手动模拟一台图灵机的执行过程。
- 理解「停机问题不可判定」的对角线证明，并说清它意味着什么。
- 区分**不可计算**（永远做不到）与**难以计算**（做得到但太慢），并说清 P、NP 的含义。

## 核心直觉

### 图灵机：把「计算」这件事本身形式化

在图灵之前，「计算」只是个模糊的日常概念。图灵的贡献是给它一个**精确的数学定义**：一台图灵机由五部分构成。

1. **无限长的纸带**：分成一格格，每格写一个符号（含空白符）。这就是内存。
2. **读写头**：指向纸带上的某一格，能读、能写、能左右移动一格。
3. **有限状态集**：机器当前处于哪个状态，比如 `q0`、`q1`、`halt`。这是「有限」的——这一点至关重要。
4. **转移函数**：核心规则表，形如 `(当前状态, 读到的符号) → (写入符号, 移动方向, 新状态)`。
5. **初始状态与接受/拒绝状态**。

运行过程就是不断查表执行：读当前格 → 查转移函数 → 写、移动、换状态 → 重复，直到进入停机状态。

**为什么这么简陋的模型就够了？** 因为**丘奇-图灵论题（Church–Turing Thesis）** 断言：

> 任何「凭直觉认为可以机械计算」的函数，都能被图灵机计算。

这不是定理（「直觉可计算」无法形式化，因此无法证明），而是一个至今未被推翻的论断。λ 演算、递归函数、寄存器机、你的笔记本电脑——所有这些计算模型被证明**互相等价**，能力完全相同。这种等价性叫**图灵完备（Turing complete）**。

推论很有冲击力：**你的手机和一台无限纸带的图灵机，能计算的函数集合是一模一样的**。差别只在速度和内存，不在能力。

有趣的是，图灵完备性极易达成：C、Python、Java 自不必说，连 SQL（带递归 CTE）、正则表达式引擎（带反向引用）、Excel 公式（带 LAMBDA）、甚至《我的世界》红石电路和《魔法风云会》的卡牌规则都被证明是图灵完备的。

### 停机问题：第一个被证明不可计算的问题

**问题**：能否写一个程序 `halts(P, I)`，输入任意程序 `P` 和输入 `I`，判断 `P(I)` 是会停机还是会无限循环？

**答案：不可能。** 证明用的是对角线法，只有五行：

假设存在这样的 `halts`。那我们构造一个捣乱程序 `paradox`：

```python
def paradox(P):
    if halts(P, P):      # 如果「P 以自己为输入」会停机
        while True:      # 那我就死循环
            pass
    else:                # 如果它不停机
        return           # 那我就立刻停机
```

现在问：`paradox(paradox)` 会停机吗？

- 若**会停机**，则按定义 `halts(paradox, paradox)` 返回 `True`，于是 `paradox` 进入 `while True` → **不停机**。矛盾。
- 若**不停机**，则 `halts(paradox, paradox)` 返回 `False`，于是 `paradox` 立刻 `return` → **停机**。矛盾。

两种情况都矛盾，所以假设错误——`halts` 不存在。$\blacksquare$

**这个结论的现实意义**：

- 没有任何工具能**完美**检测出所有死循环。IDE 的死循环警告、静态分析器都只能处理特定模式。
- 没有任何杀毒软件能**完美**判断一段程序是否有恶意行为（这可以归约到停机问题）。
- 编译器无法判断所有的「不可达代码」。
- **莱斯定理（Rice's Theorem）** 把结论推到极致：*关于程序行为的任何非平凡性质，都是不可判定的*。「这个程序会不会输出 42」「这两个程序是否等价」——全都不可判定。

这不是「我们还不够聪明」，而是**逻辑上的不可能**。

### 不可计算 vs 难以计算

这是两个完全不同的层次，务必分清：

| 层次 | 含义 | 例子 |
|---|---|---|
| **不可计算（不可判定）** | 不存在算法，永远做不到 | 停机问题、希尔伯特第十问题、程序等价性 |
| **可计算但难（指数级）** | 有算法，但规模一大就跑不完 | 旅行商精确解、SAT 求解 |
| **可计算且易（多项式）** | 有实用算法 | 排序、最短路、矩阵乘法 |

第二、三层的分界就是著名的 **P vs NP** 问题：

- **P**：能在**多项式时间内求解**的问题（如排序、最短路径）。
- **NP**：能在**多项式时间内验证一个候选解**的问题（如数独——给你一个填好的盘，几秒就能验证对错，但从空盘求解很难）。
- 显然 $P \subseteq NP$（能快速解就能快速验证）。
- **$P = NP$？** 这是克雷数学研究所七个千禧年难题之一，悬赏一百万美元，至今未解。多数学者相信 $P \ne NP$。

**NP 完全（NP-Complete）** 问题是 NP 中「最难的一批」：任何 NP 问题都能在多项式时间内归约到它。所以**只要有一个 NP 完全问题被找到多项式解法，$P = NP$ 立刻成立**。SAT、旅行商（判定版）、图着色、子集和都是 NP 完全的。

现实影响：现代密码学（RSA、椭圆曲线）的安全性建立在「大整数分解很难」上。如果 $P = NP$ 被证明且给出了构造性算法，整个互联网的加密体系一夜之间失效。

## 最小示例

用 Python 实现一个通用图灵机模拟器，跑一个「二进制加一」的机器：

```python
def turing_machine(tape, rules, start="q0", halt="halt", blank="_"):
    """
    tape:  初始纸带（字符串）
    rules: {(状态, 读到的符号): (写入符号, 移动方向 L/R, 新状态)}
    """
    tape = list(tape)
    head, state, steps = len(tape) - 1, start, 0     # 从最右端开始（低位）
    history = []

    while state != halt:
        if head < 0:                                  # 向左越界，补空白
            tape.insert(0, blank)
            head = 0
        while head >= len(tape):                      # 向右越界，补空白
            tape.append(blank)

        symbol = tape[head]
        key = (state, symbol)
        if key not in rules:
            raise ValueError(f"无转移规则：状态 {state} 读到 '{symbol}'")

        write, move, new_state = rules[key]
        history.append((steps, state, "".join(tape), head, symbol))
        tape[head] = write
        head += 1 if move == "R" else -1
        state = new_state
        steps += 1
        if steps > 1000:
            raise RuntimeError("超过 1000 步，可能不停机")

    return "".join(tape).strip(blank), steps, history


# 二进制加一机：从最低位开始，遇 1 变 0 继续进位，遇 0 或空白变 1 后停机
increment_rules = {
    ("q0", "1"): ("0", "L", "q0"),      # 1 + 进位 → 0，继续向左进位
    ("q0", "0"): ("1", "L", "halt"),    # 0 + 进位 → 1，完成
    ("q0", "_"): ("1", "L", "halt"),    # 最高位溢出，补 1
}

for binary in ["1011", "0111", "1111"]:
    result, steps, hist = turing_machine(binary, increment_rules)
    print(f"{binary} (={int(binary, 2)}) + 1 = {result} (={int(result, 2)})，{steps} 步")

# 1011 (=11) + 1 = 1100 (=12)，2 步
# 0111 (=7)  + 1 = 1000 (=8)，4 步
# 1111 (=15) + 1 = 10000 (=16)，5 步
```

**手动模拟** `1011 + 1`（读写头 `^` 标出当前位置）：

| 步 | 状态 | 纸带 | 头位置 | 读到 | 规则 | 动作 |
|---|---|---|---|---|---|---|
| 0 | q0 | `1011` | 3 | `1` | (q0,1)→(0,L,q0) | 写 0，左移 |
| 1 | q0 | `101`**`0`** | 2 | `1` | (q0,1)→(0,L,q0) | 写 0，左移 |
| 2 | q0 | `10`**`00`** | 1 | `0` | (q0,0)→(1,L,halt) | 写 1，停机 |
| — | halt | `1`**`1`**`00` | — | — | — | 结果 `1100` = 12 ✅ |

**手算步数规律**：这台机器的步数 = 末尾连续 1 的个数 + 1。`1011` 末尾一个 1 → 2 步；`0111` 末尾三个 1 → 4 步；`1111` 末尾四个 1 → 5 步。与程序输出完全一致。

**复杂度**：设二进制串长 $n$，最坏情况（全是 1）需要 $O(n)$ 步。图灵机的「时间复杂度」就定义为步数，「空间复杂度」定义为用到的纸带格数——现代复杂度理论正是建立在这个模型上的。

### 三种不可计算问题的对照

| 问题 | 描述 | 状态 |
|---|---|---|
| 停机问题 | 判断任意程序是否停机 | 不可判定（1936 图灵） |
| 希尔伯特第十问题 | 判断丢番图方程是否有整数解 | 不可判定（1970 Matiyasevich） |
| 波斯特对应问题 | 多米诺骨牌能否排成上下相同的串 | 不可判定 |
| 忙碌海狸函数 $BB(n)$ | $n$ 状态图灵机停机前最多写多少个 1 | **不可计算**，且增长快过任何可计算函数 |

$BB(n)$ 特别值得一提：$BB(1)=1$、$BB(2)=4$、$BB(3)=6$、$BB(4)=13$，而 $BB(5) = 47176870$（2024 年才被确认），$BB(6)$ 已知大于 $10^{10^{10^{10^{10^7}}}}$。这个函数是「不可计算」最震撼的具体例子。

## 易错点

1. **把「不可计算」理解成「计算机不够快」。** 停机问题不是速度问题——就算给你无限时间和无限内存，也不存在这样的算法。这是逻辑层面的不可能。

2. **混淆不可判定与 NP 完全。** 旅行商问题是**可计算**的（暴力枚举一定能算出来），只是慢；停机问题是**根本没有算法**。前者是效率问题，后者是存在性问题。

3. **以为图灵完备意味着「好用」。** 图灵完备只是能力下限的标志。Brainfuck 语言图灵完备，但没人拿它写业务。反过来，很多刻意设计成**非**图灵完备的语言（如 SQL 早期版本、Coq 的终止性检查、以太坊的 gas 机制）恰恰是为了**保证程序一定会停机**——用能力换可预测性。

4. **误以为量子计算机能突破图灵机。** 量子计算机在**可计算性**上与经典图灵机完全等价，只是在某些问题上更快（Shor 算法分解质因数是多项式时间）。它不能解决停机问题。

5. **认为 $P \ne NP$ 已被证明。** 这仍是开放问题。目前只是「多数人相信」，且已有数百个错误的证明尝试被推翻。

6. **忽视「不可判定」的实践影响。** 因为停机问题不可判定，所以静态分析工具必然在「误报」和「漏报」之间取舍——这不是工具做得不好，而是理论上的必然。理解这一点能让你对工具的局限更宽容也更清醒。

2. 实现一台判断**回文**的图灵机：读最左符号、擦掉、跑到最右比较、擦掉、返回，直到纸带为空（接受）或发现不匹配（拒绝）。用 `abba` 和 `abab` 测试。
3. 手工模拟 `0111 + 1` 的全过程，画出四步的纸带状态表，验证结果是 `1000`。
4. 写出停机问题的对角线证明（不看本页），并用自己的话解释「为什么自我引用是矛盾的来源」。
5. 举出三个你日常用到的工具，它们的功能受限于不可判定性（提示：类型检查器、死代码消除、内存泄漏检测）。

## 小结

图灵机是计算机科学的**公理起点**：它用一条纸带和一张规则表，把「计算」这个模糊概念钉死成了数学对象。由此得到的两个结论至今支配着这门学科——**丘奇-图灵论题**告诉我们所有计算模型能力相同（所以你不必寻找「更强的计算机」），**停机问题的不可判定性**告诉我们存在计算机永远无法回答的问题（所以完美的静态分析工具、完美的杀毒软件在理论上就不存在）。再往上一层，P vs NP 划出了「能算」与「算得起」的界线，托举着整个现代密码学。这些不是屠龙之技，而是让你知道**哪些方向根本不必尝试**的地图边界。

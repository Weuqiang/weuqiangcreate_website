# 贪心算法

贪心（Greedy）是最简单也最危险的算法范式：**每一步都选当前看起来最好的**，不回头、不后悔。简单在于代码往往几行就写完；危险在于**它经常是错的**，而且错得悄无声息——你得到一个看似合理的答案，但它不是最优解。

## 学习目标

- 说清贪心成立的两个前提：**贪心选择性质**与**最优子结构**。
- 掌握三种证明贪心正确性的方法，至少能用「交换论证」做一次完整证明。
- 熟练解决区间调度、找零、霍夫曼编码三类经典问题。
- 面对新问题时，能快速构造反例判断贪心**是否失效**。

## 核心直觉

### 贪心 vs 动态规划

这两者都要求「最优子结构」，区别在于**考虑多少种选择**：

| 维度 | 贪心 | 动态规划 |
|---|---|---|
| 每步的决策 | 只选一个（当前最优），**不回头** | 枚举所有可能，取最好的 |
| 是否需要子问题的解 | 不需要，先决策后求解 | 需要，先解子问题再决策 |
| 时间复杂度 | 通常 $O(n)$ 或 $O(n\log n)$（排序） | 通常 $O(n^2)$ 或更高 |
| 正确性 | **需要严格证明** | 只要状态转移对就对 |

一句话：**贪心是「不需要回溯的 DP」**。当且仅当「局部最优必然导向全局最优」时才能用。

### 两个前提条件

**1. 贪心选择性质**：全局最优解可以通过一系列局部最优选择得到。也就是说，做出当前这个贪心选择后，**剩下的问题仍然是同类型的子问题，而且和当前选择无关**。

**2. 最优子结构**：问题的最优解包含子问题的最优解。

第 1 条是贪心独有的、也是最难验证的。举个直观的失效例子——**0/1 背包**：

```text
背包容量 10
物品 A：重量 6，价值 30，性价比 5.0
物品 B：重量 5，价值 20，性价比 4.0
物品 C：重量 5，价值 20，性价比 4.0
```

按性价比贪心：先拿 A（占 6，价值 30），剩余容量 4，B 和 C 都放不下 → **总价值 30**。
真正的最优解：B + C（占 10）→ **总价值 40**。

贪心失败了。因为「拿了 A」这个选择改变了后续子问题的性质（剩余容量变成了 4 这个尴尬的数），违反了贪心选择性质。所以 0/1 背包必须用 [动态规划](/docs/计算机科学基础/数据结构与算法/动态规划入门)。

但把物品改成**可以切分**（分数背包），贪心就对了：按性价比从高到低装，装不下就装一部分。区别就在于「可切分」让每一步的选择不再限制后续。

### 三种证明方法

1. **交换论证（Exchange Argument）**——最常用。假设存在一个最优解 $OPT$ 与贪心解 $G$ 不同，找到第一个不同的位置，证明把 $OPT$ 在该位置的选择**换成**贪心的选择后，解不会变差。反复交换即可把 $OPT$ 变成 $G$，故 $G$ 也是最优。

2. **贪心留在前面（Greedy Stays Ahead）**——归纳证明贪心解在每一步都不劣于任何其他解。Dijkstra 的正确性就是这样证的。

3. **构造反例证伪**——想不出证明时，花五分钟构造小规模反例。**能找到反例就立刻放弃贪心**，这比硬证快得多。

## 最小示例

### 例 1：活动选择（区间调度）

给定若干活动的开始与结束时间，一间教室最多能安排多少个不冲突的活动？

**贪心策略：按结束时间升序排序，每次选结束最早且与已选不冲突的。**

```python
def activity_selection(intervals):
    """intervals: [(start, end), ...]，返回最多可选的不重叠区间"""
    intervals.sort(key=lambda x: x[1])       # 关键：按结束时间排序
    chosen, last_end = [], float('-inf')
    for s, e in intervals:
        if s >= last_end:                    # 不冲突
            chosen.append((s, e))
            last_end = e
    return chosen


acts = [(1, 4), (3, 5), (0, 6), (5, 7), (3, 9), (5, 9), (6, 10), (8, 11)]
print(activity_selection(acts))
# [(1, 4), (5, 7), (8, 11)]  → 最多安排 3 个
```

**为什么按「结束时间」而不是「开始时间」或「时长」？** 用交换论证：结束最早的活动 $a_1$ 给后面**留下的空余时间最多**。设最优解的第一个活动是 $b_1$，那么 $end(a_1) \le end(b_1)$。把 $b_1$ 换成 $a_1$，后续活动仍然都能安排（因为空出的时间只多不少），活动数不变。所以存在一个包含 $a_1$ 的最优解。递归应用即得。

反观其他策略的反例：

| 策略 | 反例 | 结果 |
|---|---|---|
| 按开始时间最早 | `(0,10), (1,2), (3,4)` | 只选 1 个，最优是 2 个 |
| 按时长最短 | `(0,5), (4,6), (5,10)` | 只选 (4,6) 共 1 个，最优是 2 个 |
| **按结束时间最早** | — | ✅ 总是最优 |

### 例 2：找零问题——贪心何时失效

```python
def coin_change_greedy(coins, amount):
    """贪心找零：每次用最大面额"""
    coins = sorted(coins, reverse=True)
    result, remain = [], amount
    for c in coins:
        while remain >= c:
            result.append(c)
            remain -= c
    return result if remain == 0 else None


# 人民币/美元体系：贪心正确
print(coin_change_greedy([1, 5, 10, 25], 63))
# [25, 25, 10, 1, 1, 1] → 6 枚，确实最优

# 构造的反例币制：贪心失效！
print(coin_change_greedy([1, 3, 4], 6))
# [4, 1, 1] → 3 枚
# 真正最优是 [3, 3] → 2 枚
```

**结论**：找零问题的贪心正确性**取决于币制**。像 1/5/10/25 这种「后一个面额是前一个的整数倍或满足特定条件」的**正则币制**贪心可行；任意币制必须用 DP。这是「贪心需要证明」的最好例证——同一段代码，换套硬币就错了。

### 例 3：霍夫曼编码

给定字符频率，构造前缀码使**平均编码长度最短**。贪心策略：**每次合并频率最小的两个节点**。

```python
import heapq
from collections import Counter


def huffman(text):
    freq = Counter(text)
    if len(freq) == 1:                       # 只有一种字符的边界情况
        return {next(iter(freq)): "0"}

    heap = [[f, i, {ch: ""}] for i, (ch, f) in enumerate(freq.items())]
    heapq.heapify(heap)
    counter = len(heap)

    while len(heap) > 1:
        f1, _, left = heapq.heappop(heap)    # 取两个最小频率
        f2, _, right = heapq.heappop(heap)
        merged = {}
        for ch, code in left.items():
            merged[ch] = "0" + code          # 左子树加前缀 0
        for ch, code in right.items():
            merged[ch] = "1" + code          # 右子树加前缀 1
        heapq.heappush(heap, [f1 + f2, counter, merged])
        counter += 1

    return heap[0][2]


text = "aaaaaaaabbbbccd"          # a:8, b:4, c:2, d:1
codes = huffman(text)
for ch in sorted(codes):
    print(ch, codes[ch])
# a 1 / b 01 / c 001 / d 000
# 具体的 0/1 分配取决于左右子树顺序，但每个字符的「码长」是确定的

encoded_bits = sum(len(codes[ch]) for ch in text)
print(f"霍夫曼编码：{encoded_bits} bit")      # 8*1 + 4*2 + 2*3 + 1*3 = 25 bit
print(f"定长编码：{len(text) * 2} bit")       # 4 个字符需 2 bit → 15*2 = 30 bit
```

**手算验算**：频率 a=8, b=4, c=2, d=1，总长 15。

| 字符 | 频率 | 霍夫曼码 | 码长 | 频率 × 码长 |
|---|---|---|---|---|
| a | 8 | `1` | 1 | 8 |
| b | 4 | `01` | 2 | 8 |
| c | 2 | `001` | 3 | 6 |
| d | 1 | `000` | 3 | 3 |
| **合计** | 15 | — | — | **25 bit** |

注意这套码是**前缀码**：没有任何一个码字是另一个的前缀，所以解码时不需要分隔符，从左往右扫一遍就能唯一还原。

定长编码需要 $\lceil \log_2 4 \rceil = 2$ bit/字符 $\times 15 = 30$ bit。霍夫曼节省了 $5/30 \approx 17\%$。频率分布越不均匀，节省越多。

贪心正确性的直觉：**频率最低的两个字符一定在编码树的最深处，且互为兄弟**。既然它们注定最深，不如现在就把它们合并掉——这就是交换论证。

| 问题 | 贪心策略 | 是否最优 | 复杂度 |
|---|---|---|---|
| 活动选择 | 结束时间最早优先 | ✅ 是 | $O(n\log n)$ 排序主导 |
| 分数背包 | 性价比最高优先 | ✅ 是 | $O(n\log n)$ |
| 0/1 背包 | 性价比最高优先 | ❌ **否**，需 DP | — |
| 找零（正则币制） | 最大面额优先 | ✅ 是 | $O(\text{面额数} + \text{枚数})$ |
| 找零（任意币制） | 最大面额优先 | ❌ **否**，需 DP | — |
| 霍夫曼编码 | 合并最小两个频率 | ✅ 是 | $O(n\log n)$ 堆操作 |
| 最小生成树 | 最小边 / 最近点优先 | ✅ 是（切割性质） | $O(E\log E)$ |
| 单源最短路（非负） | 当前最近点优先 | ✅ 是 | $O((V+E)\log V)$ |

## 易错点

1. **不证明就用贪心。** 这是贪心最大的坑。写完能跑、样例也过，但在特定输入上给出次优解。**养成习惯：写贪心前先花 3 分钟构造反例**，构造不出来再动手。

2. **排序的键选错。** 贪心题九成的难点在「按什么排序」。活动选择按结束时间、区间合并按开始时间、任务调度按截止时间——一字之差，答案全错。

3. **把「局部最优」等同于「贪心可行」。** 每一步都取局部最优是贪心的**做法**，不是它**正确的理由**。0/1 背包每步也取了局部最优，但结果不对。

4. **忽视等价情况的处理。** 排序时若键相等，次序可能影响结果（尤其是要求输出方案而非仅数值时）。要么明确定义二级排序键，要么证明次序无关。

5. **误认为贪心一定比 DP 快。** 大多数时候是，但贪心的价值首先在于**正确**。为了省一个 $\log$ 而用错误的贪心，是本末倒置。

6. **区间问题的边界搞混。** `[1,4]` 和 `[4,7]` 算不算冲突？取决于区间是闭区间还是半开区间。上面代码用 `s >= last_end` 表示「端点相接不算冲突」，如果题目要求严格分开，得改成 `s > last_end`。

## 练习

1. **区间合并**：给定若干可能重叠的区间，合并所有重叠部分。思考这题该按什么排序（提示：与活动选择不同）。
2. **无重叠区间**：给定区间集合，最少移除多少个区间才能使剩余区间互不重叠？（提示：等价于活动选择的补集。）
3. **加油站问题**：环形路上有 $n$ 个加油站，第 $i$ 站可加油 `gas[i]`、到下一站耗油 `cost[i]`。求能绕行一圈的起点。用 $O(n)$ 贪心解决，并证明「如果从 A 出发到不了 B，那么 A 与 B 之间任何一点出发也到不了 B」。
4. **任务调度带截止时间**：每个任务有耗时和截止时间，求最多能按时完成几个。提示：按截止时间排序 + 用大顶堆做「后悔」——发现超时就丢掉已选中耗时最长的那个。
5. 为找零问题写一个**验证器**：对给定币制，暴力枚举 1 到 100 的所有金额，对比贪心解与 DP 解，找出所有贪心失效的金额。用 `[1,3,4]` 和 `[1,5,10,25]` 分别测试。

## 小结

贪心算法的代码通常是所有范式里最短的，但它的**思维成本最高**——难点不在实现，而在「凭什么这样是对的」。掌握贪心的正确姿势是：先想清楚贪心的键是什么，然后要么用交换论证证明它，要么构造反例推翻它，两条路都走不通时果断退回 [动态规划](/docs/计算机科学基础/数据结构与算法/动态规划入门)。记住那张对照表：**分数背包可贪、0/1 背包不可；正则币制可贪、任意币制不可**。这两组对照浓缩了贪心的全部精髓。

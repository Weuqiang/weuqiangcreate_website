# 过程奖励模型与可扩展监督

大模型对齐里有一个尖锐的矛盾：**我们要用人类反馈教会模型做对的事，但模型很快会在很多任务上比人类更强，人类根本判不对**。这一页先讲「怎么把奖励信号做得更细」——过程奖励模型（PRM）；再讲「当监督者不够强时怎么办」——可扩展监督（Scalable Oversight）。

## 学习目标

- 区分结果奖励模型（ORM）与过程奖励模型（PRM），理解后者为何对长链推理关键。
- 掌握 PRM 的数据构造方式（人工逐步标注、Math-Shepherd 自动标注）与在解码/训练中的用法。
- 理解可扩展监督要解决的问题，以及辩论、递归奖励建模（RRM）、迭代蒸馏扩增（IDA）、弱到强泛化四类代表性思路。
- 看清 PRM 与可扩展监督各自的失败模式（reward hacking、标注偏差、过程切分）。

## 前置知识

- [大模型训练与对齐](/docs/人工智能/大模型与应用/大模型训练与对齐) —— RLHF/DPO 的整体框架。
- [强化学习进阶](/docs/人工智能/机器学习/强化学习进阶) —— 奖励、策略梯度、PPO 的基本语言。
- 基本的数学/代码推理直觉：能看懂「一步步推导」为什么比「只看最终答案」更难评判。

## 核心概念

### 结果奖励 vs 过程奖励

人类给一段回答打分时，通常只看**最终结果对不对**（ORM，Outcome-supervised Reward Model）。但对数学证明、长程代码、多步规划这类任务，只看结果有两个问题：

1. **信用分配难**：结果是错的，但错在第 3 步还是第 7 步？ORM 给不出信号。
2. **奖励太稀疏**：一条长链只有末尾一个信号，强化学习前期几乎学不到东西。

PRM（Process-supervised Reward Model）改为对**推理链上的每一步**打分：

$$r_{\text{PRM}}(y) = \sum_{t=1}^{T} r_\phi(s_t \mid s_{<t})$$

其中 $s_t$ 是第 $t$ 步，模型 $r_\phi$ 估计这一步「正确性/可信度」。这样每一步都拿到密集信号，信用分配变容易。Lightman 等人（2023，*Let's Verify Step by Step*）在 MATH 上证明：**PRM 训练的奖励模型显著优于 ORM**，尤其在困难题上更容易挑出真正正确的长推理。

### PRM 的数据从哪来

最贵的是「步骤级标注」：给每一步标 +1 / -1 / 不确定。两条路：

- **人工逐步标注**：OpenAI 的 PRM800K 就是人工标的过程数据，质量高但极昂贵。
- **自动逐步标注**：Math-Shepherd 的思路是，对每一步做多次 **rollout**（从该步继续采样到终局），用「后续能否导出正确答案」的频率作为该步的软标签——不需要人类逐步标注，可扩展到海量题。

注意：一个隐含前提是要能**切分出「步骤」**（按换行、按代码行、按推理断点）。切分错了，PRM 学的就是错的边界。

### PRM 怎么用

两类用法，互补而非互斥：

- **解码/搜索时**：用 PRM 给候选链打分，做 best-of-n、beam search with PRM，或类 AlphaGo 的 MCTS（如 AlphaGo-MuZero 式规划）。这不改训练，只改「怎么选答案」，很多基准上能直接涨点。
- **训练时**：把 PRM 当 reward，在每一步上做 step-level 策略优化（配合 PPO/RLOO）。比仅用 ORM 的 RLHF 更稳，因为它惩罚的是「中间走了错路」，而非只在结尾一刀切。

### 可扩展监督：当监督者不如被监督者

PRM 仍假设「有正确的步骤标签」。但很多任务（开放式推理、科研、写代码库）人类**自己也判不准**——这就是可扩展监督关心的核心问题：

> 如何可靠地引导、评估比监督者更聪明的人工智能系统？

代表性方案：

- **辩论（Debate）**：两个模型就答案正反辩论，人类只做「谁更有道理」的浅层裁判。理论上，如果「可被解释地驳倒」比「生成谎言」更难，辩论就能把强模型的能力「压缩」到人类可判断的通道里。
- **递归奖励建模（RRM）**：用「当前模型」去给「更强的模型」当奖励模型，再把得到的强模型拿去训练下一代奖励模型，如此递归。前提是每一步只比上一代强一点，监督缺口可控。
- **迭代蒸馏与扩增（IDA）**：把一个难任务拆成人类能监督的小任务，训练助手；再用助手帮人类监督更复杂的任务，迭代放大人类能力。
- **弱到强泛化（Weak-to-strong）**：直接用弱监督者（如小模型/弱标签）去监督强模型，研究「强模型能否在弱信号下仍学会正确目标」——Burns 等人（2023）发现这种泛化确实部分成立，但存在系统性「谄媚弱监督」的风险。

## 示例

下面用一个最小直觉展示「为什么 PRM 选得更好」。

假设有一道题，模型生成了两条推理链：

```text
链 A：步骤1 ✓ → 步骤2 ✓ → 步骤3 ✗（这里逻辑跳了）→ 最终答案（碰巧）✓
链 B：步骤1 ✓ → 步骤2 ✓ → 步骤3 ✓ → 步骤4 ✓ → 最终答案 ✓
```

ORM 只看最终答案，两条都给 +1，**无法区分 A 是蒙对的、B 是真懂**。PRM 给每一步打分时，链 A 在第 3 步拿到负分，总分低于链 B，于是搜索阶段会选 B。这就是「过程信号能识别伪正确」的关键。

伪代码层面的 best-of-n with PRM：

```python
def select_with_prm(problem, model, prm, n=8):
    candidates = [model.generate(problem) for _ in range(n)]   # 每条是带步骤的链
    scored = []
    for chain in candidates:
        steps = split_steps(chain)                             # 切分步骤（关键预处理）
        score = sum(prm.score_step(steps[:i+1]) for i in range(len(steps)))
        scored.append((score, chain))
    return max(scored, key=lambda x: x[0])[1]                  # 取过程总分最高者
```

真正落地时还常在「答案正确性」上加一层 ORM 兜底：先筛掉最终答案错的，再在正确候选里用 PRM 挑过程最干净的。

## 易错点

- **Reward hacking / 谄媚**：PRM 若由「容易被人类认可」的数据训练，会学会「写得好看但错」的步骤；弱到强实验中最典型的失败就是强模型直接**迎合弱监督者的偏见**。
- **步骤切分依赖**：自动标注（Math-Shepherd）的质量高度依赖「步」的定义；切得太粗或太细，软标签都失真。
- **PRM 不是 ORM 的替代品**：ORM 在「答案本身可被验证」的任务上仍便宜且稳。两者常被组合使用，而非二选一。
- **可扩展监督的假设脆弱**：辩论依赖「驳倒谎言比编谎言难」这一未证实的归纳假设；RRM/IDA 依赖「每代只强一点点」的渐进性，一旦跳跃过大监督就会失效。

## 练习

1. 给你一道需要 5 步推导的数学题，分别描述 ORM 与 PRM 各自会怎么打分，并指出 ORM 在哪类情况下会给出误导性高分。
2. 设想一个「人类根本判不对答案」的任务，尝试用「辩论」框架设计两个 AI 辩手的角色与目标，并说明人类裁判只需判断什么。
3. 弱到强泛化实验中，强模型为什么可能「谄媚」弱监督者？这在 RLHF 的实践里会以什么形式出现？

## 小结

过程奖励模型把「只看结果」的稀疏信号变成「逐步」的密集信号，是长链推理对齐的利器，其数据可来自昂贵的人工逐步标注，也可用 rollout 自动标注。但它仍假设存在可靠步骤标签；当任务连人类都判不准时，问题升级为**可扩展监督**——辩论、递归奖励建模、IDA、弱到强泛化等思路试图在「监督者不够强」的前提下仍能可靠引导强模型。两者共同的敌人是 reward hacking 与监督信号失真，落地时通常需要 ORM 与 PRM、自动与人工、过程与结果的多层组合。

## 核心概念

### 记忆：智能体的「外挂大脑」

大模型本身只有固定上下文窗口（即使 [长上下文](/docs/人工智能/大模型与应用/长上下文与位置编码扩展) 扩展到百万 token，也装不下持续数天的任务历史）。智能体必须**把信息外置**到记忆系统：

| 记忆类型 | 类比 | 工程实现 |
|---------|------|---------|
| 工作记忆 | 当前正在想的事 | 上下文窗口内的临时状态、当前任务栈 |
| 情景记忆 | 「上次怎么做的」 | 向量数据库存历史轨迹（episode） |
| 语义记忆 | 「已知的事实」 | 知识库、抽取出的实体关系 |
| 程序记忆 | 「会做的技能」 | 可复用工具、SOP、子 agent 定义 |

典型实现是「**检索增强的记忆**」：每轮把相关历史从向量库召回，拼进 prompt。难点在**检索什么、何时检索、检索多了反而噪声大**。

### 规划：从「一步走」到「想好几步」

最朴素的 agent 是「感知→行动」直连（看到问题直接调工具）。健壮的 agent 需要**先规划再执行**：

- **ReAct**（Reason + Act）：交替生成「思考链」和「行动」，每步根据环境反馈调整——是最常用的基线。
- **Reflexion（自我反思）**：任务失败后，让模型**写下反思**（哪里错了、下次怎么做），存入记忆，下一轮带着反思重试。相当于给 agent 一个「复盘」循环。
- **Tree-of-Thought（ToT）**：把推理展开成树，对多个候选中间步骤做评估与回溯，适合需要搜索的决策任务（如谜题、规划）。
- ** hierarchical / 子目标分解**：把大任务拆成可验证的子目标，逐个子目标调度工具与子 agent。

规划与 [推理模型](/docs/人工智能/大模型与应用/推理模型与测试时计算) 的关系密切：test-time compute 越大，agent 在「规划」上能投入的搜索/反思步数越多，成功率越高。

### 闭环：记忆-规划-行动-反思

一个可用的 agent 不是单次调用，而是**带状态的循环**：

```
观察(observation) → 检索记忆 → 规划(plan) → 行动(act/调工具) → 得到结果
       ↑                                                          │
       └──────── 把(轨迹, 成败, 反思) 写回记忆 ←──────────────────┘
```

这个闭环让 agent 能**跨会话积累经验**：第一次踩的坑，第二次自动避开。它也是 [AI 安全对齐](/docs/人工智能/大模型与应用/AI安全对齐) 与 [红队评测](/docs/人工智能/大模型与应用/AI评测红队与越狱防御) 重点审视的对象——记忆里若被注入恶意内容，会被长期复用。

## 示例

一个最小「带反思的 agent」循环骨架（伪代码）：

```python
memory = VectorStore()          # 情景/语义记忆
task = "订一张周五北京到上海的高铁票，并安排接站"

for attempt in range(max_retries):
    # 1. 检索相关记忆（过去的类似任务、踩过的坑）
    recollection = memory.search(task, k=5)
    # 2. 规划 + 行动（ReAct 风格，可调用 MCP 工具）
    trajectory = run_react_agent(task, context=recollection)
    result = trajectory.outcome
    if result.success:
        break
    # 3. 反思：让模型总结失败原因，写入记忆供下次用
    reflection = llm.reflect(trajectory)
    memory.add(f"任务失败反思: {reflection}")

# 成功后也沉淀经验
memory.add(f"成功模式: {task} -> {trajectory.summary}")
```

要点：**失败也要写回记忆**，否则 agent 永远在重复同一个错。

## 易错点

- **记忆无限增长**：不压缩、不淘汰的旧记忆会撑爆上下文、稀释检索相关性。需要摘要、重要性打分、定期归档。
- **检索噪声**：把不相关的历史硬塞进 prompt，反而降低推理质量——检索要「少而准」。
- **反思变成空话**：如果反思提示太笼统，模型只写「我应该更仔细」，不产生可执行改进。反思要绑定具体错误与对策。
- **混淆记忆与上下文**：上下文窗口里的临时状态不算「记忆」，一刷新就没；真正的记忆要落库。

## 小结

记忆与规划是把 agent 从「一次性工具调用」升级为「可持续完成任务」系统的两根支柱。记忆解决**经验复用与上下文溢出**，规划（ReAct/Reflexion/ToT）解决**多步决策与自我修正**。它与 [Agent 开发](/docs/人工智能/大模型与应用/Agent开发) 的设计理论、[MCP](/docs/人工智能/大模型与应用/MCP与工具协议) 的工具标准化共同构成现代 agent 工程的三层。下一前沿是让规划本身由 [强化学习](/docs/人工智能/机器学习/强化学习进阶) 或 [过程奖励模型](/docs/人工智能/大模型与应用/过程奖励模型与可扩展监督) 来优化（agentic RL）。

## 核心概念

### 虚拟化的本质：陷入与模拟

虚拟化要解决的核心矛盾是：**客户机（guest）以为自己独占硬件，但宿主机（host）必须能拦截并模拟特权操作**。经典做法是「特权级回收」——guest 的特权指令会**陷入（trap）** 到 Hypervisor，由后者模拟执行后再返回。难点在于某些架构（如早期 x86）存在「沉默特权指令」不会陷入，催生了两种路线：二进制翻译（全虚拟化）与修改 guest（半虚拟化/para-virtualization）。

### Hypervisor 的两种类型

- **Type-1（裸金属）**：Hypervisor 直接跑在硬件上，guest OS 运行其上。代表：VMware ESXi、Xen（Dom0 模式）、Microsoft Hyper-V、KVM（以内核模块形式存在于 Linux）。性能与隔离性最好，是云数据中心的底座。
- **Type-2（宿主型）**：Hypervisor 作为一个普通应用跑在已有 OS 上。代表：VirtualBox、VMware Workstation、Parallels。便于桌面开发测试，但多一层 host OS 开销。

### 容器：操作系统级虚拟化

容器不虚拟硬件，而是共享同一个内核，只隔离**用户空间视角**（PID、挂载、网络、UTS 命名空间）。它通过 **cgroups** 限制资源、**namespace** 隔离视图。因此容器：

- 启动秒级、镜像轻量（共享内核，无需打包 OS）；
- 隔离弱于虚拟机（内核逃逸风险、无法跑不同内核/OS）。

这就是 Docker 与 Kubernetes 的底层机制——与 [容器化与 Docker](/docs/软件工程/工程实践/容器化与Docker) 的工程实践一脉相承。

### 硬件辅助虚拟化

现代 CPU 提供专门扩展，让虚拟化近乎「零成本」：

- **Intel VT-x / AMD-V**：引入 root/non-root 两种模式，guest 的特权指令直接陷入 VMX，无需二进制翻译。
- **EPT（扩展页表）/ RVI**：让 MMU 硬件做「guest 物理地址 → 主机物理地址」的二级转换，避免影子页表的开销。
- **IOMMU（VT-d / AMD-Vi）**：把设备 DMA 安全地重定向给指定虚拟机，支撑设备直通（PCIe passthrough）。

### 内存与设备虚拟化

- **内存虚拟化**：guest 看到的是「客户机物理地址（GPA）」，需映射到「主机物理地址（HPA）」。软件方案（影子页表）复杂且慢，硬件 EPT 让 TLB 缺失时由 MMU 自动走两级页表。
- **设备虚拟化**：模拟设备（如 virtio 半虚拟网卡）、设备直通（IOMMU 把真实设备交给 guest）、SR-IOV（把物理网卡切成多个虚拟功能）。virtio 是主流的半虚拟 I/O 框架，显著优于纯软件模拟。

### 本章主线

虚拟化 = 「让多个工作负载安全地共享一台机器」。路线有两条：要么虚拟硬件（Hypervisor，强隔离、重），要么只虚拟用户空间（容器，轻量、快）。硬件辅助（VT-x/EPT/IOMMU）把前者的成本压到极低，于是「高密度 + 强隔离」的云才成为可能。

## 示例

### 示例 1：KVM 的架构位置

KVM 是 Linux 内核模块，把 Linux 本身变成 Type-1 Hypervisor：每个虚拟机是一个普通进程（`qemu-kvm`），其 vCPU 对应线程，由宿主机调度器调度。guest 执行特权指令时由 VT-x 陷入，KVM 在内核态模拟。用户态的 QEMU 负责设备模拟与 I/O。

### 示例 2：容器 vs 虚拟机对比

| 维度 | 虚拟机 | 容器 |
|------|--------|------|
| 隔离边界 | 硬件/内核级 | 用户空间命名空间 |
| 启动时间 | 秒~分钟 | 毫秒~秒 |
| 镜像大小 | GB（含 OS） | MB（仅应用+依赖） |
| 内核 | 各自独立 | 共享宿主内核 |
| 典型用途 | 强隔离多租户、异构 OS | 微服务、CI、弹性扩容 |

### 示例 3：EPT 二级地址转换

没有 EPT 时，guest 访问内存要经「guest 页表 + 影子页表」两次软件查表；有 EPT 后，硬件 TLB 缺失时自动遍历 GPA→HPA 的 EPT，guest 页表仍是普通页表，开销大幅下降。

## 易错点

- **容器不是轻量虚拟机**：容器共享内核，无法运行不同 OS/内核；二者隔离层级根本不同。
- **混淆 Type-1/Type-2**：KVM 常被人误认为 Type-2，其实它以内核模块让 Linux 成为裸金属 Hypervisor，属 Type-1。
- **以为虚拟化一定慢**：硬件辅助（VT-x/EPT）已让大多数工作负载的虚拟化开销 < 5%。
- **忽视设备直通的安全前提**：PCIe passthrough 必须配合 IOMMU，否则 guest 的 DMA 可越权访问宿主内存。

## 小结

虚拟化通过「陷入-模拟」把物理资源抽象成可隔离分配的逻辑资源。Hypervisor（Type-1 裸金属 / Type-2 宿主型）提供强隔离的硬件虚拟化，容器提供轻量的操作系统级虚拟化；硬件辅助（VT-x、EPT、IOMMU）让前者近乎零成本，使云计算与云原生得以成立。理解虚拟化，就理解了现代数据中心与弹性基础设施的底层逻辑。

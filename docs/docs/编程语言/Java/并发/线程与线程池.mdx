# 线程与线程池

并发是 Java 的强项。本篇讲线程的创建、状态，以及生产环境必备的**线程池**。

## 学习目标

- 用 `Thread` / `Runnable` 创建线程，说清 6 种线程状态；
- 解释为什么生产环境要用线程池而非 `new Thread()`；
- 讲清 `ThreadPoolExecutor` 的提交行为与拒绝策略。

## 前置知识

- 已了解 [类加载机制](../../JVM/类加载机制)（类初始化是线程安全的）；
- 想对比并发模型可看 [Go 的 goroutine 与 channel](../../../Go/并发模型/goroutine与channel)。

## 1. 创建线程

```java
// 方式一：继承 Thread
new Thread(() -> System.out.println("hi")).start();

// 方式二：实现 Runnable（更推荐，便于组合）
Runnable task = () -> System.out.println("running");
new Thread(task).start();
```

Java 21+ 还提供**虚拟线程（Virtual Thread）**：`Thread.startVirtualThread(() -> {...})`，由 JVM 调度、开销极低，适合海量 IO 并发。

## 2. 线程状态

```
NEW → RUNNABLE → BLOCKED/WAITING/TIMED_WAITING → TERMINATED
```

- `sleep()`：休眠，不释放锁。
- `wait()/notify()`：在 `synchronized` 块内，释放锁等待/唤醒。
- `join()`：等待目标线程结束。

## 3. 为什么需要线程池

每来一个任务 `new Thread()` 代价高：线程创建/销毁开销、无节制创建会耗尽资源。线程池**复用线程、控制并发数**。

```java
ExecutorService pool = Executors.newFixedThreadPool(4);  // 4 个工作线程
for (int i = 0; i < 10; i++) {
    int id = i;
    pool.submit(() -> System.out.println("任务 " + id));
}
pool.shutdown();   // 不再接收新任务，等待已提交完成
```

## 4. ThreadPoolExecutor 核心参数

```java
new ThreadPoolExecutor(
    corePoolSize,        // 核心线程数（常驻）
    maximumPoolSize,     // 最大线程数
    keepAliveTime,       // 空闲线程存活时间
    TimeUnit.SECONDS,
    new LinkedBlockingQueue<>()  // 任务队列
);
```

提交任务时的行为：

1. 核心线程未满 → 创建新线程；
2. 核心满 → 入队；
3. 队列满 → 创建非核心线程至 maximum；
4. 都满 → 触发**拒绝策略**（`AbortPolicy` 抛异常等）。

## 5. 最佳实践

- 不用 `Executors.newCachedThreadPool()`（可能无限线程），显式构造 `ThreadPoolExecutor`。
- CPU 密集：线程数 ≈ 核数；IO 密集：可更大（如核数 × 2）。
- 业务用 `submit()` 拿 `Future` 取结果/异常。

## 易错点

- `submit()` 的任务若抛异常，不会立刻抛出，而是藏在 `Future.get()` 里——不调用 `get()` 可能吞掉错误。
- `shutdown()` 不等任务结束、`shutdownNow()` 尝试中断；要等完成用 `awaitTermination`。
- 在 `synchronized` 块内调用 `Thread.sleep()` 不会释放锁，容易拖慢并发。

## 练习

1. 用固定线程池并发下载/计算 100 个任务，统计总耗时；
2. 自定义 `RejectedExecutionHandler`，观察队列满时的拒绝行为。

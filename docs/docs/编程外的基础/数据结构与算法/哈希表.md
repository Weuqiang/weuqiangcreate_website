# 哈希表

哈希表（Hash Table）是现代编程里最常用、也最「神奇」的结构：它让「按 key 找 value」的平均代价从 $O(n)$ 降到 **$O(1)$**。你每天都在用——Python 的 `dict`、Java 的 `HashMap`、JS 的 `Object` 底层都是它。

## 学习目标

- 说清哈希表为什么能 $O(1)$ 查找。
- 理解哈希冲突及两种主流解决办法。
- 能用哈希表把「两数之和」从 $O(n^2)$ 优化到 $O(n)$。

## 核心概念

### 1. 哈希函数

把任意 key（字符串、对象等）映射成一个整数下标：`index = hash(key) % 容量`。理想情况下不同 key 落到不同下标，于是「找 key」变成「直接算下标」——一步到位 $O(1)$。

### 2. 冲突与解决

不同 key 算出同一下标叫**冲突**，无法完全避免。两种主流解法：

- **链地址法（拉链）**：同一下标挂一条链表，存所有冲突元素（查找时再在链里比 key）。Python `dict` 即用此法变体。
- **开放寻址法**：冲突了就按规则找下一个空位（线性探测、二次探测）。

### 3. 为什么平均 $O(1)$、最坏 $O(n)$

只要哈希函数分散得好、装载因子（元素数/容量）不过高，冲突很少，查找接近一步。但若所有 key 都冲突（最坏/恶意哈希攻击），退化成链表查找 $O(n)$。因此好的哈希函数 + 动态扩容很关键。

## 最小可运行示例

Python 直接用语义化的 `dict`：

```python
d = {}
d["apple"] = 3
d["banana"] = 5
print(d["apple"])        # O(1) -> 3
print("apple" in d)      # 成员判断 O(1)
```

应用一：去重

```python
def dedup(a):
    return list(dict.fromkeys(a))   # 保持顺序去重
print(dedup([1,2,2,3,1]))          # [1, 2, 3]
```

应用二：计数

```python
from collections import Counter
print(Counter("abracadabra")["a"])  # 5
```

应用三：两数之和（经典面试题）

```python
def two_sum(nums, target):
    seen = {}                       # 值 -> 下标
    for i, x in enumerate(nums):
        if target - x in seen:      # 需要的前半部分已出现过？
            return [seen[target - x], i]
        seen[x] = i
    return None

print(two_sum([2,7,11,15], 9))      # [0, 1]
```

> 暴力解要两层循环 $O(n^2)$；哈希表把「前半部分见过的数」记下来，一次遍历 $O(n)$。

## 易错点

1. **把可变对象当 key**：列表、`set` 等不可哈希（Python 会抛 `TypeError`）。用元组或字符串做 key。
2. **忘了哈希冲突**：别假设「下标直接命中」，比较时务必再比 key 是否真的相等。
3. **装载因子过高**：元素太多会频繁冲突、变慢；`dict` 会自动扩容，自己实现时要注意。
4. **误用为有序**：Python 3.7+ 的 `dict` 保**插入**序，但不是按 key 大小排序；需要排序请用 `sorted(d)`。

## 练习

1. 用哈希表判断两个字符串是否为「异位词」（字母相同排列不同）。
2. 找出数组中出现次数超过一半的元素（哈希计数或摩尔投票）。
3. 实现一个简单的 `HashSet`，支持 `add` / `contains` / `remove`（底层用数组+链表）。

## 小结

哈希表用「空间换时间」：多花数组空间，换来平均 $O(1)$ 的查找。它是去重、计数、缓存、索引的基石。下一篇 [树与二叉树](../树与二叉树) 会回到层次结构。

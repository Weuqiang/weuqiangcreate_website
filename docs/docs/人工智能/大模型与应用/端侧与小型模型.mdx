## 核心概念

### 为什么「小」重新重要

过去两年模型越做越大，但落地时发现：**很多场景并不需要千亿参数**。小模型（通常指 ≤ 3B，甚至 ≤ 1B 参数）的价值在于：

1. **延迟与成本**：在手机/浏览器/嵌入式上本地跑，省去往返云端的几百毫秒与每 token 费用。
2. **隐私与离线**：数据不出设备，且无网络也能用（车机、医疗边缘、工控）。
3. **可控与可定制**：小模型训练/微调成本低，企业可私有化定制领域模型。

> 区分：**[推理加速](/docs/人工智能/大模型与应用/推理加速)** 是把「大模型」变快（量化/KV cache/蒸馏）；**端侧小模型**是「本就用一个小模型」，目标设备是 NPU/手机而非 GPU 服务器。两者互补，但问题域不同。

### 小模型从哪来：蒸馏与专门训练

小模型不是「把大模型砍小」那么简单，主流两条路：

- **知识蒸馏（Knowledge Distillation）**：用大模型（teacher）的输出（软标签/logits）训练小模型（student），让小模型学到「老师的判断分布」而非仅硬标签。这是 [推理加速](/docs/人工智能/大模型与应用/推理加速) 里提到的蒸馏思路在「造小模型」上的专门应用。
- **从头训小模型 + 数据配方**：如 Phi 系列强调「用高质量教科书级数据 + 合成数据」训练小模型，证明数据质量可弥补参数少。这与 [合成数据](/docs/人工智能/大模型与应用/合成数据与数据工程) 思路一致。

### 主流小模型谱系（举例）

- **Phi-3 / Phi-4**（微软）：强调教科书质量数据，3.8B 以下表现突出。
- **Gemma 2/3 2B/4B**（Google）：开放权重，端侧友好。
- **Qwen2.5 0.5B/1.5B/3B**（阿里）：中文与多语言均衡，生态完善。
- **SmolLM2**（Hugging Face）：极小的研究友好模型。
- **MiniCPM**（面壁）：主打端侧多模态小模型。
- **Llama 3.2 1B/3B**：Meta 的轻量开放模型。

### 端侧推理引擎与约束

把小模型真正跑在设备上，靠的是**端侧推理引擎**：

- **llama.cpp / GGUF**：用量化权重（Q4/Q5）在 CPU/端侧 GPU 上高效推理，是桌面与边缘最普及的方案。
- **MNN / NCNN**：面向移动端的轻量推理框架（阿里/腾讯）。
- **ONNX Runtime Mobile / ExecuTorch / Core ML / TensorRT-LLM**：各平台（Windows/Linux 移动/Apple/NVIDIA）的原生加速路径。

端侧的核心约束不是「算力够不够」，而是**内存带宽与功耗**：

- 模型权重要常驻内存，推理速度受「每秒能从内存搬多少权重」限制（memory-bound），因此 **int4 量化**几乎必备。
- NPU 擅长低精度矩阵乘，但要量化为其支持的格式；不支持的算子会回退 CPU，反而更慢。
- 电池与发热限制持续推理时长，需做批处理与唤醒策略。

## 示例

一个「把小模型量化到 4bit 并用 llama.cpp 跑」的最小流程（伪代码/命令）：

```bash
# 1. 把 HuggingFace 模型转成 GGUF 并量化到 Q4（只需一次）
python convert_hf_to_gguf.py Qwen2.5-1.5B --out qwen.gguf
./llama-quantize qwen.gguf qwen-q4.gguf Q4_K_M

# 2. 在端侧（甚至树莓派/手机）直接跑，无需 GPU 服务器
./llama-cli -m qwen-q4.gguf -p "用一句话解释什么是内存带宽瓶颈"
```

要点：`Q4_K_M` 把 1.5B 模型压到约 1GB 内存占用，使其能在手机或树莓派上实时跑——这正是「端侧小模型」的落脚点。

## 易错点

- **把「本地部署」等同于「端侧」**：[本地部署](/docs/人工智能/大模型与应用/本地部署) 的 ollama/vllm 多在带 GPU 的机器上，不等于手机 NPU 部署；端侧要额外考虑量化格式与算子支持。
- **忽视内存带宽瓶颈**：只看参数量忽略权重搬运成本，实际推理并不快。
- **量化过度损精度**：Q2/Q3 虽更小，但小模型本就容量有限，过低量化会崩；小模型通常 Q4/Q5 是甜点。
- **套用大模型评测**：小模型定位是「够用就好」，用大模型基准硬比不公平；应按端侧任务（延迟、内存、准确率权衡）评估。

## 小结

端侧与小型模型是 2024–2026 年落地最务实的方向：用**蒸馏/高质量数据**造小模型，用 **llama.cpp/GGUF、MNN、Core ML** 等引擎部署到 NPU/手机，靠 **int4 量化**对抗内存带宽瓶颈。它与 [推理加速](/docs/人工智能/大模型与应用/推理加速)、[模型微调](/docs/人工智能/大模型与应用/模型微调) 的量化、[本地部署](/docs/人工智能/大模型与应用/本地部署) 构成「模型变小、部署下沉」的完整技术链，但问题域明确区别于「给云端大模型提速」。

# 均摊分析

Python 的 `list.append` 常被说成 $O(1)$，但它偶尔需要**扩容**——申请一块更大的内存、把所有元素搬过去，那一次显然是 $O(n)$。既然存在 $O(n)$ 的情况，凭什么说它是 $O(1)$？

答案是**均摊分析（Amortized Analysis）**：它衡量的不是单次操作的最坏代价，而是**一长串操作的平均代价**。

## 学习目标

- 说清均摊复杂度与平均复杂度的本质区别。
- 掌握三种分析方法：聚合法、记账法、势能法。
- 完整推导动态数组扩容为什么是均摊 $O(1)$，并解释为什么必须**倍增**而不能**定量增长**。
- 认出实践中的均摊场景：动态数组、哈希表扩容、并查集、栈的批量弹出。

## 核心直觉

### 均摊 ≠ 平均

这是最容易混淆的一点：

| 概念 | 含义 | 是否依赖概率 | 保证强度 |
|---|---|---|---|
| **最坏复杂度** | 单次操作最差能有多慢 | 否 | 最强 |
| **平均复杂度** | 在某种输入分布假设下的期望 | **是** | 弱（换个分布就不成立） |
| **均摊复杂度** | $n$ 次操作总代价 $/\ n$ | **否** | 强（对任意操作序列都成立） |

关键区别：**平均复杂度需要假设输入是随机的**（比如快排的 $O(n\log n)$ 平均复杂度，假设枢轴随机），而**均摊复杂度是确定性的保证**——无论你怎么构造操作序列，$n$ 次操作的总代价都不会超过某个界。

所以「`append` 均摊 $O(1)$」比「快排平均 $O(n\log n)$」是更强的承诺：前者你**没法构造出反例**，后者可以（构造特定输入让快排退化）。

### 核心思想：贵的操作很少见，且它「攒够了本钱」

动态数组扩容的直觉：每次扩容代价 $O(n)$，但扩容后容量翻倍，**要再走 $n$ 步才会触发下一次扩容**。也就是说，这次昂贵的 $O(n)$ 代价，是由前面 $n$ 次便宜的操作「攒」出来的。把它平摊到那 $n$ 次操作上，每次只多花 $O(1)$。

## 最小示例

### 案例一：动态数组扩容（聚合法）

**聚合法**：直接算 $n$ 次操作的总代价 $T(n)$，均摊代价就是 $T(n)/n$。

```python
class DynamicArray:
    def __init__(self):
        self.data = [None] * 1           # 初始容量 1
        self.size = 0
        self.capacity = 1
        self.total_copies = 0            # 统计总搬移次数

    def append(self, x):
        if self.size == self.capacity:   # 满了，扩容
            self._resize(2 * self.capacity)
        self.data[self.size] = x
        self.size += 1

    def _resize(self, new_cap):
        new_data = [None] * new_cap
        for i in range(self.size):       # ← 这里是 O(n) 的搬移
            new_data[i] = self.data[i]
            self.total_copies += 1
        self.data = new_data
        self.capacity = new_cap


arr = DynamicArray()
for i in range(1024):
    arr.append(i)

print(f"插入 {arr.size} 个元素，总搬移次数 = {arr.total_copies}")
print(f"平均每次插入的搬移 = {arr.total_copies / arr.size:.3f}")
# 插入 1024 个元素，总搬移次数 = 1023
# 平均每次插入的搬移 = 0.999
```

**手算推导**。插入 $n$ 个元素（设 $n = 2^k$），扩容发生在容量为 $1, 2, 4, 8, \dots, n/2$ 时，每次搬移的元素数等于当时的容量：

$$
\text{总搬移} = 1 + 2 + 4 + \cdots + \frac{n}{2} = \sum_{i=0}^{k-1} 2^i = 2^k - 1 = n - 1
$$

于是：

$$
T(n) = \underbrace{n}_{\text{n 次写入}} + \underbrace{(n-1)}_{\text{搬移}} < 2n \quad\Longrightarrow\quad \text{均摊代价} = \frac{T(n)}{n} < 2 = O(1)
$$

程序输出 `总搬移次数 = 1023 = 1024 - 1`，与推导完全一致。

**关键：为什么必须倍增？** 如果每次只扩容固定的 $c$ 个位置：

| 扩容策略 | 扩容次数 | 总搬移量 | 均摊代价 |
|---|---|---|---|
| 容量 $\times 2$ | $\log_2 n$ | $n - 1$ | $O(1)$ ✅ |
| 容量 $\times 1.5$ | $\log_{1.5} n$ | $\approx 2n$ | $O(1)$ ✅ |
| 容量 $+ c$（固定增量） | $n/c$ | $c(1+2+\cdots+\frac{n}{c}) \approx \frac{n^2}{2c}$ | $O(n)$ ❌ |

固定增量下总搬移是 $O(n^2)$，均摊每次 $O(n)$——**彻底失去 $O(1)$ 的性质**。这就是为什么所有语言的动态数组（C++ `vector`、Java `ArrayList`、Python `list`、Go `slice`）都用**乘法增长**而非加法增长。

顺带一提，CPython 的 `list` 实际增长因子约为 1.125（`newsize + newsize >> 3 + 6`），比 2 更省内存但扩容更频繁——依然是乘法增长，所以依然是均摊 $O(1)$。

### 案例二：记账法（会计方法）

**记账法**：给每次操作预收一笔「手续费」，便宜的操作多收一点存起来，昂贵的操作用存款支付。只要**账户余额永不为负**，预收的费率就是均摊上界。

对动态数组，我们给每次 `append` 收 **3 个代价单位**：

- 1 个单位：支付本次写入元素的实际代价。
- 1 个单位：存起来，将来搬移**自己**时用。
- 1 个单位：存起来，将来搬移**前半段里对应的那个老元素**时用。

验证：容量从 $m$ 扩到 $2m$ 时，需要搬移 $m$ 个元素。而在容量从 $m/2$ 涨到 $m$ 的过程中，新插入了 $m/2$ 个元素，每个存了 2 个单位，共 $m$ 个单位——**恰好够支付这 $m$ 次搬移**。余额始终非负，故均摊代价 $\le 3 = O(1)$。

```python
def accounting_check(n):
    """模拟记账：验证余额永不为负"""
    balance, capacity, size = 0, 1, 0
    min_balance = 0
    for _ in range(n):
        balance += 3                      # 预收 3 个单位
        if size == capacity:
            balance -= size               # 支付搬移代价
            capacity *= 2
        balance -= 1                      # 支付写入代价
        size += 1
        min_balance = min(min_balance, balance)
    return balance, min_balance


final, lowest = accounting_check(1024)
print(f"最终余额 = {final}，历史最低余额 = {lowest}")
# 最终余额 = 1025，历史最低余额 = 0   ← 从未为负，证明 3 单位足够
```

### 案例三：势能法

**势能法**：定义一个「势能函数」$\Phi$ 把数据结构的状态映射成一个非负数，均摊代价定义为：

$$
\hat{c_i} = c_i + \Phi(D_i) - \Phi(D_{i-1})
$$

其中 $c_i$ 是第 $i$ 次操作的实际代价。$n$ 次操作的均摊总代价：

$$
\sum_{i=1}^{n}\hat{c_i} = \sum_{i=1}^{n} c_i + \Phi(D_n) - \Phi(D_0)
$$

只要 $\Phi(D_n) \ge \Phi(D_0)$（通常令 $\Phi(D_0) = 0$ 且 $\Phi \ge 0$），均摊总代价就是实际总代价的上界。

对动态数组，取 $\Phi = 2 \cdot size - capacity$：

- **不扩容时**：$c_i = 1$，$size$ 加 1 使 $\Phi$ 增加 2，故 $\hat{c_i} = 1 + 2 = 3$。
- **扩容时**：设扩容前 $size = capacity = m$，实际代价 $c_i = m + 1$（搬移 $m$ 个 + 写入 1 个）。扩容后 $size = m+1$，$capacity = 2m$，所以

  $$
  \Phi_{\text{后}} - \Phi_{\text{前}} = [2(m+1) - 2m] - [2m - m] = 2 - m
  $$

  于是 $\hat{c_i} = (m+1) + (2 - m) = 3$。

两种情况均摊代价都是 3，即 $O(1)$。势能法的优雅之处在于：**它把「攒本钱」这件事量化成了一个可计算的函数**。

### 案例四：并查集

带路径压缩和按秩合并的并查集，$m$ 次操作的总代价是 $O(m \cdot \alpha(n))$，其中 $\alpha$ 是**反阿克曼函数**——它增长极其缓慢，对宇宙中所有可能的 $n$，$\alpha(n) < 5$。所以工程上直接当作均摊 $O(1)$。

```python
class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n
        self.ops = 0                       # 统计指针跳转次数

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]   # 路径压缩
            x = self.parent[x]
            self.ops += 1
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        if self.rank[ra] < self.rank[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1
        return True


import random
n = 100000
d = DSU(n)
for _ in range(n):
    d.union(random.randrange(n), random.randrange(n))
for i in range(n):
    d.find(i)

print(f"{n} 个元素、约 {3*n} 次操作，总指针跳转 = {d.ops}")
print(f"平均每次操作跳转 = {d.ops / (3*n):.3f}")
# 平均每次跳转在 1 附近 —— 实测就是常数
```

单次 `find` 在极端情况下可能跳很多层，但**路径压缩会把这条路径上的所有节点直接挂到根上**，让后续操作变快。一次昂贵的操作换来了后面无数次的便宜操作——这正是均摊的精髓。

### 均摊场景总览

| 操作 | 单次最坏 | 均摊 | 原因 |
|---|---|---|---|
| 动态数组 `append` | $O(n)$ 扩容时 | $O(1)$ | 倍增，扩容间隔翻倍 |
| 动态数组 `pop` | $O(n)$ 缩容时 | $O(1)$ | 需在 1/4 时才缩容（见易错点 3） |
| 哈希表插入 | $O(n)$ rehash 时 | $O(1)$ | 同倍增逻辑 |
| 并查集 `find`/`union` | $O(\log n)$ | $O(\alpha(n)) \approx O(1)$ | 路径压缩 + 按秩合并 |
| 单调栈的一次入栈 | $O(n)$ 连续弹出 | $O(1)$ | 每个元素最多入栈/出栈各一次 |
| 二进制计数器加一 | $O(\log n)$ 全进位 | $O(1)$ | 高位翻转次数指数递减 |
| Splay 树查找 | $O(n)$ | $O(\log n)$ | 伸展操作重平衡 |

## 易错点

1. **把均摊当平均。** 均摊是**对任意操作序列**都成立的确定性保证，不依赖任何输入分布假设。说「快排均摊 $O(n\log n)$」是错的——那是平均复杂度，且可以被恶意输入攻破。

2. **在实时系统里忽视单次最坏。** 均摊 $O(1)$ 意味着**偶尔会有一次 $O(n)$ 的卡顿**。做游戏帧循环、音频处理、硬实时控制时，这一帧的卡顿可能是不可接受的。解决办法是预分配容量（`reserve`），或用「渐进式扩容」把搬移分摊到多次操作里真正执行。

3. **缩容阈值设成 1/2 会导致抖动。** 如果「元素数降到容量一半就缩容」，那么在临界点反复 `append`/`pop` 会不断触发扩容和缩容，每次都是 $O(n)$，均摊退化成 $O(n)$。正确做法是**在元素数降到容量的 1/4 时才缩容到一半**，留出滞后区间。

4. **误以为均摊分析能降低总代价。** 均摊只是一种**分析方法**，不改变程序的实际行为。总代价还是那么多，只是换了个更公平的分配视角。

5. **势能函数选错导致证明失败。** 势能函数必须满足 $\Phi \ge 0$ 且 $\Phi(D_0) = 0$（或 $\Phi(D_n) \ge \Phi(D_0)$）。选错了会得到「均摊代价为负」这种荒谬结论。

6. **忽略均摊背后的空间代价。** 倍增扩容意味着**最多浪费一半空间**。内存敏感的场景要用更小的增长因子（如 1.5 或 1.125），代价是扩容更频繁。

## 练习

1. 修改 `DynamicArray`，把增长策略改成「每次加 10」，统计插入 10000 个元素的总搬移次数，验证它约等于 $n^2 / 20 = 5 \times 10^6$，远大于倍增策略的 $n$。
2. **二进制计数器**：实现一个 $k$ 位二进制计数器的 `increment`，实际代价是本次翻转的位数。用聚合法证明 $n$ 次 `increment` 的总翻转次数 $< 2n$（提示：第 $i$ 位每 $2^i$ 次加一才翻转一次）。
3. 给动态数组加上 `pop` 与缩容，分别实现「1/2 阈值」和「1/4 阈值」两个版本，构造一个在临界点反复 append/pop 的序列，测量两者的总搬移次数差异。
4. 用势能法分析**两个栈实现的队列**：`enqueue` 压入栈 A，`dequeue` 时若栈 B 为空就把 A 全部倒进 B。取 $\Phi = |A|$（栈 A 的元素数），证明两个操作的均摊代价都是 $O(1)$。
5. 实测：对比 Python 的 `list.append` 在「预先 `[None]*n` 分配」与「逐个 append」两种方式下的耗时，量化扩容的实际开销占比。
6. 查阅 CPython 源码中 `list_resize` 的增长公式，计算插入 100 万个元素时它扩容了多少次。

## 小结

均摊分析回答的是一个很实际的问题：**当一个操作「大部分时候很快、偶尔很慢」时，我该怎么描述它的性能？** 答案是看总账而不是看单次。三种方法各有所长——聚合法最直接（算总和除以 $n$），记账法最直观（预收费用存起来），势能法最通用（能处理复杂的状态变化）。理解均摊之后，你会明白为什么所有动态数组都用倍增扩容、为什么并查集要做路径压缩、为什么缩容阈值要设成 1/4 而不是 1/2。同时也要记住它的代价：**均摊 $O(1)$ 不等于每次都 $O(1)$**，在延迟敏感的场景里这个区别可能是致命的。

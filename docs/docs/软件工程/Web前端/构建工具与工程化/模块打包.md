# 模块打包

## 学习目标

学完本章，你应该能够：

- 解释浏览器原生 ES Module 的局限，以及为何仍需打包
- 说清 entry、output、bundle 三者的关系
- 理解 tree-shaking 与 code-splitting 分别解决什么问题
- 对比 Webpack 与 Vite 的核心取向

## 核心概念

打包器把成百上千个分散的模块（JS、CSS、图片、字体）按依赖关系「卷」成少数几个浏览器能高效加载的文件。它解决的不是「能不能跑」，而是「跑得快不快、开发爽不爽」。

本章主线：

- 为什么要打包（原生 ESM 的瓶颈）
- entry / output / bundle
- tree-shaking（摇掉死代码）
- code-splitting（按需加载）
- Vite 与 Webpack 的差异

## 为什么还需要打包

浏览器原生支持 `<script type="module">` 加载 ESM，但生产环境直接用它有三痛：

1. **请求爆炸**：一个中型项目 import 链可能拉出上千个文件，每个都一次 HTTP 请求（即便 HTTP/2 也扛不住）。
2. **无法降级**：新语法（如 `??`、`top-level await`）旧浏览器不认，需要转译。
3. **缺乏优化**：没法跨模块做死代码消除、作用域提升（scope hoisting）。

打包器一次性解决：合并请求、转译语法、全局优化。

## entry / output / bundle

```javascript
// vite 的简化心智（几乎零配置）
// 入口：index.html 里 <script type="module" src="/src/main.js">
// 产物：dist/assets/*.js
```

- **entry（入口）**：从哪个文件开始顺着 import 追溯整棵依赖树。
- **output（出口）**：产物写到哪里、叫什么。
- **bundle（包）**：依赖树被合并后的产物文件，可能包含多个模块的代码。

一个入口通常对应一个或多个 bundle；多个入口（多页应用）会各自生成 bundle。

## tree-shaking：摇掉没用到的代码

tree-shaking 依赖 ES Module 的**静态结构**（import/export 在编译期可知），把从未被引用的导出从产物里删掉。

```javascript
// math.js
export function used() { return 1; }
export function unused() { return 2; } // 从未被 import

// main.js
import { used } from './math.js';
used();
```

打包后 `unused` 会被整段删除——前提是：

- 使用 ESM（`import`/`export`），而不是 CommonJS（`require`）
- 不在 `package.json` 写 `"sideEffects": false` 误伤有副作用的模块
- 生产模式（`mode: 'production'`）才开启

## code-splitting：按需加载

tree-shaking 减小「单个 bundle 的体积」，code-splitting 则是「把代码切成多块，用到再加载」。

```javascript
// 动态 import 是天然的代码分割点
button.onclick = async () => {
  const { heavyChart } = await import('./chart.js');
  heavyChart.render();
};
```

首屏只加载核心代码，图表库等重型模块等用户真正点击时再拉取。配合路由做「按页分割」是单页应用最常见的优化。

## Vite 与 Webpack 的差异

| 维度 | Webpack | Vite |
| --- | --- | --- |
| 开发态 | 启动时打包全量依赖，慢 | 原生 ESM + 按需编译，冷启动快 |
| 生产态 | 自有打包管线 | 用 Rollup 打包 |
| 心智 | 配置项多、灵活 | 约定优于配置、开箱即用 |
| 适用 | 老项目 / 复杂定制 | 新项目首选 |

Vite 在开发时**不打包**，浏览器直接请求源码模块，再由 Vite 按需转译；生产时才用 Rollup 打包。这种「开发不打包、生产才打包」的分裂策略，兼顾了开发体验与产物质量。

## 易错点

1. **把 tree-shaking 当万能**：CommonJS 模块、副作用未声明会导致摇不掉；用 `rollup-plugin-visualizer` 看产物里是否还有预期外的代码。
2. **滥用动态 import 造成请求碎片**：切得太细反而增加请求数，要平衡。
3. **混淆开发态与生产态**：Vite 开发态不打包，某些「只在打包后出问题」的 bug 不会在本地复现，务必在 `preview`/生产构建验证。
4. **public 目录与 asset 混淆**：放 `public/` 的文件不进打包管线、原样拷贝、不哈希；放 `src/` 的才会被处理与加指纹。

## 小结

打包器把分散模块聚合成高效产物：用 tree-shaking 删死代码、用 code-splitting 做按需加载。新项目优先 Vite（开发快、Rollup 生产打包），老项目或高度定制场景仍可用 Webpack。

## 练习

1. 用 Vite 起一个项目，`npm run build` 后查看 `dist/assets`，数一数生成了几个 JS 文件，并解释原因。
2. 故意在 `math.js` 写两个导出、只用一个，用打包分析工具确认未用导出被消除。
3. 把一个重型组件改为动态 `import()`，对比首屏 bundle 体积变化。

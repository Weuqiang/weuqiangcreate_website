# 中间代码与优化

语法树之后，编译器生成**中间表示（IR）**并做优化，最后产出机器码。本篇讲后半程。

## 1. 语义分析

在 AST 上补充信息：

- **符号表**：记录变量类型、作用域；
- **类型检查**：如 `int + string` 报错；
- **作用域解析**：名字绑定到正确声明。

## 2. 中间代码（IR）

为与具体硬件解耦，编译器常用三地址码等形式的中间表示：

```
t1 = x > 0
if t1 goto L1
goto L2
L1: y = x * 2
L2:
```

- 一种 IR 可被多种后端（x86/ARM）复用；
- 优化主要在 IR 上进行，与机器无关。

## 3. 常见优化

| 优化 | 说明 |
|------|------|
| 常量折叠 | `2+3` 直接算成 `5` |
| 死代码消除 | 删掉永不执行的代码 |
| 公共子表达式 | 重复计算只算一次 |
| 循环不变外提 | 循环内不变的计算移到外面 |
| 内联 | 小函数直接展开，省调用开销 |

示例：

```c
for (int i = 0; i < n; i++) {
    x = 3 * 2 + y;     // 3*2 可折叠为 6
}
```

优化后：`x = 6 + y;` 且若 `y` 循环内不变，可外提。

## 4. 代码生成

把优化后的 IR 翻译成目标机器的汇编/机器码：

- 寄存器分配（把变量塞进有限的寄存器）；
- 指令选择（IR 操作 → 具体指令）；
- 窥孔优化（局部微调指令序列）。

## 5. JIT：运行时编译

Java/JS 等用 **JIT（即时编译）**：先解释执行，再把热点代码编译成本地机器码，兼顾启动速度与峰值性能。

## 小结

编译器是"把人类意图翻译成机器指令"的精密流水线。理解它，能解释很多"为什么快/为什么慢"的现象——比如内联为何能提速、循环为何要写得好。

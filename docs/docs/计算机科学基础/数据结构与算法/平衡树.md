# 平衡树

[二叉搜索树](/docs/计算机科学基础/数据结构与算法/二叉搜索树) 有个致命弱点：按有序数据插入会退化成链表，$O(\log n)$ 变 $O(n)$。而**有序数据恰恰是现实中最常见的输入**（自增主键、时间戳、排好序的导入文件）。平衡树就是为堵住这个漏洞而生的：它在每次插入/删除后做局部调整，**强制保证树高始终是 $O(\log n)$**。

## 学习目标

- 说清「平衡」的量化定义，以及为什么平衡能保证 $h = O(\log n)$。
- 掌握 AVL 的四种失衡情形（LL / RR / LR / RL）与对应旋转。
- 记住红黑树的五条性质，并理解它为什么比 AVL 更适合写多的场景。
- 知道 `std::map`、Java `TreeMap`、数据库索引分别用了什么树，以及为什么。

## 核心直觉

「平衡」不是要求完美对称，而是要求**左右子树高度差被一个常数约束住**。不同的平衡树选择了不同的约束强度：

| 树种 | 平衡条件 | 高度上界 | 特点 |
|---|---|---|---|
| AVL 树 | 任意节点左右子树高度差 $\le 1$ | $\approx 1.44 \log_2 n$ | 最严格，查得最快，旋转最多 |
| 红黑树 | 最长路径 $\le$ 2 倍最短路径 | $\le 2 \log_2 (n+1)$ | 较宽松，增删更快 |
| B / B+ 树 | 所有叶子在同一层 | $\log_m n$（$m$ 为阶） | 多路，为磁盘 IO 优化 |

**为什么高度差受限就能保证 $O(\log n)$？** 以 AVL 为例，反过来问：高度为 $h$ 的 AVL 树**最少**要多少个节点？记为 $N(h)$。根节点占 1 个，两棵子树中一棵高 $h-1$，另一棵至少高 $h-2$（差值不能超过 1），于是：

$$
N(h) = 1 + N(h-1) + N(h-2), \quad N(0)=1,\ N(1)=2
$$

这就是斐波那契数列的变形，$N(h)$ 按 $\phi^h$（$\phi \approx 1.618$）指数增长。反解得 $h \le \log_{\phi} n \approx 1.44 \log_2 n$。也就是说，**节点数一定，高度就被死死卡住了**，绝不可能退化成链。

### 旋转：唯一的调整工具

旋转是一次**局部指针重排**，它改变树形但**保持中序序列不变**（即 BST 性质不变）。这一点至关重要——旋转不会破坏正确性，只会改善形状。

右旋（以 y 为轴向右转）：

```text
      y                x
     / \              / \
    x   C    ==>     A   y
   / \                  / \
  A   B                B   C

中序：A x B y C   （旋转前后完全一致）
```

AVL 插入后可能出现四种失衡，用「失衡节点 → 更高的孩子 → 更高的孙子」这条路径的形状命名：

| 情形 | 路径形状 | 修复方式 |
|---|---|---|
| LL | 左孩子的左子树过高 | 对失衡节点**右旋**一次 |
| RR | 右孩子的右子树过高 | 对失衡节点**左旋**一次 |
| LR | 左孩子的右子树过高 | 先对左孩子**左旋**，再对失衡节点**右旋** |
| RL | 右孩子的左子树过高 | 先对右孩子**右旋**，再对失衡节点**左旋** |

记忆口诀：**同向一次旋（反方向），异向两次旋（先把它掰成同向，再转）**。

### 红黑树：用颜色换性能

AVL 太严格了——插入一个节点可能触发旋转，删除甚至可能触发 $O(\log n)$ 次旋转。红黑树放宽了要求，用五条性质保证「最长路径不超过最短路径的 2 倍」：

1. 每个节点非红即黑。
2. 根节点是黑色。
3. 所有叶子（NIL 空节点）是黑色。
4. **红色节点的两个孩子必须都是黑色**（即不存在连续两个红节点）。
5. **从任一节点到其所有后代叶子的路径，包含相同数目的黑色节点**（黑高相同）。

性质 5 保证了「黑节点视角下」树是完美平衡的；性质 4 保证红节点最多把路径拉长一倍（红黑相间是最坏情况）。二者合起来给出 $h \le 2\log_2(n+1)$。

代价是查询略慢于 AVL（树可能高 40% 左右），但**插入/删除的旋转次数是常数级**（插入最多 2 次旋转，删除最多 3 次）。所以：**读多写少选 AVL，读写均衡选红黑树**——这正是几乎所有标准库选红黑树的原因。

## 最小示例

完整实现一棵 AVL 树的插入：

```python
class AVLNode:
    def __init__(self, val):
        self.val = val
        self.left = None
        self.right = None
        self.height = 1          # 叶子高度记为 1


def height(node):
    return node.height if node else 0


def balance_factor(node):
    """平衡因子 = 左高 - 右高；合法范围 [-1, 1]"""
    return height(node.left) - height(node.right) if node else 0


def update_height(node):
    node.height = 1 + max(height(node.left), height(node.right))


def rotate_right(y):
    """右旋：x 上位成为新根"""
    x = y.left
    y.left = x.right
    x.right = y
    update_height(y)             # 注意顺序：先更新下面的 y
    update_height(x)
    return x


def rotate_left(x):
    """左旋：y 上位成为新根"""
    y = x.right
    x.right = y.left
    y.left = x
    update_height(x)
    update_height(y)
    return y


def avl_insert(root, val):
    # 1) 和普通 BST 一样先插入
    if root is None:
        return AVLNode(val)
    if val < root.val:
        root.left = avl_insert(root.left, val)
    elif val > root.val:
        root.right = avl_insert(root.right, val)
    else:
        return root              # 去重

    # 2) 回溯时更新高度
    update_height(root)

    # 3) 检查失衡并旋转
    bf = balance_factor(root)
    if bf > 1 and val < root.left.val:            # LL
        return rotate_right(root)
    if bf < -1 and val > root.right.val:          # RR
        return rotate_left(root)
    if bf > 1 and val > root.left.val:            # LR
        root.left = rotate_left(root.left)
        return rotate_right(root)
    if bf < -1 and val < root.right.val:          # RL
        root.right = rotate_right(root.right)
        return rotate_left(root)
    return root


def inorder(node, out=None):
    if out is None:
        out = []
    if node:
        inorder(node.left, out)
        out.append(node.val)
        inorder(node.right, out)
    return out


# ---- 验算：最坏情况的有序插入 ----
root = None
for v in range(1, 16):           # 1,2,3,...,15 升序插入
    root = avl_insert(root, v)

print(inorder(root))             # [1..15]，有序性保持
print(root.val)                  # 8   ← 根自动变成中位数
print(root.height)               # 4   ← 高度只有 4！
```

**手算对比**：升序插入 1..15 共 15 个节点。

| 结构 | 树高 | 最坏查找比较次数 |
|---|---|---|
| 普通 BST | 15 | 15 次（退化成链） |
| AVL 树 | 4 | 4 次 |
| 理论下界 | $\lceil \log_2 16 \rceil = 4$ | 4 次 |

AVL 达到了理论下界。程序输出的 `height = 4`、`root.val = 8` 正好印证：树自动把中位数 8 转到了根上。

再看一次旋转的触发过程（插入 1, 2, 3）：

```text
插入 1:   1
插入 2:   1
           \
            2          平衡因子 = -1，合法
插入 3:   1
           \
            2          平衡因子(1) = 0 - 2 = -2，RR 失衡
             \
              3
左旋 →      2
           / \
          1   3        恢复平衡
```

| 操作 | AVL | 红黑树 | 退化 BST |
|---|---|---|---|
| 查找 | $O(\log n)$，常数最优 | $O(\log n)$，略慢 | $O(n)$ |
| 插入 | $O(\log n)$，旋转 $\le 2$ 次 | $O(\log n)$，旋转 $\le 2$ 次 | $O(n)$ |
| 删除 | $O(\log n)$，旋转可达 $O(\log n)$ 次 | $O(\log n)$，旋转 $\le 3$ 次 | $O(n)$ |
| 额外空间/节点 | 1 个 int 存高度 | 1 个 bit 存颜色 | 无 |
| 典型应用 | 内存数据库索引、读密集场景 | C++ `std::map`、Java `TreeMap`、Linux CFS 调度器 | — |

## 易错点

1. **旋转后忘记更新高度，或更新顺序反了。** 必须**先更新沉下去的那个节点**（旋转后位置更低的），再更新上位的新根。顺序反了会算出错误高度，导致后续判断全错。

2. **用值比较判断 LL/LR，在删除时会出错。** 上面插入版用 `val < root.left.val` 判断方向是可以的，但**删除**时没有「插入值」这个参照，必须改用子树的平衡因子来判断：`balance_factor(root.left) >= 0` 才是 LL，否则是 LR。

3. **递归回溯时不接返回值。** 旋转会改变子树根，所以 `root.left = avl_insert(root.left, val)` 里的赋值不能省。这是 AVL 实现中最高频的 bug。

4. **以为红黑树「更平衡」。** 恰恰相反，红黑树比 AVL **更不平衡**（允许 2 倍差距）。它换来的是更少的旋转次数，因此写操作更快。选型时别把两者当成「好/更好」的关系，而是「读优化/写优化」的权衡。

5. **在磁盘场景用二叉平衡树。** 数据库索引用 **B+ 树**而不是红黑树，原因是磁盘 IO 以块（4KB～16KB）为单位。二叉树每层只有一个节点，$\log_2 n$ 层就是 $\log_2 n$ 次 IO；B+ 树每个节点存几百个键，$\log_{300} n$ 层，几亿数据也只要 3～4 次 IO。**内存里用二叉，磁盘上用多路**。

6. **忽视「不需要平衡树」的可能。** 如果数据只读不写，直接用**有序数组 + 二分查找**更快更省内存；如果不需要顺序，用**哈希表**。平衡树的适用面是「既要顺序、又要频繁增删」。

## 小结

平衡树的核心思想只有一句：**用局部旋转的小代价，换取全局树高的强保证**。AVL 用高度差 $\le 1$ 的严格约束换最快查询，红黑树用颜色规则换最少旋转，B+ 树用多路分支换最少磁盘 IO——三者是同一思想在不同代价模型下的三个解。日常开发中你几乎不会手写平衡树（标准库已经给了），但理解它能让你在选型时说清楚「为什么这里用 `TreeMap` 而不是 `HashMap`」「为什么数据库索引是 B+ 树」，这才是这一页真正的价值。

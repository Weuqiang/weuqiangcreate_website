# 中间代码与优化

语法树之后，编译器生成**中间表示（IR）**并做优化，最后产出机器码。本篇讲后半程。

## 学习目标

学完本章，你应该能够：

- 说清语义分析检查什么（类型、声明、作用域）。
- 理解三地址码等线性中间表示为何便于优化。
- 列举几种常见优化（常量折叠、死代码消除、公共子表达式）。
- 知道 JIT 如何在运行时编译以获得性能。

## 前置知识

在阅读下面的内容前，建议先掌握：

- 已了解 [词法与语法分析](/docs/计算机科学基础/计算机科学导论/编译原理/词法与语法分析) 产出的 AST。
- 理解基本控制流（分支、循环）即可。
- 可参考 [指令与 CPU](/docs/计算机科学基础/计算机科学导论/组成原理/指令与CPU) 理解目标代码的执行。

## 核心概念

拿到 AST 后，编译器先做语义分析：类型对不对、变量声明了没、作用域清不清楚，任何一步报错就停下来。之后把 AST 翻译成与机器无关的中间表示（IR，如三地址码），在 IR 上做优化——这些优化只关心「计算等价地更快更小」，不关心最终跑在哪台机器。最后后端再把 IR 映射成具体指令。JIT（即时编译）则把这个流程搬到运行时：先解释执行，对热点代码再编译成本地机器码，兼顾启动速度与峰值性能。

本章主线：
- 从语义分析保证「程序有意义」
- 用中间表示承载可移植的优化
- 再到代码生成与 JIT 的运行时策略

## 1. 语义分析

在 AST 上补充信息：

- **符号表**：记录变量类型、作用域；
- **类型检查**：如 `int + string` 报错；
- **作用域解析**：名字绑定到正确声明。

## 2. 中间代码（IR）

为与具体硬件解耦，编译器常用三地址码等形式的中间表示：

```text
t1 = x > 0
if t1 goto L1
goto L2
L1: y = x * 2
L2:
```

- 一种 IR 可被多种后端（x86/ARM）复用；
- 优化主要在 IR 上进行，与机器无关。

## 3. 常见优化

| 优化 | 说明 |
|------|------|
| 常量折叠 | `2+3` 直接算成 `5` |
| 死代码消除 | 删掉永不执行的代码 |
| 公共子表达式 | 重复计算只算一次 |
| 循环不变外提 | 循环内不变的计算移到外面 |
| 内联 | 小函数直接展开，省调用开销 |

示例：

```c
for (int i = 0; i < n; i++) {
    x = 3 * 2 + y;     // 3*2 可折叠为 6
}
```

优化后：`x = 6 + y;` 且若 `y` 循环内不变，可外提。

## 4. 代码生成

把优化后的 IR 翻译成目标机器的汇编/机器码：

- 寄存器分配（把变量塞进有限的寄存器）；
- 指令选择（IR 操作 → 具体指令）；
- 窥孔优化（局部微调指令序列）。

## 5. JIT：运行时编译

Java/JS 等用 **JIT（即时编译）**：先解释执行，再把热点代码编译成本地机器码，兼顾启动速度与峰值性能。

## 小结

编译器是"把人类意图翻译成机器指令"的精密流水线。理解它，能解释很多"为什么快/为什么慢"的现象——比如内联为何能提速、循环为何要写得好。

## 易错点

- **优化在 IR 上做，与机器无关**：同一份优化可被 x86/ARM 后端复用，前端语言与后端架构因此解耦。
- **"循环不变外提"需先证明"不变"**：贸然外提带副作用的表达式会改语义，优化器靠分析保证安全。
- **JIT 不是"越快越好"**：解释启动快、JIT 峰值快，二者权衡；过度编译反而拖慢启动。

## 练习

1. 对 `for (i) x = a*b + c;` 做常量折叠与公共子表达式消除，写出优化前后的 IR。
2. 为什么 `inline` 小函数能提速？它可能带来什么副作用（如代码膨胀）？

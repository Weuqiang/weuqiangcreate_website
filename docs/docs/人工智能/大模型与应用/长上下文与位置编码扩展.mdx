## 核心概念

**长上下文**指让模型处理远超训练时窗口长度的输入（如整本书、整个代码库、数十轮对话历史）。需求很实在：RAG 召回的文档、Agent 的多步轨迹、法律/科研长文，都远超几 k token。

难点在两点：

1. **注意力复杂度**：自注意力对长度 `N` 是 `O(N²)` 的计算与显存，窗口从 8k 涨到 128k，开销翻几百倍，KV 缓存直接撑爆显存。
2. **位置编码的外推性**：Transformer 靠“位置编码”知道 token 顺序。若训练时只见过 ≤4k 的位置，直接喂 32k 的位置 id，模型会看到**训练分布之外**的坐标，效果崩坏——这就是“长度外推（length extrapolation）”问题。

**位置编码**是解题钥匙，主流演化：

- **绝对位置（sinusoidal / 可学习）**：把位置当成固定向量加进 token。简单，但外推差、相对位置关系不显式。
- **相对位置（如 T5、DeBERTa）**：编码“两个 token 的距离差”而非绝对位置，更鲁棒。
- **ALiBi**：不显式加位置向量，而是在注意力分数上**按距离加一个线性偏置**（近的加得少、远的加得多），天然具备外推性，不依赖位置嵌入。
- **RoPE（旋转位置编码）**：把“位置”表示为对 query/key 向量的**旋转**操作，使内积只依赖相对位置。它数学性质好，且“改一下旋转基数”就能做窗口扩展——当今长上下文模型（Llama、Qwen、DeepSeek）几乎都用它。

## 窗口扩展：让短训模型用上长上下文

模型训练时窗口固定（如 4k），推理时想用到 32k，怎么办？核心是**别让位置 id 超出训练见过的范围**：

- **位置插值（PI）**：把位置坐标从 `[0, L_train)` 线性压缩到 `[0, L_train)`，使 32k 的输入“看起来”仍落在 4k 范围内。简单有效，但会损失高频分辨率。
- **NTK-aware 插值**：不把所有频率一律压缩，而是**高频少压、低频多压**（改变 RoPE 的基数 `base`，而非简单缩放），保留细粒度位置信息，外推更稳。
- **YaRN**：在 NTK-aware 基础上加“注意力温度缩放”等修正，兼顾长程与短程表现，是目前的常用方案。

> 直觉：RoPE 把位置编码成旋转，改旋转基数就相当于“重新标定坐标轴”，让更长序列仍映射到模型熟悉的区间——这就是它比绝对位置更适合扩展的原因。

## 示例：RoPE 与 NTK 基数调整（概念代码）

```python
import math

def rope_base_scaled(old_base=10000.0, L_train=4096, L_target=32768):
    # NTK-aware：把 base 放大，使目标长度下等效频率分辨率不塌缩
    # 经验公式：new_base = old_base * (L_target / L_train)^(dim/(dim-2))
    dim = 128
    factor = (L_target / L_train) ** (dim / (dim - 2))
    return old_base * factor

# 推理时改用 new_base 构造旋转矩阵即可，权重不动，
# 从而让 32k 的位置坐标“折叠”回模型训练时见过的范围。
scaled = rope_base_scaled()
print(scaled)   # 远大于 10000，等价于把坐标重新标定
```

## 稀疏与线性注意力：另一条路

当上下文长到百万级，`O(N²)` 注意力即便扩展位置也扛不住。此时回到 [状态空间模型与新架构](/docs/人工智能/大模型与应用/状态空间模型与新架构) 的思路：用 Mamba/S6、线性注意力把复杂度降到 `O(N)`；或在大模型里混合**滑动窗口注意力 + 全局 token（如注意力 sink）**，只让少数关键位置参与全注意力。实践中常“长上下文用 RoPE+YaRN 撑到百 k，超长再靠稀疏/线性层”。

## 易错点

- **长上下文 ≠ 有效利用**：模型能“装下”长文，却常忽略中段信息（“lost-in-the-middle”效应）——重要事实放在开头或结尾才更可能被用到。
- **位置外推超出训练分布会退化**：不扩展直接喂远超窗口的位置 id，输出质量骤降；务必用 NTK/YaRN 等标定。
- **高频分辨率被插值稀释**：朴素位置插值把整个坐标压缩，会模糊相邻 token 的细微顺序；优先 NTK-aware/YaRN。
- **KV 缓存显存**：长上下文推理的瓶颈常在显存而非算力，需要 GQA、KV 量化、分页缓存（PagedAttention）等配合。
- **注意力仍是 `O(N²)`**：窗口扩展不改变复杂度，超长序列仍需稀疏/线性结构或分段处理。

## 练习

1. 比较绝对位置编码与 RoPE 在“推理时位置 id 超过训练最大值”时的行为差异，说明为什么 RoPE 更易扩展。
2. 用上面的 `rope_base_scaled` 公式，算 `L_target=65536` 时的 `new_base`，并解释它如何保护高频位置。
3. 设计一个“lost-in-the-middle”的最小实验：把关键事实放在长文档不同位置，比较模型抽取准确率，验证位置敏感。

## 小结

长上下文的价值在真实长文档/Agent 场景，瓶颈是注意力的 `O(N²)` 与位置编码的外推性。RoPE 因“旋转表示相对位置”而成为扩展友好型编码；NTK-aware 插值、YaRN 通过重新标定旋转基数，让短训模型平滑用上长窗口。再长的序列则需稀疏/线性注意力（Mamba 等）或混合结构兜底。但要警惕“装得下≠用得上”的中段失效。

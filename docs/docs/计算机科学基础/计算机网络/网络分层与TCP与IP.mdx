# 网络分层与 TCP/IP

计算机网络的核心是"分层"：每层只管自己的事，数据层层封装、对面层层拆开。本篇讲 TCP/IP 与可靠传输。

## 学习目标

学完本章，你应该能够：

- 说清为什么网络要分层，以及各层大致职责。
- 理解 IP 的寻址与路由（下一跳、子网）。
- 解释 TCP 如何用序列号、确认与重传保证可靠。
- 对比 TCP 与 UDP 的取舍：可靠 vs 低延迟。

## 前置知识

在阅读下面的内容前，建议先掌握：

- 了解 [进程与线程](/docs/计算机科学基础/操作系统/进程线程与调度) 中「两个程序要通信」的动机。
- 知道数据在网线里以电信号/光信号传输即可。
- 用过 ping 或浏览器访问过网站更好，但不要求。

## 核心概念

网络极其复杂，于是人们用「分层」把问题切成可管理的层：应用层管含义（HTTP），传输层管端到端（TCP/UDP），网络层管寻址与路由（IP），链路层管相邻节点怎么传比特。IP 负责把包送到哪个网络、再由路由器一跳跳转发；TCP 在 IP 之上补上「可靠」——给每个字节编号、收不到就重传、乱序就排好，代价是握手与确认带来的延迟；UDP 则相反，发了就不管，换来了低延迟，适合实时音视频。端口则让同一台机器上的不同程序各收各的包。

本章主线：
- 从分层模型拆解复杂网络
- 用 IP 理解寻址与逐跳路由
- 用 TCP/UDP 对比可靠与实时的取舍

## 1. 分层模型

```text
应用层    HTTP / DNS / FTP
传输层    TCP / UDP
网络层    IP
链路层    以太网 / WiFi
物理层    电缆 / 光纤 / 电磁波
```

- 发送：上层数据交给下层，加**头部**封装；
- 接收：下层逐层拆头，向上递交。

## 2. IP：寻址与路由

- IP 地址标识一台主机（IPv4 32 位，IPv6 128 位）；
- 路由器根据目标 IP 查表转发，跨网络把包送到目的地；
- IP 是"尽力交付"，**不保证**到达、不保证顺序。

## 3. TCP：可靠传输

TCP 在不可靠的 IP 之上提供可靠字节流：

- **三次握手**建立连接：
  ```text
  客户端 → SYN → 服务端
  客户端 ← SYN+ACK ← 服务端
  客户端 → ACK → 服务端
  ```
- **确认与重传**：收到确认才算送达，超时重发；
- **序号与窗口**：保证有序、流量控制（滑动窗口）；
- **四次挥手**断开连接。

## 4. UDP：快但不保证

- 无连接、无重传，适合实时音视频、游戏（丢包比延迟更可接受）；
- DNS 查询、视频通话常用 UDP。

| 对比 | TCP | UDP |
|------|-----|-----|
| 连接 | 有 | 无 |
| 可靠 | 是 | 否 |
| 速度 | 较慢 | 快 |
| 场景 | 网页/文件 | 实时/广播 |

## 5. 端口

IP 找到主机，**端口（0–65535）**找到主机上的进程（如 80=HTTP，443=HTTPS，22=SSH）。

## 小结

网络分层让复杂通信可分解：IP 管"送到哪"，TCP 管"可靠送到"，应用层管"干什么"。下一站：[HTTP 与网络安全](../HTTP与网络安全)。

## 易错点

- **IP 不可靠 ≠ TCP 不可靠**：IP 层"尽力交付"不保证到达；TCP 在其上用确认/重传补齐可靠性。
- **三次握手防的是"旧连接"**：为同步初始序号、避免历史脏包，并非为防攻击。
- **端口是进程的门牌，不是主机的**：同一主机不同服务用不同端口区分（如 80/443/22）。

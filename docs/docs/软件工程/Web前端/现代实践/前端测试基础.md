# 前端测试基础

## 学习目标

学完本章，你应该能够：

- 区分单元测试、组件测试、端到端测试三层
- 用 Vitest/Jest 写一个数理逻辑的单元测试
- 理解「测试金字塔」为何强调多写快测试
- 知道 Playwright 类工具解决什么

## 核心概念

测试不是「写了功能再补作业」，而是把「什么算对」固化下来，让改动不悄悄破坏旧行为。前端测试按「离用户远近」分成三层，越往下越快越多、越往上越慢越少。

本章主线：

- 测试金字塔三层
- 单元测试（Vitest / Jest）
- 组件测试
- 端到端（Playwright）

## 测试金字塔

```
        /\        E2E（少、慢、贴近真实）
       /  \      
      /----\     组件/集成（中）
     /------\    
    /--------\   单元测试（多、快、便宜）
```

- **单元测试**：测一个函数/模块，隔离依赖，毫秒级。
- **组件测试**：测一个组件在给定 props/状态/交互下的渲染与行为。
- **端到端（E2E）**：用真实浏览器跑完整用户流程（登录→下单），最慢最贵。

原则：**多写单元测试、少写 E2E**。E2E 一个挂了难定位、还常因环境抖动误报。

## 单元测试：Vitest / Jest

```javascript
// sum.js
export const sum = (a, b) => a + b;

// sum.test.js
import { describe, it, expect } from 'vitest';
import { sum } from './sum.js';

describe('sum', () => {
  it('正数相加', () => {
    expect(sum(1, 2)).toBe(3);
  });
  it('负数相加', () => {
    expect(sum(-1, -2)).toBe(-3);
  });
});
```

- `describe` 分组、`it` 单个用例、`expect(...).toBe(...)` 断言。
- Vitest 与 Vite 同源、零配置、快；Jest 生态老牌、成熟。新 Vite 项目首选 Vitest。
- 对依赖外部（API、DOM）的代码，用 mock 隔离，只测「被测单元」本身。

## 组件测试

验证组件在给定输入下的输出与交互：

```javascript
// 用 @testing-library 风格（框架无关思想）
render(<Counter />);
const btn = screen.getByRole('button');
fireEvent.click(btn);
expect(screen.getByText(/点击了 1 次/)).toBeInTheDocument();
```

重点测**行为而非实现**：点按钮后文本变没变，而不是去断言内部 state 字段。这样重构实现时测试不碎。

## 端到端：Playwright

```javascript
// 真实浏览器跑用户流程
import { test, expect } from '@playwright/test';

test('登录后能看到仪表盘', async ({ page }) => {
  await page.goto('/login');
  await page.fill('#user', 'a');
  await page.fill('#pass', 'b');
  await page.click('text=登录');
  await expect(page).toHaveURL('/dashboard');
});
```

Playwright 驱动真实 Chromium/Firefox，覆盖「跨页面、跨网络、跨浏览器」的真实路径。贵在真实、败在慢与脆，宜只覆盖最核心的少数流程。

## 易错点

1. **测试实现而非行为**：断言内部私有状态，重构即崩；应测「用户可见的结果」。
2. **E2E 比重过高**：慢、脆、难定位，应该金字塔底重。
3. **mock 过度**：把所有依赖都 mock，测试通过的代码实际集成就崩；关键路径保留真实集成测试。
4. **不测边界**：只测 happy path，空输入/超长/异常分支是 bug 温床。

## 小结

前端测试按「离用户远近」分三层：单元测试快而多、组件测试居中、E2E 慢而少。用 Vitest/Jest 写单元测试、用 Testing Library 测行为、用 Playwright 守核心流程。金字塔底重、顶部轻，是性价比最高的分配。

## 练习

1. 给一个纯函数（如日期格式化）写 3 个单元测试，含一个边界用例。
2. 用 Testing Library 为一个计数器组件写「点击后数字 +1」的行为测试。
3. 写一个 Playwright 脚本覆盖「访问首页 → 点击导航 → 到达目标页」的最小流程。

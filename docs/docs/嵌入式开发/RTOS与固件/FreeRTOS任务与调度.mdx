# FreeRTOS 任务与调度

当项目变复杂（要同时读传感器、跑通信、控电机），`while(1)` 大循环就力不从心了。**RTOS** 让你把工作拆成多个「任务」，由内核调度。

## 学习目标

学完本章，你应该能够：

- 说清 RTOS 任务与操作系统线程的对应关系
- 解释优先级抢占与时间片轮转的调度规则
- 用队列/信号量/互斥量完成任务间通信
- 知道栈溢出是 RTOS 最常见的崩溃源并会排查

## 核心概念

RTOS 内核是一个“永不返回的主循环替代品”——它按优先级在多个任务间切换 CPU，让你用“并发思维”而非“状态机轮询”组织代码。

本章主线：
- 任务创建与栈分配
- 优先级抢占与时间片
- 用队列/信号量通信
- 栈溢出与调试

## 1. 任务 = 一个独立函数

```cpp
void vBlinkTask(void *pv) {
  for (;;) {
    HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
    vTaskDelay(pdMS_TO_TICKS(500));   // 主动让出 CPU
  }
}

void vSensorTask(void *pv) {
  for (;;) {
    read_sensor();
    vTaskDelay(pdMS_TO_TICKS(100));
  }
}
```

创建并启动：

```cpp
xTaskCreate(vBlinkTask, "blink", 128, NULL, 1, NULL);
xTaskCreate(vSensorTask, "sensor", 256, NULL, 2, NULL);
vTaskStartScheduler();   // 把控制权交给内核
```

## 2. 调度：优先级 + 时间片

- 高优先级任务就绪时，抢占低优先级。
- 同优先级按时间片轮转。
- `vTaskDelay` 让任务进入阻塞态，CPU 转去跑别的任务。

## 3. 任务间通信

不要在任务间直接共享全局变量，用 RTOS 原语：

- **队列（Queue）**：任务 A 发、任务 B 收（如传感器→网络）。
- **信号量（Semaphore）**：资源互斥或事件通知。
- **互斥量（Mutex）**：保护共享资源，避免竞态。

```cpp
QueueHandle_t q = xQueueCreate(10, sizeof(int));
xQueueSend(q, &value, portMAX_DELAY);
xQueueReceive(q, &value, portMAX_DELAY);
```

## 4. 栈空间

每个任务有独立栈。栈溢出是 RTOS 最常见崩溃源——CubeMX 里给任务分配足够栈，并开启 `Stack Overflow Checking` 调试。

## 示例

一个最小可运行的 FreeRTOS 框架：两个任务 + 一个队列，传感器任务发、网络任务收，ISR 中用 `FromISR` 安全版本投递（完整可照搬）：

```cpp
#include "FreeRTOS.h"
#include "task.h"
#include "queue.h"

QueueHandle_t g_q;

void vSensorTask(void *pv) {
    int sample = 0;
    for (;;) {
        sample = read_sensor();                       // 假设已有读传感器函数
        xQueueSend(g_q, &sample, 0);                 // 非阻塞发送；队列满则丢弃
        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

void vNetTask(void *pv) {
    int val;
    for (;;) {
        if (xQueueReceive(g_q, &val, portMAX_DELAY) == pdPASS) {
            send_to_cloud(val);                       // 阻塞等待，直到有数据
        }
    }
}

int main(void) {
    HAL_Init(); SystemClock_Config();
    g_q = xQueueCreate(10, sizeof(int));             // 队列长度 10，每项 4 字节
    xTaskCreate(vSensorTask, "sensor", 256, NULL, 2, NULL);
    xTaskCreate(vNetTask,    "net",    256, NULL, 1, NULL);
    vTaskStartScheduler();                            // 交权给内核，永不返回
    for (;;);                                         // 兜底：调度器启动失败才到这里
}
```

> 注意：ISR 里投递要用 `xQueueSendFromISR`，并传给 `pxHigherPriorityTaskWoken` 决定是否调 `portYIELD_FROM_ISR`，否则会死机。

## 小结

FreeRTOS 用任务抽象并发，调度由优先级加时间片决定；任务间通信走队列、信号量、互斥量，绝不直接共享全局变量；栈溢出是最常见崩溃，需开启 Stack Overflow Check。

## 易错点

- **共享变量别裸用**：多任务并发读写全局变量会竞态，必须用队列/互斥量。
- **中断里别调阻塞 API**：`xQueueSend` 带 `portMAX_DELAY` 等在 ISR 里会死机，要用 `...FromISR` 版本。
- **栈给太小必崩**：栈溢出会踩坏相邻内存，现象诡异；开 Stack Overflow Check 及早发现。

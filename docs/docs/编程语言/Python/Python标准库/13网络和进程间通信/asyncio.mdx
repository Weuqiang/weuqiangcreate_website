## 学习目标

- 说清 asyncio 解决什么问题：单线程内用「协作式多任务」并发处理大量 IO 等待
- 用 `async` / `await` 写出可读的并发代码，掌握 `asyncio.run()` 启动协程
- 用 `asyncio.gather` / `create_task` 并发运行多个协程
- 避开三大坑：阻塞事件循环、忘记 `await`、在协程里调用同步阻塞函数

## 核心直觉

CPU 执行一条指令极快，但「等网络响应 / 等磁盘 / 等数据库」动辄几十毫秒——这段时间 CPU 其实在空转。多线程靠操作系统切换来利用等待期，但线程切换有开销，且受 GIL 限制无法真正并行 CPU 工作。

asyncio 走另一条路：**单线程 + 事件循环**。协程用 `await` 主动让出控制权：当协程遇到 `await`，它把手里的控制权交还事件循环，循环转去执行别的协程；等 IO 数据到了，再回来接着跑。全程没有线程切换，却能让成千上万个 IO 等待「重叠」起来。

> 一句话：`asyncio` 适合 **IO 密集型**（网络、磁盘、爬虫、微服务调用）；**不适合 CPU 密集型**（那该用 `multiprocessing` 多进程）。

## 最小示例

现代写法用 `asyncio.run()` 启动，不要再用手动 `get_event_loop` + `run_forever`：

```python showLineNumbers
import asyncio

async def say(delay, msg):
    await asyncio.sleep(delay)   # 模拟 IO 等待，主动让出控制权
    print(msg)

async def main():
    # 顺序执行：总耗时 ≈ 1 + 2 = 3 秒
    await say(1, "hello")
    await say(2, "world")

# asyncio.run 负责创建事件循环、运行 main、收尾关闭
asyncio.run(main())
```

把两个 `say` 并发起来，总耗时降到约 2 秒（取最长那个）：

```python
async def main():
    # gather 并发运行多个协程，等全部完成
    await asyncio.gather(
        say(1, "hello"),
        say(2, "world"),
    )
```

## 任务与并发控制

`gather` 适合「一次性并发一批」。`create_task` 把协程包装成 Task 立即排入循环，便于边产生边调度：

```python
async def main():
    task1 = asyncio.create_task(say(1, "a"))
    task2 = asyncio.create_task(say(2, "b"))
    # 此处 main 可先做别的事
    await task1
    await task2
```

限制并发数（避免一次性打爆对端）可用信号量：

```python
sem = asyncio.Semaphore(10)  # 最多 10 个并发

async def fetch(url):
    async with sem:
        return await do_request(url)
```

## 易错点

- **阻塞事件循环**：在协程里调用 `time.sleep(3)`、`requests.get()`、`open()` 这类同步阻塞函数，会卡住整个循环，所有协程一起卡。IO 一律用 `async` 版本（`asyncio.sleep` / `aiohttp` / `httpx.AsyncClient`）。
- **忘记 `await`**：`await say()` 才会真正运行；只写 `say()` 返回的是一个「还没跑的协程对象」，不执行也不报错，极难排查（lint 会警告 "coroutine never awaited"）。
- **混用线程做 CPU 重活**：重计算要丢给 `asyncio.to_thread(...)` 或 `loop.run_in_executor`，别直接在协程里算。
- **`gather` 吞异常**：某个协程抛错，`gather` 默认不会立刻中断其他任务；需要时用 `return_exceptions=True` 或外层 `try`。

## 练习

1. 用 `asyncio.gather` 并发请求 5 个 URL（用 `httpx.AsyncClient` 或 `aiohttp`），对比顺序请求耗时。
2. 写一个带 `Semaphore(3)` 的并发下载器，控制同时只下 3 个文件。
3. 故意在协程里写 `time.sleep(1)` 观察程序变慢，再换成 `await asyncio.sleep(1)` 看差别。

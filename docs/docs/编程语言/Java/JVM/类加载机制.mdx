# 类加载机制

Java 代码编译成 `.class` 字节码后，由 JVM 在运行时**按需加载**到内存。理解类加载有助于排查 `ClassNotFoundException`、`NoClassDefFoundError` 与热部署问题。

## 学习目标

- 说清"加载—链接—初始化"三步各自做什么；
- 解释双亲委派模型为何能保证核心类唯一；
- 知道何时会出现 `ClassNotFoundException` / `NoClassDefFoundError`。

## 前置知识

- 已读完 [JVM 内存模型与 GC](../JVM内存模型与GC)；
- 了解 [线程与线程池](../../并发/线程与线程池) 有助于理解"类初始化线程安全"。

## 核心概念

Java 类并非一启动就全部载入：需要时由类加载器按需加载。过程分三步——加载（找字节码、生成 Class 对象）、链接（验证/准备/解析）、初始化（执行静态块与赋值）。“双亲委派”指加载请求先委派给父加载器，父找不到才自己来，保证核心类不被篡改、避免重复加载。

## 1. 类加载过程

一个类从磁盘到可用，经历三步：

1. **加载（Loading）**：类加载器把 `.class` 读入内存，生成 `Class` 对象。
2. **链接（Linking）**：
   - 验证：字节码合法性；
   - 准备：为静态变量分配内存并赋零值（不是你写的初始值）；
   - 解析：把符号引用替换为直接引用。
3. **初始化（Initialization）**：执行类构造器 `<clinit>()`，即静态变量赋值与静态块。

## 2. 双亲委派模型

JVM 有三层类加载器，加载时**先委托父加载器**，父找不到才自己加载：

```text
Bootstrap  → 核心类库(rt.jar / modules)
  ↑
Extension  → 扩展包
  ↑
Application → 用户 classpath（默认）
```

好处：

- **避免重复加载**：父类加载过，子类不再加载。
- **安全**：用户无法伪造 `java.lang.String` 等核心类。

## 3. 示例：自定义类加载器

```java
class MyClassLoader extends ClassLoader {
    @Override
    protected Class<?> findClass(String name) throws ClassNotFoundException {
        byte[] bytes = loadBytesFromFile(name);   // 从文件/网络读取
        return defineClass(name, bytes, 0, bytes.length);
    }
}
```

> 热部署、插件化、加密字节码常借助自定义加载器实现。

## 4. 常见异常

| 异常 | 含义 |
|------|------|
| `ClassNotFoundException` | 运行时显式加载（如 `Class.forName`）找不到类 |
| `NoClassDefFoundError` | 编译在、运行不在（依赖缺失/类初始化失败） |

## 小结

类加载是“按需、分三步、双亲委派”的过程；理解它有助于排查 `ClassNotFoundException`、理解 Tomcat/Spring Boot 的类隔离。

## 易错点

- 静态变量赋值在"初始化"阶段才执行，准备阶段只是零值——依赖静态字段默认值的代码要当心。
- 同一个类被不同加载器加载，JVM 视为不同类型，`instanceof` 会返回 `false`。
- `NoClassDefFoundError` 常因某类的静态块抛异常导致初始化失败，而非单纯找不到 `.class`。

## 练习

1. 故意让某个类的静态块抛异常，观察首次使用时抛出 `NoClassDefFoundError`；
2. 用 `java -verbose:class` 启动，观察类的加载顺序。

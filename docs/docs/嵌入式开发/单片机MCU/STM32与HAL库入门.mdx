# STM32 与 HAL 库入门

STM32（ARM Cortex-M）性能远超 8 位 Arduino，是工业与产品的主流 MCU。HAL 库把寄存器操作封装成统一 API，降低上手门槛。

## 学习目标

学完本章，你应该能够：

- 用 CubeMX 配置时钟与引脚并生成代码
- 用 HAL 库操作 GPIO 与串口
- 说明 HAL 库与裸寄存器的取舍
- 跑通下载与在线调试

## 核心概念

STM32 是“外设丰富但需要先开时钟”的 MCU；HAL 库用统一 API 屏蔽芯片差异，代价是体积与效率。

本章主线：
- 开发环境与 CubeMX
- 时钟树
- HAL 外设初始化

## 1. 开发环境

- **STM32CubeMX**：图形化配置时钟、引脚、外设，自动生成初始化代码。
- **IDE**：STM32CubeIDE（基于 Eclipse）或 VS Code + 插件。

## 2. 用 CubeMX 配置一个点灯

1. 选芯片（如 STM32F103C8T6「蓝丸」）。
2. 把某个引脚设为 `GPIO_Output`。
3. 配置系统时钟（HSE→PLL）。
4. 生成代码（选 HAL 库）。

生成的 `main()` 里你只需写业务：

```cpp
while (1) {
  HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
  HAL_Delay(500);
}
```

## 3. 定时器与中断

相比 `HAL_Delay` 的「忙等」，定时器中断不阻塞主循环：

```cpp
// 在定时器溢出回调里翻转 LED
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim) {
  if (htim->Instance == TIM2) {
    HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
  }
}
```

启动：`HAL_TIM_Base_Start_IT(&htim2);`

## 4. 为什么用 HAL

- 统一 API，换芯片改动小。
- 自动处理时钟树与引脚复用。
- 代价：代码体积略大、抽象层稍慢（对多数应用无感）。

> 追求极致性能时可改用 LL 库或直接寄存器操作。

## 示例

一个典型的 STM32 HAL `main` 骨架：先初始化时钟与外设，再用定时器中断（而非 `HAL_Delay` 忙等）翻转 LED，体现"配置外设 + 处理中断"的套路：

```cpp
int main(void) {
    HAL_Init();
    SystemClock_Config();          // CubeMX 生成的时钟树配置
    MX_GPIO_Init();                // 引脚与时钟使能（含 LED 引脚）
    MX_TIM2_Init();
    HAL_TIM_Base_Start_IT(&htim2); // 启动定时器溢出中断

    while (1) {
        // 主循环不阻塞，可并行处理其它任务
    }
}

// 定时器每溢出一次（如 1s）翻转 LED，不占用 CPU 等待
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim) {
    if (htim->Instance == TIM2) {
        HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
    }
}
```

> `htim2`、`LED_GPIO_Port` 等符号由 CubeMX 生成；若 LED 不闪，先查 `__HAL_RCC_GPIOx_CLK_ENABLE()` 与定时器时钟是否已使能。

## 小结

STM32 上手先配时钟树与引脚，HAL 库让你少写寄存器；想抠性能再下沉到 LL 库或裸寄存器。

## 易错点

- **HAL_Delay 是忙等**：延时期间 CPU 空转、不调度别的任务；实时逻辑用定时器中断或 RTOS。
- **忘了开时钟/配引脚复用**：CubeMX 没勾的外设时钟不工作，现象是"代码对但没反应"。
- **HAL 封装有开销**：高频中断或极 tight 时序下，直接寄存器/LL 更可控。

## 练习

1. 用 CubeMX 配一个 TIM 定时器，让 LED 每 1 秒翻转（不靠 HAL_Delay）。
2. 配置一个外部中断（按键），按下时翻转 LED，对比"轮询"与"中断"的差别。

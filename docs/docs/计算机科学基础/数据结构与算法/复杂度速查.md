# 复杂度速查

这是一页**查询用**的对照表。写代码时想不起「`list.insert(0,x)` 到底是 $O(1)$ 还是 $O(n)$」、面试前想快速过一遍各排序的稳定性、做题时想根据数据规模倒推该用什么算法——都可以直接翻到对应表格。

每张表后面都附了一句「怎么记」，帮你从原理推导而不是死背。

## 学习目标

- 能凭记忆说出主流数据结构各操作的复杂度，并解释原因。
- 根据题目给的数据规模 $n$，反推出允许的算法复杂度上限。
- 避开语言内置操作的复杂度陷阱（尤其是 Python）。

## 核心直觉

### 按数据规模反推算法（竞赛与面试通用）

假设 1 秒内约能执行 $10^8$ 次基本操作，这张表能帮你在读完题目的第一分钟就锁定算法方向：

| 数据规模 $n$ | 可接受的复杂度 | 对应算法 |
|---|---|---|
| $n \le 10$ | $O(n!)$ | 全排列、暴力回溯 |
| $n \le 20$ | $O(2^n)$ | 子集枚举、状态压缩 DP |
| $n \le 100$ | $O(n^4)$ | 四层循环、复杂 DP |
| $n \le 500$ | $O(n^3)$ | Floyd、区间 DP、矩阵运算 |
| $n \le 5000$ | $O(n^2)$ | 朴素 DP、双层循环 |
| $n \le 10^6$ | $O(n\log n)$ | 排序、堆、分治、二分套二分 |
| $n \le 10^8$ | $O(n)$ | 单次线性扫描、双指针、前缀和 |
| $n > 10^8$ | $O(\log n)$ 或 $O(1)$ | 二分、数学公式、快速幂 |

**怎么用**：看到 $n \le 10^5$，立刻排除 $O(n^2)$（那是 $10^{10}$ 次操作，两分钟起步），往 $O(n\log n)$ 或 $O(n)$ 上想。

## 最小示例

### 表 1：数据结构操作复杂度

| 数据结构 | 访问/索引 | 查找 | 插入 | 删除 | 空间 | 备注 |
|---|---|---|---|---|---|---|
| **数组（静态）** | $O(1)$ | $O(n)$ | $O(n)$ | $O(n)$ | $O(n)$ | 索引最快，增删要搬移 |
| **动态数组** | $O(1)$ | $O(n)$ | $O(1)$ 均摊（尾部） | $O(1)$ 均摊（尾部） | $O(n)$ | 头部增删仍是 $O(n)$ |
| **有序数组** | $O(1)$ | $O(\log n)$ 二分 | $O(n)$ | $O(n)$ | $O(n)$ | 只读场景的最优解 |
| **单链表** | $O(n)$ | $O(n)$ | $O(1)$ 已知位置 | $O(1)$ 已知位置 | $O(n)$ | 「已知位置」是关键前提 |
| **双向链表** | $O(n)$ | $O(n)$ | $O(1)$ | $O(1)$ | $O(n)$ | LRU 缓存的标配 |
| **栈 / 队列** | — | $O(n)$ | $O(1)$ | $O(1)$ | $O(n)$ | 只在端点操作 |
| **哈希表** | — | $O(1)$ 平均 / $O(n)$ 最坏 | $O(1)$ 均摊 | $O(1)$ 平均 | $O(n)$ | 不保序 |
| **二叉搜索树** | — | $O(\log n)$ 平均 / $O(n)$ 最坏 | 同左 | 同左 | $O(n)$ | 有序数据会退化 |
| **平衡树（AVL/红黑）** | — | $O(\log n)$ | $O(\log n)$ | $O(\log n)$ | $O(n)$ | 最坏也有保证 |
| **二叉堆** | $O(1)$ 取最值 | $O(n)$ 任意元素 | $O(\log n)$ | $O(\log n)$ 堆顶 | $O(n)$ | 建堆是 $O(n)$ |
| **Trie** | — | $O(L)$ | $O(L)$ | $O(L)$ | $O(n \cdot L \cdot \Sigma)$ 最坏 | $L$ 为串长，与 $n$ 无关 |
| **并查集** | — | $O(\alpha(n))$ 均摊 | — | — | $O(n)$ | $\alpha(n) < 5$，视作常数 |
| **B+ 树** | — | $O(\log_m n)$ | $O(\log_m n)$ | $O(\log_m n)$ | $O(n)$ | 磁盘 IO 次数少，数据库索引 |

**怎么记**：只有三种基本策略——*连续内存*（数组：索引快、增删慢）、*指针链接*（链表：增删快、索引慢）、*散列或树*（哈希：常数但无序；树：对数但有序）。所有结构都是这三者的组合或变体。

### 表 2：排序算法

| 算法 | 最好 | 平均 | 最坏 | 空间 | 稳定 | 适用场景 |
|---|---|---|---|---|---|---|
| 冒泡排序 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | ✅ | 教学用 |
| 选择排序 | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | ❌ | 交换次数最少（$n-1$ 次） |
| 插入排序 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | ✅ | **小数组 / 近乎有序时极快** |
| 希尔排序 | $O(n\log n)$ | $O(n^{1.3})$ | $O(n^2)$ | $O(1)$ | ❌ | 插入排序的改进 |
| **归并排序** | $O(n\log n)$ | $O(n\log n)$ | $O(n\log n)$ | $O(n)$ | ✅ | 需稳定 / 外部排序 / 链表 |
| **快速排序** | $O(n\log n)$ | $O(n\log n)$ | $O(n^2)$ | $O(\log n)$ | ❌ | **通用首选**，常数最小 |
| **堆排序** | $O(n\log n)$ | $O(n\log n)$ | $O(n\log n)$ | $O(1)$ | ❌ | 内存受限 + 最坏有保证 |
| 计数排序 | $O(n+k)$ | $O(n+k)$ | $O(n+k)$ | $O(k)$ | ✅ | 整数且值域 $k$ 小 |
| 基数排序 | $O(d(n+k))$ | $O(d(n+k))$ | $O(d(n+k))$ | $O(n+k)$ | ✅ | 定长整数/字符串 |
| 桶排序 | $O(n+k)$ | $O(n+k)$ | $O(n^2)$ | $O(n+k)$ | ✅ | 数据均匀分布 |
| **Timsort**（Python/Java） | $O(n)$ | $O(n\log n)$ | $O(n\log n)$ | $O(n)$ | ✅ | 归并+插入的混合，实战最强 |

**怎么记**：基于比较的排序**下界是 $\Omega(n\log n)$**（因为 $n!$ 种排列需要 $\log_2(n!) = \Theta(n\log n)$ 次比较来区分）。想突破这个下界，只能放弃比较——计数、基数、桶排序都是靠「直接按值定位」做到线性的，代价是对数据形态有额外要求。

**稳定性怎么记**：**相邻元素才交换的排序通常稳定**（冒泡、插入、归并）；**跨距离交换的通常不稳定**（选择、快排、堆排、希尔）。

### 表 3：图算法

| 算法 | 时间 | 空间 | 前提 | 求什么 |
|---|---|---|---|---|
| DFS / BFS | $O(V+E)$ | $O(V)$ | — | 遍历、连通性、无权最短路 |
| 拓扑排序 | $O(V+E)$ | $O(V)$ | 有向无环图 | 依赖顺序 |
| Dijkstra（堆） | $O((V+E)\log V)$ | $O(V)$ | **非负权** | 单源最短路 |
| Dijkstra（朴素） | $O(V^2)$ | $O(V)$ | 非负权 | 单源最短路（稠密图更优） |
| Bellman-Ford | $O(V \cdot E)$ | $O(V)$ | 可含负权 | 单源最短路 + 负环检测 |
| Floyd-Warshall | $O(V^3)$ | $O(V^2)$ | 无负环 | **所有点对**最短路 |
| Kruskal | $O(E\log E)$ | $O(V+E)$ | 无向连通 | 最小生成树（稀疏图） |
| Prim（堆） | $O((V+E)\log V)$ | $O(V+E)$ | 无向连通 | 最小生成树 |
| Prim（朴素） | $O(V^2)$ | $O(V^2)$ | 无向连通 | 最小生成树（稠密图） |
| Tarjan 强连通分量 | $O(V+E)$ | $O(V)$ | 有向图 | SCC 缩点 |

**怎么记**：图算法的复杂度几乎都能写成「$V$ 和 $E$ 的组合 × 每次操作的代价」。用堆就多一个 $\log V$，用邻接矩阵就有 $V^2$，三重循环就是 $V^3$。

### 表 4：Python 内置操作（最容易踩坑的一张表）

| 操作 | 复杂度 | 陷阱说明 |
|---|---|---|
| `lst[i]` | $O(1)$ | — |
| `lst.append(x)` | $O(1)$ 均摊 | 扩容时单次 $O(n)$ |
| `lst.pop()` | $O(1)$ | 尾部弹出 |
| `lst.pop(0)` | **$O(n)$** | ⚠️ 头部弹出要整体前移，用 `deque` 代替 |
| `lst.insert(0, x)` | **$O(n)$** | ⚠️ 同上 |
| `x in lst` | **$O(n)$** | ⚠️ 线性扫描，改用 `set` |
| `x in set` / `x in dict` | $O(1)$ 平均 | 首选 |
| `lst.sort()` | $O(n\log n)$ | Timsort，稳定 |
| `lst[a:b]` 切片 | $O(b-a)$ | ⚠️ 会**复制**，循环里切片易成 $O(n^2)$ |
| `s1 + s2`（字符串） | $O(len_1 + len_2)$ | ⚠️ 循环里累加是 $O(n^2)$，用 `"".join()` |
| `"".join(lst)` | $O(n)$ | 拼接字符串的正确方式 |
| `dict.get/set/del` | $O(1)$ 平均 | 最坏 $O(n)$（大量哈希冲突） |
| `set` 并/交/差 | $O(len_1 + len_2)$ / $O(\min)$ | 交集按小的那个算 |
| `deque.appendleft/popleft` | $O(1)$ | 双端队列，头部操作的正解 |
| `heapq.heappush/heappop` | $O(\log n)$ | — |
| `heapq.heapify(lst)` | **$O(n)$** | 比逐个 push 的 $O(n\log n)$ 快 |
| `max/min/sum(lst)` | $O(n)$ | — |
| `bisect.insort` | $O(n)$ | ⚠️ 二分找位置只要 $O(\log n)$，但插入仍需搬移 |

下面这段代码实测三个最典型的陷阱：

```python
import time
from collections import deque

N = 50000


def timeit(label, func):
    t = time.perf_counter()
    func()
    print(f"{label:<28} {time.perf_counter() - t:>8.4f} s")


# 陷阱 1：list.pop(0) vs deque.popleft
def bad_pop():
    lst = list(range(N))
    while lst:
        lst.pop(0)              # 每次 O(n) → 总共 O(n²)


def good_pop():
    dq = deque(range(N))
    while dq:
        dq.popleft()            # 每次 O(1) → 总共 O(n)


# 陷阱 2：字符串累加 vs join
def bad_concat():
    s = ""
    for i in range(N):
        s += "x"                # 每次复制整个字符串


def good_concat():
    "".join("x" for _ in range(N))


# 陷阱 3：list 查找 vs set 查找
def bad_lookup():
    data = list(range(N))
    return sum(1 for i in range(1000) if i in data)      # O(1000 × n)


def good_lookup():
    data = set(range(N))
    return sum(1 for i in range(1000) if i in data)      # O(1000)


timeit("list.pop(0)  O(n²)", bad_pop)
timeit("deque.popleft  O(n)", good_pop)
timeit("字符串 += 累加", bad_concat)
timeit('"".join()', good_concat)
timeit("in list  O(n)", bad_lookup)
timeit("in set   O(1)", good_lookup)
```

典型输出（机器不同数值不同，但**量级差距是稳定的**）：

```text
list.pop(0)  O(n²)             0.4820 s
deque.popleft  O(n)            0.0031 s      ← 快约 150 倍
字符串 += 累加                  0.0060 s
"".join()                      0.0021 s
in list  O(n)                  0.3140 s
in set   O(1)                  0.0002 s      ← 快约 1500 倍
```

注意 CPython 对字符串 `+=` 有特殊优化（引用计数为 1 时原地扩展），所以差距没有理论上那么夸张，但换成其他实现或稍复杂的场景就会暴露 $O(n^2)$。

|---|---|---|---|
| 二分查找 | $O(\log n)$ | 有序 / 答案单调 | 查找、二分答案 |
| 双指针 / 滑动窗口 | $O(n)$ | 区间性质单调 | 最长无重复子串 |

| 动态规划 | $O(\text{状态数} \times \text{转移数})$ | 有重叠子问题 | 背包、编辑距离 |
| 贪心 | $O(n\log n)$ 排序主导 | 有贪心选择性质 | 区间调度、霍夫曼 |

| 位运算状压 | $O(2^n \cdot n)$ | $n \le 20$ 的集合问题 | 旅行商、集合覆盖 |

## 易错点

1. **把「平均」当「保证」。** 哈希表平均 $O(1)$，但在哈希冲突严重（甚至被恶意构造）时会退化到 $O(n)$。对抗性场景要用带随机种子的哈希或平衡树。

2. **忽略常数因子和缓存。** $O(n\log n)$ 的快排在实际中常比 $O(n)$ 的基数排序更快，因为后者常数大、内存访问不连续。数组遍历比链表遍历快得多，尽管两者都是 $O(n)$——**缓存命中率的影响可以达到 10 倍以上**。

3. **只算时间不算空间。** $O(n^2)$ 的 DP 表在 $n = 10^5$ 时需要 $10^{10}$ 个单元，必然 OOM。很多 DP 题的真正难点是**滚动数组把空间从 $O(n^2)$ 压到 $O(n)$**。

4. **多变量复杂度乱化简。** $O(V+E)$ 不能写成 $O(V)$；$O(n \cdot m)$ 不能写成 $O(n^2)$（除非确实 $m = n$）。

5. **误记链表插入是 $O(1)$。** 链表插入本身是 $O(1)$，但**前提是你已经拿到了那个位置的指针**。如果需要先查找位置，总代价还是 $O(n)$。

6. **认为堆能高效查找任意元素。** 堆只保证堆顶是最值，查找任意元素是 $O(n)$。需要「按值查找 + 按优先级取最值」时，用「堆 + 哈希表」的组合，或直接用平衡树。

7. **不区分「均摊」与「最坏」。** 动态数组 `append` 均摊 $O(1)$，但那一次扩容确实是 $O(n)$。实时系统要按最坏情况设计。

## 小结

复杂度速查表的价值不在于背下来，而在于**建立「这个操作大概多贵」的直觉**。真正需要记牢的只有几条主线：*连续内存索引快、指针结构增删快、哈希常数级但无序、树结构对数级且有序*；*比较排序的下界是 $n\log n$*；*图算法的复杂度就是 $V$、$E$ 和堆的 $\log$ 的组合*。至于 Python 那张陷阱表，建议直接收藏——`pop(0)`、`in list`、循环里字符串累加这三个坑，几乎每个初学者都会踩一遍。

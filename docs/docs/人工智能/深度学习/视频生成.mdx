## 核心概念

**视频生成**指由文本（T2V）或图像（I2V）条件驱动，合成一段连续、时序一致、内容合理的视频。它是图像生成的超集：在“空间”维度之外多了“时间”维度，代价是指数级增长的算力与“帧间不能乱跳”的强约束。

两条主线：

1. **从 U-Net 扩散到 DiT（Diffusion Transformer）**：早期视频扩散（如早期模型）沿用图像扩散的 U-Net；新一代（Sora、Stable Video、CogVideoX 等）改用 Transformer 做扩散去噪主干，利用注意力建模长程时空依赖，且更易扩展到高分辨率/长时长。
2. **时空潜空间压缩**：直接对像素去噪成本天文数字。主流做法是先用 3D 自编码器（VAE）把“高宽×时间”的视频压成一个紧凑的**时空潜表示**，再在潜空间里跑扩散；Sora 进一步把潜表示切成**时空 patch**（类似 ViT 把图切成 patch），用标准 Transformer 处理，天然支持可变分辨率与时长。

## 为什么视频比图像难

- **时序一致性**：相邻帧不能“物体凭空出现/消失/突变”，需要跨帧连贯。
- **运动建模**：要让画面“动得合理”（物理、遮挡、相机运动），而不只是逐帧独立生成。
- **算力爆炸**：视频 token 数 ≈ 图像 token × 帧数，注意力是二次的，长视频极易 OOM。
- **评估主观**：没有像图像那样干净的 FID 就够，视频还要看流畅度、动作合理性，常靠人工或专用视频评分模型。

## 示例：DiT 去噪的主干（概念代码）

```python
import torch

# 假设 x 是“时空潜表示”被 patchify 后的 token 序列 [B, T*H*W, C]
# t 是扩散时间步，c 是文本条件（来自文本编码器）
def dit_denoise(x_noisy, t, c, model):
    # 1) 把噪声潜 token 与文本条件融合（cross-attention 或 concat）
    # 2) 用一堆 Transformer block 做时空自注意力 + 条件注意力
    # 3) 输出对每个 token 的噪声预测 epsilon
    eps = model(x_noisy, timestep=t, cond=c)
    return eps

# 训练目标（简化）：预测加进去的噪声，与图像扩散一致
# loss = mean((eps_pred - eps_true)^2)
# 推理时从纯噪声出发，反复调用 dit_denoise 做多步去噪，
# 最后用 3D 解码器把潜表示还原成像素视频。
```

> 关键工程点：patchify 让“视频”变成“更长的 token 序列”，于是标准 Transformer 即可处理，**分辨率/时长只是 token 数量不同**，架构无需改。

## 时序一致性怎么保证

- **因果/非因果帧生成**：早期逐帧自回归（前一帧条件生成后一帧）简单但易漂移；现在多在潜空间用全序列注意力一次性建模，配合运动先验。
- **运动与光流约束**：在损失或后处理里加入时序平滑/光流一致性，抑制闪烁。
- **参考帧/条件帧**：I2V 用首帧作强条件，T2V 用粗略运动脚本或相机参数作条件，约束“往哪动”。

## 易错点

- **帧间闪烁与物体突变**：弱时序约束下，物体边缘、纹理会逐帧“抖动”或突然变形；需要强时空注意力或后处理稳帧。
- **长视频一致性崩坏**：生成 10 秒以上时，人物/场景身份容易漂移（脸变、场景跳切）；目前多靠分段+条件锚定，仍不成熟。
- **算力门槛极高**：高分辨率长视频需要集群级显存与训练数据；个人/小团队难复现 Sora 级效果。
- **评估主观且易被“首帧骗过”**：静态质量好不代表动态合理，需专门的视频质量/动作评分，不能只看单帧。
- **与“世界模型”混淆**：视频生成追求“看起来真”，[多模态世界模型](/docs/人工智能/深度学习/多模态世界模型) 追求“可交互、可预测因果关系”——前者不保证物理正确。

## 小结

视频生成是图像生成的时空扩展，核心难题在**时序一致性与算力**。主流路线用 3D VAE 做时空潜压缩、用 DiT 在 patchified 潜 token 上做扩散去噪，Sora 式 patchify 让可变分辨率/时长统一到一套 Transformer 架构。落地瓶颈仍是算力、长视频一致性与主观评估。它与“世界模型”目标不同：前者求“像”，后者求“对”。

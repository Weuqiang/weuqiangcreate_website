## 核心概念

**合成数据**指由模型（通常是更强的“教师”模型）自动生成、用于训练其他模型的数据。它不是“假数据”的贬义，而是一种被大量实证有效的训练策略。动机有三：

1. **数据墙（data wall）**：高质量人类文本/代码的增长赶不上模型吞数据的速度，公开语料几近被“洗”过一遍；继续 scaling 需要新来源。
2. **隐私与合规**：医疗、金融等敏感域不能直用真实数据，合成数据可在“保留统计特性”的同时脱敏。
3. **稀缺与可控**：推理链、数学题解、对话偏好、特定语种/方言等高质量样本稀缺，可由强模型按需“造”并打标。

**数据飞轮（data flywheel）**：用当前模型生成数据 → 严格滤波/验证 → 训练出更好的模型 → 新模型造出更好的数据 → 再训练。配合 [RLHF/过程奖励](/docs/人工智能/大模型与应用/过程奖励模型与可扩展监督)，能放大对齐收益。

本章主线：
- 为什么要合成：从数据墙到可控标注
- 怎么造：蒸馏、自我博弈、可验证领域自动打标
- 质量门控：滤波、去重、去污染
- 风险：模型崩塌与自我指涉循环

## 典型流程

```text
教师模型（更强）
   │  生成：QA 对 / 思维链 / 代码+测试 / 多轮对话 / 偏好对比
   ▼
质量门控
   ├─ 规则/分类器过滤（语言、格式、毒性、重复）
   ├─ 验证器筛选（数学答案、代码测试、事实核对）
   └─ 去重 + 去污染（与评测集/训练集重叠检测）
   ▼
训练学生模型（更弱/更小/更专）
   ▼
评估 → 回馈到“造数据”的策略（飞轮）
```

> 在可自动验证的领域（数学、代码），合成数据质量尤其高：答案对不对能用程序判，于是能批量造出“过程正确”的优质样本。

## 示例：用 LLM 造带思维链的数学 QA

```python
import json, re

def make_math_qa(teacher, topic, n=1000):
    prompt = (
        f"生成 {n} 道关于{topic}的中学数学题，"
        "每题给出：题干、逐步推导（思维链）、最终答案（用【答案】标出）。"
    )
    raw = teacher.generate(prompt, temperature=0.9)
    samples = parse_qa_blocks(raw)            # 解析成结构化样本
    clean = []
    for s in samples:
        if verify_math(s):                    # 用 sympy/计算验证答案
            clean.append(s)                   # 只保留可验证正确的
    return clean                             # 进入训练集

# 风险点：teacher 自己也会算错，所以"可验证"这一步不能省，
# 否则错误会被学生继承并放大。
```

## 风险：模型崩塌（model collapse）

当模型反复在“上一代模型的输出”上训练，分布会逐步**窄化**：稀有、长尾、复杂的内容被抛弃，模型越来越只生成“安全的平均样本”，最终多样性与能力退化。防范：

- **保持真实数据占比**：合成数据应作为“增强/补充”，而非完全替代真实语料。
- **去重与去污染**：避免同一合成样本被多次回灌形成回声室。
- **质量阈值 + 多样性采样**：过滤低质、保留异构来源。
- **监控分布漂移**：定期比对生成数据分布与真实分布。

## 易错点

- **错误会被继承放大**：教师模型的错答若不过滤就进训练集，学生学到错误，下一代教师更错——形成负飞轮。务必可验证/可过滤。
- **模型崩塌（熵坍缩）**：纯合成数据循环训练会让分布收窄、多样性丧失；必须混真实数据并去重。
- **偏见与格式放大**：教师有的偏见、套话、固定模板，合成数据会成倍复制；需要去偏与多样化 prompt。
- **评测污染**：用“模型自己生成的题”测“自己训练出的模型”，分数虚高且无意义；合成题须与保留评测集严格隔离/去重。
- **过度依赖“看起来对”**：语言流畅≠事实正确，尤其开放问答类合成数据更需要事实核对，而非只看通顺度。

## 小结

合成数据是大模型突破“数据墙”、覆盖隐私与稀缺域的关键补给，核心流程是“强模型造数据 → 质量门控（滤波/验证/去重/去污染）→ 训练学生模型 → 飞轮迭代”。它的最大风险是**错误继承**与**模型崩塌**：必须保留真实数据占比、做可验证筛选、并与评测集严格隔离。用得好是放大器，用不好是退化循环。

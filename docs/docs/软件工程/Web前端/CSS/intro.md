# CSS 简介

CSS（Cascading Style Sheets，层叠样式表）是描述**网页如何呈现**的语言。HTML 说"这是一个标题、那是一段正文"，CSS 说"标题用 32 像素的深灰色无衬线字体、正文行高 1.75"。二者分工的意义在于：同一份内容可以换一套样式就变成完全不同的界面，而不必改动任何结构。

## 学习目标

学完本章，你应该能够：

- 说清 CSS 与 HTML 的职责边界，理解"结构与表现分离"为什么重要
- 写出符合语法的 CSS 规则，并解释规则的三个组成部分
- 掌握三种引入 CSS 的方式，并知道各自适用的场景
- 意识到"浏览器默认样式"的存在，不再困惑于"我什么都没写为什么有间距"

## 前置知识

- 先掌握 [HTML 简介](/docs/软件工程/Web前端/HTML/intro) 与 [网页的语义结构](/docs/软件工程/Web前端/HTML/semantic)：CSS 通过标签名、类名、层级关系来定位元素，不熟悉 HTML 结构就无从下手。

## 核心概念

CSS 的世界里只有一件事：**给元素的某个属性赋一个值**。所谓样式表，就是一大堆"在什么条件下、给哪个属性、赋什么值"的声明集合。

本章主线：
- CSS 的职责：把"表现"从"结构"里剥离出来
- 语法结构：选择器 + 属性 + 值
- 三种引入方式：外部、内部、行内
- 浏览器默认样式：你并不是从零开始

### 为什么要把表现分离出去

早期的网页会直接在 HTML 里写外观，比如用 `font` 标签指定字体颜色、用 `bgcolor` 属性指定背景色。这样做的后果是：想统一改一下正文颜色，得翻遍几百个页面逐个修改；想给同一份内容做一个"打印版"，只能复制一份 HTML 再改。

把表现抽到 CSS 之后：

- **一处修改，全站生效**：改一个样式表文件，所有引用它的页面同时更新。
- **同一结构、多套皮肤**：屏幕、打印、深色模式各用一套样式，HTML 一动不动。
- **文件可缓存**：样式表被浏览器缓存后，后续页面加载只需下载 HTML。
- **可访问性更好**：屏幕阅读器读的是纯净的语义结构，不会被表现标签干扰。

这与软件工程里的[关注点分离](/docs/软件工程/工程实践/设计模式)是同一个思想：把因不同原因而变化的东西拆开。

## 语法结构

一条 CSS 规则（rule）长这样：

```css
h1 {
  color: #333333;
  font-size: 32px;
}
```

拆开看有三个部分：

- **选择器（selector）**：`h1`，决定这条规则作用在哪些元素上。
- **属性（property）**：`color`、`font-size`，你要改的那个方面。
- **值（value）**：`#333333`、`32px`，改成什么。

一个"属性: 值"的组合叫一条**声明（declaration）**，用分号结尾；花括号里的一组声明叫**声明块（declaration block）**。

几条语法细节：

- 最后一条声明的分号可以省略，但**强烈建议保留**——否则以后追加声明时容易漏写。
- CSS 对空白不敏感，换行和缩进只为可读性。
- 属性名不区分大小写，但约定全小写。选择器中的类名、ID 名**区分大小写**。
- 注释只有一种写法：`/* 这是注释 */`。CSS 没有单行注释语法。

写错了会怎样？CSS 的容错策略是**静默丢弃**：遇到不认识的属性名或非法的值，浏览器会跳过这一条声明，继续处理下一条，既不报错也不中断。这个设计让老浏览器能忽略新特性而不崩溃，但也意味着**拼错属性名不会有任何提示**，只会表现为"样式没生效"。

## 三种引入方式

### 外部样式表（推荐）

把 CSS 写在独立的 `.css` 文件里，在 HTML 的 `head` 中用 `link` 标签引入：

```html
<head>
  <link rel="stylesheet" href="/styles/main.css">
</head>
```

这是**生产环境的默认选择**：结构与表现彻底分离、可被浏览器缓存、多页面共享。参见 [HTML 链接标签](/docs/软件工程/Web前端/HTML/link)。

### 内部样式表

写在 HTML 文档的 `style` 标签里：

```html
<head>
  <style>
    body { margin: 0; }
  </style>
</head>
```

适合**单页面的小型演示**，或者需要随 HTML 一起返回的关键样式（首屏渲染优化时会把关键 CSS 内联进 HTML，避免额外请求）。缺点是无法跨页面复用，也无法被单独缓存。

### 行内样式

直接写在元素的 `style` 属性上：

```html
<p style="color: red;">这段是红色的</p>
```

**日常开发中应尽量避免**：无法复用、无法用媒体查询、优先级极高导致难以覆盖（见[层叠与优先级](/docs/软件工程/Web前端/CSS/cascade)）。它的合理用途只有一个——由程序动态计算出来的值，比如 JavaScript 根据数据算出的进度条宽度，这种情况参见 [DOM 样式操作](/docs/软件工程/Web前端/JavaScript/dom/css)。

## 浏览器默认样式

打开一个只有 `<h1>标题</h1>` 的空白 HTML，你会看到标题是粗体、字号很大、上下有间距——这些都不是你写的，而是浏览器内置的**默认样式表**（user-agent stylesheet）。

这解释了两个常见困惑：

- "我没写 `margin`，为什么 `body` 四周有白边？"——浏览器给 `body` 默认了 `margin: 8px`。
- "为什么 `ul` 前面有小圆点还缩进了？"——默认的 `list-style` 和 `padding-left`。

处理方式有两种流派：

- **Reset**：把所有元素的默认样式清零，从一张白纸开始。
- **Normalize**：保留合理的默认值，只抹平不同浏览器之间的差异。

现代项目更多采用后者，或者只写几条最小化的重置：

```css
*,
*::before,
*::after {
  box-sizing: border-box;
}

body {
  margin: 0;
}
```

其中 `box-sizing` 那条几乎是现代 CSS 的标配，原因见[盒模型](/docs/软件工程/Web前端/CSS/box-model)。

## 用开发者工具学 CSS

浏览器按 F12 打开开发者工具，切到 Elements（元素）面板，这是学 CSS 效率最高的地方：

- **Styles 面板**：显示选中元素命中的所有规则，按优先级从高到低排列；被覆盖的声明会加删除线——一眼看出"谁赢了、谁输了"。
- **Computed 面板**：显示每个属性的最终计算值，展开还能看到这个值来自哪条规则、在哪个文件的第几行。
- **盒模型图**：可视化显示 content / padding / border / margin 的实际像素值。
- 面板里的值**可以直接改**，回车立即生效，方便试错。

养成"改 CSS 先看 Computed"的习惯，能省下大量猜测时间。

## 易错点

- **拼错属性名不会报错**。`colr: red` 会被静默丢弃，表现为"样式莫名其妙不生效"。检查时优先看开发者工具里该声明是否被标为无效。
- **值缺单位**。`width: 100` 是非法的（除了 `0` 和无单位的 `line-height`），必须写 `100px` 或 `100%`。
- **样式表路径写错**。`link` 的 `href` 出错时页面照常显示，只是完全没有样式，容易误判成 CSS 写错了。先在网络面板确认 CSS 文件是否 200。
- **把 CSS 文件放在 `body` 末尾**。这会导致页面先以无样式状态渲染再突然变样（FOUC，无样式内容闪烁）。样式表应放在 `head` 里。
- **误以为 CSS 会"报错停止"**。它不会。一条声明写错只影响这一条，同一规则里的其他声明照常生效。

## 练习

动手检验一下自己：

1. 写一个只有 `h1` 和 `p` 的 HTML 页面，分别用三种方式给它加样式，观察三者同时存在时哪个生效。
2. 在开发者工具里选中 `body`，找出它的 `margin` 来自哪里，然后写一条规则覆盖掉它。
3. 故意把 `color` 拼成 `colour`，观察开发者工具里这条声明的显示状态，记住这个特征。
4. 找一个你常用的网站，在 Styles 面板里改掉它的主色调，体会"表现与结构分离"的含义。

## 小结

CSS 用"选择器 + 属性 + 值"的规则描述网页表现，通过外部样式表引入是生产环境的默认做法。它对错误采取静默丢弃策略，所以"样式不生效"要靠开发者工具排查而非等待报错。浏览器自带一套默认样式，你写的规则是在它之上叠加——这正是下一章「层叠」要解决的问题。

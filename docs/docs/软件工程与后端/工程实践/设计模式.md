设计模式是前人总结的可复用方案。理解意图比背结构更重要：用对场景是解药，滥用则成负担。

## 创建型

- **单例**：全局唯一实例（如配置中心）。注意线程安全。
- **工厂方法**：把对象创建延迟到子类，隐藏具体类型。
- **建造者**：分步构造复杂对象，避免超长构造参数。

## 结构型

- **适配器**：把一个接口转换成调用方期望的接口。
- **装饰器**：在不改原类的前提下动态叠加职责。
- **代理**：为对象提供替身以控制访问（缓存、权限、延迟加载）。

## 行为型

- **策略**：把可互换的算法封装起来，运行时切换。
- **观察者**：一对多通知，状态变化自动推送给订阅者。
- **模板方法**：父类定骨架，子类填步骤。

## SOLID 原则

- **S** 单一职责：一个类只因一个理由变化。
- **O** 开闭：对扩展开放、对修改关闭。
- **L** 里氏替换：子类可替换父类而不破坏程序。
- **I** 接口隔离：客户端不应依赖它不需要的接口。
- **D** 依赖倒置：依赖抽象，不依赖具体实现。

## Python 策略模式示例

```python
class Discount:
    def price(self, amount):
        raise NotImplementedError

class NoDiscount(Discount):
    def price(self, amount):
        return amount

class HalfDiscount(Discount):
    def price(self, amount):
        return amount * 0.5

def checkout(amount, strategy: Discount):
    return strategy.price(amount)
```

:::warning
模式是手段不是目标。当你为了「用模式」而引入复杂度时，往往该停下来。
:::

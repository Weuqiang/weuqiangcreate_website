## 核心概念

**Transformer 的瓶颈**：自注意力对长度为 `N` 的序列，计算与显存都是 `O(N²)`。当 `N` 从 2k 涨到 1M（长文档、基因组、音频、高分辨率视频），`N²` 直接让训练/推理不可行。尽管有稀疏注意力、FlashAttention、KV 缓存优化，本质复杂度仍在。

**状态空间模型（SSM）**是一类受控制理论启发的序列建模方法：把输入序列通过一组**连续状态**映射输出，离散化后可用递推（类似 RNN）在 `O(N)` 上扫描，或用特定结构并行训练。其核心是线性时不变系统：

```text
x'(t) = A x(t) + B u(t)      # 状态演化
y(t)  = C x(t) + D u(t)      # 观测输出
```

离散化（零阶保持）后得到 `x_k = Ā x_{k-1} + B̄ u_k`，**每步只依赖上一状态**，因此推理是常数的 `O(1)` 每 token、整体 `O(N)`，且能处理超长序列。

**Mamba 与选择性（S6）**：经典 SSM 的 `A/B/C` 是**与输入无关**的固定参数，导致它“对内容一视同仁”，难以做内容相关的推理（如“复制”“检索特定 token”）。Mamba 让 `A/B/C` 甚至步长 **依赖当前输入**（选择性扫描），使模型能“看到输入后决定记住/忘记什么”，在保持近线性复杂度的同时补齐了内容感知能力。

## 复杂度对比

| 架构 | 训练复杂度 | 推理每步 | 长序列友好 | 内容相关选择 |
|------|-----------|---------|-----------|-------------|
| Transformer（稠密注意力） | O(N²) | O(N)（KV 缓存） | 差 | 是 |
| 经典 SSM（如 S4） | O(N log N)（FFT）或 O(N) | O(1) | 极好 | 否 |
| 选择性 SSM（Mamba/S6） | O(N) | O(1) | 极好 | 是 |
| 线性注意力 | O(N) | O(1) | 好 | 是（近似） |
| RWKV | O(N) | O(1) | 好 | 部分 |

## 示例：选择性扫描的直觉

```python
# 伪代码：Mamba 的 selective scan（简化）
def selective_scan(x, A, B, C, delta):
    # A, B, C, delta 都"依赖输入 x" —— 这就是"选择性"
    h = zeros_like(x[..., 0])           # 隐状态
    ys = []
    for t in range(x.shape[1]):
        # 离散化步长随输入变：重要的 token 步长小、记得久
        A_bar, B_bar = discretize(A[:, t], B[:, t], delta[:, t])
        h = A_bar * h + B_bar * x[:, t]  # 线性递推：O(1) 每步
        ys.append(C[:, t] * h)
    return stack(ys, dim=1)
# 因为每步只用到 h（上一状态），整体 O(N)，且天然支持流式/无限长。
```

## 其他近邻方案

- **线性注意力**：把 `softmax(QKᵀ)V` 改写成 `(QKᵀ/归一化)V` 的可交换形式，先算 `KVᵀ` 再乘 `Q`，复杂度降为 `O(N)`；代价是表达能力弱于 softmax 注意力。
- **RWKV**：用线性Attention + 类 RNN 的“衰减记忆”做类 Transformer 的并行训练、RNN 的 `O(1)` 推理。
- **混合架构**：纯新架构在训练并行性、生态成熟度上仍弱于 Transformer。实践常见“大部分注意力 + 少量 SSM/线性层”或“浅层用 SSM 抓长程、深层用注意力抓局部”，兼顾两者。

## 易错点

- **经典 SSM 不擅长“内容检索”**：固定参数的 SSM 像“低通滤波器”，难以精确复制/检索特定位置的内容；需要选择性的 S6 或配合注意力。
- **双向性受限**：纯递推 SSM 天然因果（只能看过去），做需要“看全文”的任务（如填空、双向理解）不如双向注意力；可用双向 SSM 或混合弥补。
- **训练并行性不如注意力**：虽然推理快，但某些 SSM 训练需特化核（如并行扫描），生态与优化器兼容性不如成熟 Transformer 栈。
- **长上下文≠真正“理解”长程**：能塞下百万 token 不代表模型会正确利用远端信息，仍需位置/记忆机制与评测验证。
- **别盲目替换**：绝大多数任务 Transformer 仍够用且生态最好；仅在“超长序列 + 延迟/显存敏感”场景才优先考虑新架构或混合。

## 小结

Transformer 的 `O(N²)` 注意力在超长序列上代价过高，催生了以 SSM 为代表的近线性序列建模。经典 SSM 靠线性递推实现 `O(N)` 与 `O(1)` 流式推理，但缺乏内容选择性；Mamba 的 S6 让参数依赖输入，补齐了内容感知。线性注意力、RWKV 是近邻方案，而混合架构（SSM+注意力）在成熟度与效果间更稳。新架构适合“超长序列 + 延迟/显存敏感”的场景，而非全面替代 Transformer。

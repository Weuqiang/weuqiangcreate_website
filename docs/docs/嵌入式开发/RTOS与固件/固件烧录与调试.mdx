# 固件烧录与调试

写好固件只是第一步，**把它烧进芯片并稳定调试**才是工程日常。

## 1. 烧录方式

| 接口 | 说明 |
|------|------|
| SWD / JTAG | 调试器（如 ST-Link、J-Link）在线烧录 + 单步调试 |
| UART Bootloader | 通过串口升级固件（产品现场常用） |
| DFU | USB 设备固件升级 |

```text
PC ──[ST-Link]── SWD ── STM32
       SWCLK  SWDIO  GND  VCC
```

## 2. 在线调试

借助调试器可以：

- 设断点、单步执行
- 观察/修改变量与寄存器
- 查看调用栈

比「串口打印大法」高效得多，尤其排查 HardFault。

## 3. 日志与断言

```cpp
#define LOG(...) printf(__VA_ARGS__)
LOG("temp=%.2f\r\n", temp);

#include <assert.h>
assert(ptr != NULL);   // 失败即停机，便于定位
```

> 发布版本用宏关掉日志，减小体积、避免泄露信息。

## 4. OTA 升级（简述）

产品上线后常需无线升级：把新固件写入**备份分区**，校验通过后再切换启动分区。关键是用**校验和/签名**防刷坏变砖。

## 5. 常见坑

- 忘记在 `main` 之前初始化时钟/外设 → 跑飞。
- 中断里调用非 `ISR` 安全的 API（如 `printf`）→ 死锁。
- 看门狗未按时喂 → 反复重启。

## 易错点

- **中断里调用 printf 类 API**：多数 RTOS 的 `printf` 非 ISR 安全，会死锁或踩内存，改用队列把日志甩到任务里打。
- **HardFault 多半是野指针/栈溢出**：先查数组越界、未初始化指针、栈太小。
- **OTA 不校验 = 变砖风险**：新固件必须校验和/签名通过再切换启动分区。

## 练习

1. 用 ST-Link 在 `main` 里下断点，观察复位后 PC 从哪条指令开始跑（启动文件）。
2. 故意写越界数组，用调试器捕获 HardFault，记录 fault 状态寄存器的值。

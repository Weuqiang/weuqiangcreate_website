# 最小生成树

要在 $n$ 个城市之间铺光缆，让任意两城互通，**总成本最低**该怎么铺？答案一定是一棵**树**——因为多一条边就成环，环上任意一条边都可以拆掉而不影响连通性，纯属浪费。这棵总权重最小的生成树，就是**最小生成树（Minimum Spanning Tree, MST）**。

## 学习目标

- 说清生成树的两个硬约束：**恰好 $V-1$ 条边**、**连通且无环**。
- 掌握 Kruskal（按边贪心 + 并查集）与 Prim（按点扩张 + 优先队列）两种实现。
- 理解**切割性质**——为什么这两个贪心算法都是正确的。
- 根据图的稀疏程度选对算法。

## 核心直觉

### 生成树的基本事实

对一个有 $V$ 个顶点的连通图：

- 生成树包含全部 $V$ 个顶点，**恰好 $V-1$ 条边**（少一条不连通，多一条必成环）。
- 一个图可以有很多棵生成树，MST 是其中权重和最小的（可能不唯一，但**最小权重值唯一**）。
- 若图不连通，则不存在生成树，只有**最小生成森林**。

### 切割性质：两个贪心为何都对

MST 的正确性建立在一条定理上，叫**切割性质（Cut Property）**：

> 把顶点集任意划分成两个非空集合 $S$ 和 $V \setminus S$（这个划分叫一个「切割」），那么横跨这个切割的所有边中，**权重最小的那条边一定属于某棵 MST**。

证明思路（反证法）：假设最小横切边 $e$ 不在某棵 MST $T$ 中。把 $e$ 加进 $T$ 会形成一个环，这个环必然还包含另一条横跨该切割的边 $f$（因为环要从 $S$ 出去还得回来）。由于 $e$ 是最小横切边，$w(e) \le w(f)$。把 $f$ 换成 $e$，得到的仍是生成树，且权重不增。所以存在包含 $e$ 的 MST。

这条性质直接催生了两种算法：

- **Prim**：始终维护一个「已选点集合 $S$」，每次选出横跨 $S$ 与外部的最小边，把新点纳入 $S$。这就是**逐次应用切割性质**。
- **Kruskal**：把所有边按权重升序排序，逐条尝试加入，只要不成环就加。加入第 $k$ 条边时，它是连接两个当前连通分量的最小边——也是一次切割性质的应用。

### 两种算法对比

| 维度 | Kruskal | Prim |
|---|---|---|
| 视角 | **边**驱动：全局排序后逐条挑 | **点**驱动：从一点开始向外长 |
| 辅助结构 | 并查集（判环） | 优先队列（选最近点） |
| 时间复杂度 | $O(E \log E)$ | $O((V+E)\log V)$ 堆优化 / $O(V^2)$ 朴素 |
| 适合 | **稀疏图**（$E$ 小，排序快） | **稠密图**（$E \approx V^2$，朴素版更优） |
| 中间状态 | 森林（多个分量） | 始终是一棵连通树 |
| 天然支持 | 最小生成**森林**（图不连通也能跑） | 只能求当前连通分量 |

## 最小示例

### Kruskal + 并查集

并查集（Union-Find）是 Kruskal 的关键：它以近似 $O(1)$ 的代价回答「这两个点是否已连通」。

```python
class DSU:
    """并查集：路径压缩 + 按秩合并"""
    def __init__(self, nodes):
        self.parent = {u: u for u in nodes}
        self.rank = {u: 0 for u in nodes}

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]   # 路径压缩
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False                 # 已连通，加这条边会成环
        if self.rank[ra] < self.rank[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1
        return True


def kruskal(nodes, edges):
    """edges: [(weight, u, v), ...]"""
    dsu = DSU(nodes)
    mst, total = [], 0
    for w, u, v in sorted(edges):        # 按权重升序
        if dsu.union(u, v):              # 不成环才要
            mst.append((u, v, w))
            total += w
            if len(mst) == len(nodes) - 1:
                break                    # 已凑够 V-1 条边，提前结束
    return mst, total


nodes = ['A', 'B', 'C', 'D', 'E', 'F']
edges = [
    (4, 'A', 'B'), (2, 'A', 'C'), (5, 'B', 'C'),
    (10, 'B', 'D'), (3, 'C', 'E'), (4, 'E', 'D'),
    (11, 'D', 'F'), (8, 'E', 'F'),
]

mst, total = kruskal(nodes, edges)
print(mst)     # [('A','C',2), ('C','E',3), ('A','B',4), ('E','D',4), ('E','F',8)]
print(total)   # 21
```

**手算推演** Kruskal 的每一步（边按权重排序后为 2, 3, 4, 4, 5, 8, 10, 11）：

| 步 | 边 | 权重 | 两端是否已连通 | 决策 | 当前分量 |
|---|---|---|---|---|---|
| 1 | A–C | 2 | 否 | ✅ 加入 | AC, B, D, E, F |
| 2 | C–E | 3 | 否 | ✅ 加入 | ACE, B, D, F |
| 3 | A–B | 4 | 否 | ✅ 加入 | ABCE, D, F |
| 4 | E–D | 4 | 否 | ✅ 加入 | ABCDE, F |
| 5 | B–C | 5 | **是**（都在 ABCDE） | ❌ 跳过（成环） | ABCDE, F |
| 6 | E–F | 8 | 否 | ✅ 加入 | ABCDEF |

到第 6 步已有 5 条边 = $V - 1 = 5$，提前结束。总权重 $2+3+4+4+8 = 21$，与程序输出一致。剩下的 B–D(10)、D–F(11) 根本没被考虑。

### Prim（堆优化）

```python
import heapq
from collections import defaultdict


def prim(nodes, edges, start=None):
    adj = defaultdict(list)
    for w, u, v in edges:
        adj[u].append((w, v))
        adj[v].append((w, u))            # 无向图双向存

    start = start or nodes[0]
    visited = {start}
    pq = list(adj[start])                # 起点的所有出边
    heapq.heapify(pq)
    mst, total = [], 0

    while pq and len(visited) < len(nodes):
        w, v = heapq.heappop(pq)
        if v in visited:                 # 过期条目，跳过
            continue
        visited.add(v)
        mst.append((v, w))
        total += w
        for w2, nxt in adj[v]:
            if nxt not in visited:
                heapq.heappush(pq, (w2, nxt))
    return mst, total


mst2, total2 = prim(nodes, edges, 'A')
print(total2)   # 21  ← 与 Kruskal 结果相同
```

两种算法得到的**边集可能不同**（当有等权边时），但**总权重必然相同**。上例中总权重都是 21。

| 操作 / 算法 | 时间复杂度 | 空间 | 说明 |
|---|---|---|---|
| 边排序（Kruskal） | $O(E \log E)$ | $O(E)$ | 主导项 |
| 并查集 $E$ 次操作 | $O(E \cdot \alpha(V))$ | $O(V)$ | $\alpha$ 是反阿克曼函数，实际 $< 5$ |
| **Kruskal 总计** | $O(E \log E)$ | $O(V + E)$ | 稀疏图首选 |
| Prim 朴素（邻接矩阵） | $O(V^2)$ | $O(V^2)$ | 稠密图首选 |
| Prim 堆优化 | $O((V+E)\log V)$ | $O(V+E)$ | 通用 |
| Prim 斐波那契堆 | $O(E + V\log V)$ | $O(V+E)$ | 理论最优，常数大，实际少用 |

**选型速记**：$E \approx V$（稀疏）用 Kruskal；$E \approx V^2$（稠密）用朴素 Prim；不确定就用堆优化 Prim。

## 易错点

1. **把 MST 当成最短路径树。** 这是最常见的混淆。MST 保证**所有边的权重总和最小**，但**不保证任意两点之间的路径最短**。上例 MST 中 A 到 D 的路径是 `A→C→E→D = 2+3+4 = 9`，恰好也是最短路；但换个图这两者就会分道扬镳。目标不同：MST 优化「总成本」，最短路优化「点对距离」。

2. **并查集不做路径压缩。** 不压缩时 `find` 最坏是 $O(V)$，Kruskal 退化到 $O(E \cdot V)$。路径压缩只有一行，务必加上。

3. **Prim 忘记跳过已访问点。** 和 Dijkstra 一样，堆里会有过期条目，弹出时必须 `if v in visited: continue`。漏了会重复加边，得到超过 $V-1$ 条边的错误结果。

4. **无向图只存单向边。** Prim 的邻接表必须双向存 `adj[u].append((w,v))` 和 `adj[v].append((w,u))`，否则从某些起点出发会「走不回去」，漏掉顶点。

5. **图不连通时没有处理。** Kruskal 跑完后若边数少于 $V-1$，说明原图不连通，得到的是**最小生成森林**而非树。要么报错，要么明确按森林语义处理。Prim 则会直接漏掉其他连通分量。

6. **误以为 MST 唯一。** 有等权边时 MST 可能有多棵，但**最小总权重是唯一的**。如果要求 MST 唯一，充分条件是「所有边权互不相同」。

7. **在有向图上求 MST。** 有向图的对应问题叫**最小树形图**（Arborescence），需要 Chu–Liu/Edmonds 算法，Kruskal 和 Prim 都不适用。

## 练习

1. 给 `kruskal` 加上连通性检查：跑完后若 `len(mst) < len(nodes) - 1`，抛出「图不连通」异常。用一个孤立点测试。
2. 实现**最大生成树**：只需把 Kruskal 的排序改成降序。用它解决「在通信网络中选一组链路，使最小带宽最大」的问题。
3. 用并查集实现**动态连通性查询**：给定一系列 `union(a,b)` 和 `connected(a,b)` 操作，逐条输出结果。这是并查集脱离 MST 的独立应用。
4. 手算：对上例中的图跑 Prim（从 A 开始），写出每一轮加入的点与边，验证总权重也是 21，并对比与 Kruskal 的边集是否相同。
5. 思考题：如果给图中**每条边的权重都加上同一个常数 $c$**，MST 的边集会变吗？为什么？（提示：生成树的边数固定为 $V-1$。）如果换成最短路径问题呢？

## 小结

最小生成树是**贪心策略在图上最漂亮的成功案例**：Kruskal 从全局最小边贪心，Prim 从局部最近点贪心，两条完全不同的路径通向同一个最优解，背后是同一条切割性质在支撑。实现上，Kruskal 教会你并查集，Prim 教会你优先队列在图算法中的用法——这两个工具的价值远超 MST 本身。最后务必记牢那条分界线：**MST 最小化总成本，最短路最小化点对距离，两者不可混用**。

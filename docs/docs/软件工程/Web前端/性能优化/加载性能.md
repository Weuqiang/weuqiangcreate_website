# 加载性能

## 学习目标

学完本章，你应该能够：

- 解释关键渲染路径与「首屏」为何慢
- 用代码分割与懒加载削减首屏体积
- 用 preload / prefetch 调度资源优先级
- 优化图片与字体这两类大头资源

## 核心概念

加载性能关乎「用户多久能看到并操作内容」。瓶颈通常不在 CPU，而在**网络传输量**与**请求次数**——把要下载的东西变少、变晚、变聪明，首屏就快。

## 关键渲染路径与首屏体积

浏览器要先下载并解析 HTML → CSS → JS，才能画出首屏。首屏 JS/CSS 体积越大、请求越多，白屏越久。核心策略：**首屏只发必需的最小集合**。

```javascript
// 路由级代码分割：首屏只加载当前页，其余按需
const Home = lazy(() => import('./Home'));
const Admin = lazy(() => import('./Admin')); // 进后台页才下载
```

## 懒加载：用到的才下载

- **路由懒加载**：不同页面拆成不同 chunk，进入才拉。
- **组件/图片懒加载**：视口外的图片用 `loading="lazy"`，滚动到才请求。

```html
<img src="hero.jpg" loading="lazy" alt="说明" />
```

## 预加载：提前调度优先级

```html
<!-- 当前页立刻要用的关键资源，提前高优先级获取 -->
<link rel="preload" as="font" href="/font.woff2" crossorigin />
<!-- 下一页很可能要用的，空闲时低优先级预取 -->
<link rel="prefetch" as="script" href="/next-page.js" />
```

- `preload`：当前导航**必需**、但发现得晚的资源（字体、关键图），提高优先级。
- `prefetch`：**未来**可能用（下一页），浏览器空闲时低优先级拉，赌用户会去。

## 图片优化（最常见的体积大头）

- 用现代格式 `WebP`/`AVIF` 替代 PNG/JPG，体积可减半
- 按设备给不同分辨率（`srcset` + `sizes`）
- 响应式图片避免「手机下载桌面 4K 图」
- 用 CDN + 缓存，命中后秒回

## 字体优化

- 用 `font-display: swap` 避免「字体未到文字不可见」的隐形白屏
- 仅打包用到的字重/字型，避免整本字体入库
- 关键字体 `preload` 并加 `crossorigin`（否则会重复请求）

## 易错点

1. **首屏打包过重**：把后台管理、图表库全打进首屏 bundle；用代码分割拆开。
2. **preload 滥用**：过度 preload 会和首屏关键资源抢带宽，反而变慢。
3. **图片不压缩/不响应式**：一张 3MB 图拖垮移动端首屏。
4. **字体阻塞渲染**：忘了 `font-display: swap`，字体未加载时整段文字空白。

## 小结

加载性能靠「减、晚、智」：用代码分割与懒加载削减并推迟下载，用 preload/prefetch 调度优先级，用现代格式与响应式压低图片字体体积。把首屏关键路径上的资源压到最小，白屏与可交互时间自然下降。

## 练习

1. 用打包分析工具查看首屏 bundle，找出可懒加载的重型模块并拆分。
2. 给站点图片换成 WebP + `srcset`，对比传输体积。
3. 给关键字体加 `preload` + `font-display: swap`，用 DevTools 的 Network 面板观察字体请求时机。

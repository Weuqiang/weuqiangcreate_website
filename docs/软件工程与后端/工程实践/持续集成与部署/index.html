持续集成与部署

CI/CD 把「构建、测试、部署」自动化，让代码改动能快速、可靠地交付到生产。

CI 与 CD 的区别​

  • CI（持续集成）：开发者频繁把代码合入主干，每次合入都自动构建并运行测试，尽早发现集成问题。
  • CD（持续交付 / 持续部署）：在 CI 之后自动把通过测试的产物打包并发布到预发或生产。持续交付需人工点一下发布；持续部署则全自动。

一条典型流水线​

  1. 触发：push 或 PR。
  2. 安装依赖并缓存。
  3. 静态检查（lint）与单元测试。
  4. 构建镜像 / 打包产物。
  5. 部署到预发环境，跑集成测试。
  6. 人工审批或自动发布到生产。

GitHub Actions 示例​

name: ci
on:
  push:
    branches: [main]
  pull_request:

jobs:
  build-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"
      - run: pip install -r requirements.txt
      - run: pytest -q
      - run: docker build -t app:ci .

部署策略​

策略思路优点风险
蓝绿两套环境，切流量秒级回滚资源翻倍
金丝雀先放少量流量影响面小需流量路由
滚动逐批替换实例资源友好新旧并存期长

质量门禁​

在流水线中设置硬性门槛：测试覆盖率不低于阈值、禁止高危漏洞、构建零警告。不达标则阻断合并。

提示

先把「能跑起来的 CI」做出来，再逐步加门禁，别一上来就追求完美流水线。
